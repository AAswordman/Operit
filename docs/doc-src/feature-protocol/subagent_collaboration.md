# 子代理协作与会话存储

全局权限为“询问”时，内置协作工具默认允许。单工具的“询问”或“禁止”仍优先；子代理实际执行的文件、终端等工具仍分别检查权限。

普通聊天使用 `spawn_agent`、`send_message`、`followup_task`、`interrupt_agent`、
`list_agents` 和 `wait_agent` 管理同一代理树。`list_agent_models` 按需提供配置名称和模型名称，
模型列表不自动写入每轮上下文。查看模型列表不表示用户已授权换模型。

`send_message` 只投递消息，空闲代理需要 `followup_task` 才启动新一轮。
完成回复自动投递父代理；重复查询状态不会重复返回完整结果。
`wait_agent` 由收件箱和代理状态变化唤醒，没有待处理工作时立即返回。
停止主聊天同时停止它的代理树。内部 v1 任务运行器保留，但不向聊天模型暴露 `task`。
群组编排回合不开放协作工具。普通子代理消息在思考结束或工具执行完成的边界进入当前回合；
用户引导可以提前结束采样。子代理会话只读，继续任务通过协作工具发起。

插件 `subagent_run` 保留独立的调用预算、执行证据与结束原因。它沿用调用者会话 ID，
但不继承该会话的 V2 协作身份：插件内部不开放协作工具，也不执行 V2 的历史压缩流程。

未选择其他模型时，代理继承父回合实际使用的模型配置及索引；显式选择模型或使用固定模型的代理配置档时，
按对应选择执行。显式的 `reasoning_effort` 使用目标配置的
思考档位映射，按档位 ID 或协议值查找；没有对应映射时返回明确错误。
覆盖仅作用于该代理回合，不修改保存的模型配置，不替换其他回合正在使用的服务。

数据库从上游版本 21 升级到 23，加入会话类型、子代理运行记录及索引。
既有聊天、消息、分组、分支和 token 统计保留，不包含已撤回的文件夹实体或聊天收藏字段。
该版本变化仍需协调 Operit2 导入器支持，当前不应作为可直接合并的发布方案。

JSON v5 备份包含子代理关系。选择分支导出时同时包含其父会话及关联子代理，
使导入后的关系完整。JSON v2 和旧聊天数组仍可导入；不接受已撤回文件夹方案的 v3/v4 格式。
CSV v2 在原有列末尾追加聊天类型；CSV 用于查看记录，不承载完整协作状态恢复。
整库备份在存储锁内复制协作状态，再执行压缩，避免分片清理造成不完整快照。

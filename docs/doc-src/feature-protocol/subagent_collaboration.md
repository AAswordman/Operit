# 子代理协作与会话存储

全局权限为“询问”时，内置协作工具默认允许。单工具的“询问”或“禁止”仍优先；子代理实际执行的文件、终端等工具仍分别检查权限。

普通聊天使用 `spawn_agent`、`send_message`、`followup_task`、`interrupt_agent`、
`list_agents` 和 `wait_agent` 管理同一代理树。`list_agent_models` 按需提供配置名称和模型名称，
模型列表不自动写入每轮上下文。查看模型列表不表示用户已授权换模型。

`send_message` 只投递消息，空闲代理需要 `followup_task` 才启动新一轮。
完成回复自动投递父代理；重复查询状态不会重复返回完整结果。
`wait_agent` 由收件箱和代理状态变化唤醒，没有待处理工作时立即返回。
停止主聊天同时停止它的代理树。内部 v1 任务运行器保留，但不向聊天模型暴露 `task`。
群组编排回合不开放协作工具。普通子代理消息在思考结束或工具执行完成的边界进入当前回合；
用户引导可以提前结束采样。子代理会话只读，继续任务通过协作工具发起。

插件 `subagent_run` 保留独立的调用预算、执行证据与结束原因。它沿用调用者会话 ID，
但不继承该会话的 V2 协作身份：插件内部不开放协作工具，也不执行 V2 的历史压缩流程。

未选择其他模型时，代理继承父回合实际使用的模型配置及索引；显式选择模型或使用固定模型的代理配置档时，
按对应选择执行。显式的 `reasoning_effort` 使用目标配置的
思考档位映射，先忽略大小写匹配档位 ID 或协议值。命名档位选择不低于请求的最近档位，
超出模型上限时选择最高档位；数字预算按从小到大的顺序对应
`minimal`、`low`、`medium`、`high`、`xhigh`、`max`、`ultra`，超出档位数量时取最大预算。
只有开关的模型使用启用动作；`none` 要求模型允许关闭且配置了关闭动作。
没有配置映射时返回明确错误。显式覆盖优先于本次请求中已有的自定义思考参数。
覆盖仅作用于该代理回合，不修改保存的模型配置，不替换其他回合正在使用的服务。

数据库从上游版本 21 升级到 23，加入会话类型、子代理运行记录及索引。
既有聊天、消息、分组、分支和 token 统计保留，不包含已撤回的文件夹实体或聊天收藏字段。
维护者已在 PR #1482 确认本次改动不受此前 Operit2 对话树层级问题影响；各层仍需按依赖顺序审阅和验证。

JSON v5 备份包含子代理关系。选择分支导出时同时包含其父会话及关联子代理，
使导入后的关系完整。JSON v2 和旧聊天数组仍可导入；不接受已撤回文件夹方案的 v3/v4 格式。
CSV v2 在原有列末尾追加聊天类型；CSV 用于查看记录，不承载完整协作状态恢复。
整库备份在存储锁内复制协作状态，再执行压缩，避免分片清理造成不完整快照。

普通聊天中的派发、消息和结果卡保留当次交互的内容。点卡片可查看详情，再进入只读子会话。相同名字可以再次使用，所以卡片按运行记录、发送方会话 ID 和消息时间识别对应的子代理。结果卡不会因为代理后续执行了另一项任务而改变状态。

只读子会话允许查看工具参数、结果、上下文和 token 统计。费用按当前模型价格估算；
缺少请求边界、缓存写入或计费信息时标明不完整。普通聊天结束后，子代理回报保存在邮箱，
不会自动开启新的主聊天回合。

每棵代理树保留最近 200 个活动身份；超出时自动归档符合条件的旧子树。运行中、创建子任务中、
有待收消息或尚未被收取的发出消息的身份受到保护，数量可暂时超过上限。
归档保留聊天记录，但释放任务名字并拒绝旧 ID 的再次寻址。列表最多返回 200 个子代理，
同时报告未归档总数。协作存储 v3 将旧身份保存为不可变归档分段，仍可读取 v1/v2。

聊天展示先读取过程结构元数据，折叠过程展开后每次读取 32 条正文；长正文分块惰性渲染。
返回聊天使用消息与分块锚点恢复位置。浮窗自动采集的附件与发送目标在本次请求内保持绑定，
切换会话不会把内容发送或添加到新会话。

数据库 23 → 24 为运行记录增加协作归属、代理路径和模型轮数，并建立一次性的待恢复检查点，不读取协作文件。聊天服务初始化后独立恢复已有记录的归属，按本机保存的运行 ID 与子会话 ID 双重匹配，仅填写空归属；归属更新和清除检查点在同一事务中完成，成功后不再重复读取归档。恢复失败会保留原文件和检查点、显示错误并允许修复存储后重启重试，不阻断数据库结构升级。历史轮数没有原始计数，升级后从零开始累计。JSON v5 的新增字段均为可选；导入及创建分支时，会话 ID 随结构化引用一并重映射。

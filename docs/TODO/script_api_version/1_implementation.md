# 脚本 API 版本贯通

1. OP1 的 ToolPackage 保存 `api_version`，缺失按 `1.0.0` 解释，解析和导入使用宿主支持列表校验。ToolPkg 子包使用容器版本。
2. 发布源和市场发布请求对脚本保留 `apiVersion`，列表、详情、历史版本和发布预览统一显示 API 版本。
3. OP2 为脚本补充 API v2 角标、详情和发布信息。
4. 市场后端对显式 API 声明验证三段版本格式和 App 范围；缺失字段继续接受，不改写历史记录。网页显示 API 版本，下载资产与选定版本对应。

旧 OP1 可继续解析新增元数据，但已发布旧客户端不会新增安装拦截；本次不增加目录分流。

OP2 对相关 Dart 文件的静态分析通过。市场前后端 TypeScript 检查通过，回归覆盖旧客户端不传 API 的发布、脚本与 ToolPkg 的版本投影，以及按版本选择下载资产。OP1 本轮仅进行源码与资源检查，未执行 Android 构建或测试。

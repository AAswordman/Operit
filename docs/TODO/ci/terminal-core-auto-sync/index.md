# 终端核心默认分支自动同步

## 现状与目标

主应用通过 `terminal` 子模块固定引用终端提交。该提交已推送到独立仓库的工作分支，默认分支 `master` 仍停留在旧版本，导致仓库首页显示的源码落后于应用。

将默认分支沿已有历史推进到应用实际采用的提交，并在主应用 `dev`、`main` 更新终端引用后自动执行。终端代码仍作为独立仓库维护。

## 01 同步规则 [DONE]

读取两个可信应用分支的最新 gitlink，核对目标仓库并选择沿历史较新的终端版本；查询独立仓库默认分支并比较提交关系。新提交只作快进，已一致或已包含的提交不更新，分叉直接报告错误。使用 GitHub 的非强制引用更新，完整保留提交历史和固定的源码版本。

## 02 自动触发 [DONE]

新增 `Sync terminal core` 工作流，在 `dev`、`main` 的终端 gitlink、来源配置或同步实现变化时触发，并提供手动入口。两个分支共用并发组；每次重新读取最新引用，覆盖等待事件被合并的情况。工作流只在维护者仓库的可信分支运行，使用既有 `OPERIT_DISTRIBUTION_TOKEN` 更新终端仓库。

## 03 部署与核对

先执行只读预览，再将工作流分别合入 `dev` 和 `main`。确认实际工作流成功，终端默认分支与应用采用的终端提交完全一致。保留工作流运行链接及提交记录。

本任务不涉及应用业务源码、App 版本或资源发布。编译、构建和测试未执行；静态核对与真实同步结果在部署完成后回填。

# 固定资源只在变化时发布

普通 push、assembleDebug 和签名应用发行不会触发 resources job；离线资源仍仅由手动选择 publishOfflineResources 启动。本次在该入口增加发布前复用核对：源码指纹与固定清单先通过校验，当前 tag 已公开且附件集合、大小、摘要及总校验文件完全一致时直接返回 reused，不下载构建产物、不创建 Release/tag、不重新上传。

当前资源未公开或仅有草稿时才要求当前提交的有效资源产物；公开附件不一致时明确失败，不覆盖。草稿通过列表按 Release ID 识别，避免按 tag 查询不到未公开草稿后再次创建同名发行。发现多个同名草稿时停止，不自动删除任何资源。

V1 的原始文件与封装 ZIP 同时保留，迁移时也会在原、新仓库短暂同时存在；不能仅因名称相似当作重复内容。当前仓库只有 resources-v1 和 resources-v2-f67fc0082a8e638c6cc2 两个公开发行。+15 引用的旧 V2 标签目前缺失，影响旧客户端从该地址新下载；当前固定清单所需资产另行按元数据核对，不推断是谁删除了历史版本。

本轮仅本地提交与静态核对，新增回归未本地运行，未推送或派发工作流。后续 Github 包修复有实际脚本内容更新，整合时需准备新的对应资源；不会因此重打无变化的 V1，也不会每次发布 APK 顺带发布资源。

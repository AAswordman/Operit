# 角色卡提示词编辑窗口补全

[返回总计划](index.md)

## 反馈与现状

用户实测反馈：角色卡的角色设定、开场白、其他内容、自定义提示词和备注仍存在滚动问题，原 PR #1411 没有覆盖完整编辑体验。
主页角色选择器的编辑入口最终进入同一套角色卡设置与编辑组件。

原补丁只替换外层 `Column` 的滚动状态。当前 Foundation 1.10.4 的 `rememberScrollState()` 本身已经使用 `rememberSaveable`，所以这项替换不能解决多行输入框内部的光标、选区、滚动和键盘布局变化。
紧凑输入框与全屏编辑器仍使用旧的字符串值回调接口；外层没有独立持有每个字段的输入和内部滚动状态，全屏草稿也没有与来源字段的选区衔接。

## 作用域与步骤

1. 为每个角色卡字段持有稳定的 `TextFieldState` 和输入框内部 `ScrollState`，使用项目现有依赖支持的状态式文本输入接口。
2. 统一覆盖角色设定、开场白、其他内容（聊天／语音）、自定义提示词、备注，以及共享组件中的名称、描述；同步处理标签编辑和共用输入组件的调用方。
3. 全屏编辑使用独立草稿和独立视口，保留来源字段的选区；保存写回文本与选区，取消保持原字段内容。
4. 审查输入框与父滚动窗口的边界和键盘布局，不添加延时恢复位置或强制跳回旧位置的代码。
5. 添加真实 Compose 编辑行为的回归用例，覆盖长文本、焦点切换、重新布局、展开、保存和取消；补充真机清单。

## 实现结果

- 新增 `PromptEditorState`，按角色卡或标签 ID、字段 ID 分别持有文本、选区和内部滚动状态。
- 角色设定、开场白、其他内容（聊天／语音）、自定义提示词和备注全部使用同一套状态式输入；名称、描述和角色群共用输入框的调用方同步更新。
- 字段状态由表单持有，隐藏高级字段时不销毁其输入与滚动状态。保存角色卡时直接读取当前字段状态，避免捕获上一帧的文本。
- 全屏编辑器创建独立草稿及独立 `ScrollState`，以来源字段的选区初始化。保存时写回文本和选区，取消后不写回，重新打开时使用来源字段的当前内容。
- 标签的名称、描述与提示词输入同步使用独立状态。
- 未添加延时恢复位置、强制滚回旧位置或额外异常处理路径。

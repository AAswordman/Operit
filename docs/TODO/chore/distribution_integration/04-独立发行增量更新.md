# 独立发行增量更新

本次补录：用户确认目前 Bug 均已修复，本页功能验收结果按用户确认记为通过。验证来源及现有 CI 记录见[验证结果补录](06-验证结果补录.md)。

原更新检查从关于页面字符串推导上游完整包仓库，内测增量源固定为 `AAswordman/OperitNightlyRelease`。本轮将独立发行版的更新查询统一到 `3316891527/Operit`，正式版更新始终可检查；版本号带 `+` 的补丁版仅在启用 Beta 计划后进入更新候选，自动与手动检查使用同一规则。

客户端选择独立发行的 `app-kong.apk`，按数字版本而不是 API 返回顺序选择正式 Release，忽略草稿、预发布、无效标签与其他包名的 APK。同基础版本有成对补丁资源时显示增量更新，跨基础版本提供完整 APK。发布 JSON 正文中的元数据用于补丁链索引，界面只展示发布说明。

Android Build 新增发布开关、可选基础标签和发布说明。发布脚本校验固定签名与包名、递增 versionCode，生成已有 apkraw 协议的补丁并逐字节还原校验。完整产物上传到草稿后再公开，避免更新检查读取未上传完毕的版本。完整使用方法见 ci/distribution/updates/README.md。

首次接入仍需完整安装一次本轮 APK；旧包不会因个人仓库出现标签而改变上游更新源。首次正式 Release 建立完整 APK 基线，后续同基础版本发布才能生成补丁。当前准备 `1.12.2+5`、versionCode 61，后续发行继续同时递增版本名与 versionCode。

## 验证与边界

客户端现有 15 项 JVM 用例，包含原有补丁选择用例及新增的 6 项 Beta 渠道用例；发布脚本的既有用例保留。Beta 用例覆盖同基础版本与跨基础版本的 `+` 更新过滤、过滤后的正式版选择、退出 Beta 后不降级、继续接收新正式版以及开启 Beta 后仍接收正式版。本轮本地仅检查 diff 与字符串 XML，未运行 Android 编译或测试；构建与 JVM 用例交由仓库工作流执行。设备功能验收已按用户确认补录为通过；发布操作以实际记录为准。

## 完整增补回归

- UPD1：首次完整安装本轮 APK 后检查更新；预期只访问个人仓库的应用更新源，不读取上游完整包或内测增量源
- UPD2：创建只有标签或不带 Kong APK 的 Release 后检查更新；预期不作为可安装更新提供
- UPD3：启用 Beta 计划，在同一基础版本发布递增的 APK 与配套补丁后检查更新；预期显示最新数字版本的增量更新，不被同版本完整 APK 覆盖
- UPD4：发布跨基础版本的新包后检查更新，带 `+` 的版本先启用 Beta 计划；预期提供新版本完整 APK
- UPD5：检查草稿、预发布、相同版本和空发布列表；预期不向用户提示这些版本的更新
- UPD6：启用 Beta 计划，连续发布多个 +n 版本，在较早正式包执行增量安装；预期按保留的补丁链还原最新固定签名 APK，哈希通过并进入安装器
- UPD7：使用错误基础 APK 或篡改补丁；预期既有哈希校验明确失败，不安装损坏 APK
- UPD8：通过工作流首次发布，再发布同基础版本下一版；预期首次建立完整包基线，后续生成补丁和元数据，Release 目标为构建提交
- UPD9：向发布流程提供错误签名、包名、版本号或重复版本；预期拒绝发布，不覆盖已有正式文件

- UPD10：关闭 Beta 计划，仅提供同基础版本的 `+n` 更新并执行自动或手动检查；预期不提示补丁更新
- UPD11：关闭 Beta 计划，仅提供跨基础版本且无补丁资源的 `+n` 完整包；预期该版本仍被过滤
- UPD12：关闭 Beta 计划，同时提供新正式版与更高的 `+n` 版本；预期提示最新正式版
- UPD13：已安装 `+n` 后退出 Beta 计划再检查；预期不降级，仍能发现更高基础版本的正式版
- UPD14：在相同发布列表下切换 Beta 开关并重新检查；预期旧检查结果清除，开启后发现补丁、关闭后仅发现正式版
- UPD15：开启 Beta 计划并只提供新正式版；预期仍可检查和下载正式版

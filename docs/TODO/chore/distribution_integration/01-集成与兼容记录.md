## 交叉功能协调

- 模型分组与密钥池共用模型配置页，保留分组、排序和分组筛选。模型列表请求同时保留超时取消、错误反馈及已保存的模型顺序；聊天输入框继续显示提供商图标和分组信息。
- 纯思考续写保留助手历史及未完成工具上下文，同时按正文缺失或输出达到上限选择提示。结构化消息、工具结果标记与密钥池请求流程共同保留，DeepSeek 图片预上传在本次请求的密钥池会话之前执行。
- JSON、CSV 均按页读取消息和候选变体。JSON 使用统一消息序列化器写入结构化片段；CSV 带上片段字段、独立文件夹记录、文件夹路径和最近使用时间，格式检测与导入共用表头规则，并兼容旧正文列。
- 工作区文件链接接入新版聊天容器；既有创建、选择和文件入口接到统一浏览与预览界面。已移除旧文件管理页面的路由和导入，不恢复基点已隐藏的旧工具箱卡片。
- 记忆检索保留按功能模型绑定的向量配置，将最小语义相似度控件接入新版检索设置页。窗口刷新只持久化窗口值，避免旧累计 Token 快照覆盖新用量，并保留串行刷新与取消保护。
- 原生代码围栏同时保留反引号与波浪线支持，加入行首、最多三个前导空格以及同类且足够长度的闭合判断。Waifu XML 深度配对与流式 Markdown 修复保留。
- 单一聊天滚动中的渲染片段接入结构化消息缓存，玻璃气泡继续使用全局外观参数。密钥池支持范围在调用时判断，避免枚举构造期间读取其他枚举项。

## 打包配置

独立发行保持 Kong 共存包名 `com.ai.assistance.operit.kong` 和非 debuggable 属性，R8 和资源收缩保持基点配置。版本为 `1.12.2+1`，版本号由基点的 51 提高到 53。发行工作流默认派发 `:app:verifyCiPreviewRelease`，依赖 `assembleRelease` 生成 `app-kong.apk`，不执行 AAB 构建；产物上传规则仅匹配 APK。

发行使用专用固定 PKCS12 密钥，别名为 `operit-distribution`。私钥和密码由两个 GitHub Actions Secrets 注入，仓库只记录公开证书 SHA-256：`5E01FFF4DD01A44BAB8318BE35107AE39C60A1261CFCE33003EA3528727EA799`。APK 校验同时核对签名有效性、证书指纹、包名与非调试属性，并保存签名和包属性报告。密钥准备过程和维护规则见 [发行签名说明](../../../../ci/distribution/README.md)。

后续版本须沿用同一密钥、包名和不降低的版本号。旧 CI 包使用临时调试签名，无法仅凭新密钥保证直接覆盖；本次没有执行设备安装或卸载。实际构建、产物和覆盖安装结果以 CI 与设备验证为准。

## 发行版原生编译修复

Release [38683499386](https://github.com/3316891527/Operit/actions/runs/38683499386) 在 `:app:buildCMakeRelWithDebInfo[arm64-v8a]` 失败。`StreamMarkdownInlineCodePlugin` 的实现和块级调用使用两个构造参数，但头文件仍只有单参数声明，并缺少 `deferFences_` 成员，导致四条编译诊断。头文件补齐第二个参数和成员，第二个参数默认 `false`，保留行内调用行为；块级调用显式传入 `true`，继续让围栏插件处理代码围栏。

本次仅完成声明、实现及调用关系核对和 diff 检查，尚未运行新的发行构建。日志中的 `libsudo.so` 符号剥离提示由 Gradle 原样打包后继续执行，不是此次构建的失败任务。

## JVM 测试适配修复

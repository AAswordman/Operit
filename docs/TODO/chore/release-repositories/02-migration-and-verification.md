# 迁移、验证与切换

## 已准备的迁移入口

在源码仓库根目录执行下列命令仅生成迁移计划和原始发行元数据备份，不创建仓库、不上传、不删除。

```bash
python3 ci/distribution/repositories/migrate_releases.py --output .ci-repository-migration
```

`--initialize` 显式创建两个公开仓库，初始化 LGPL-3.0 许可证及职责、源码和第三方许可说明。`--apply` 显式复制历史发行。两个仓库已完成初始化，完整附件迁移安排在 GitHub 托管发行工作流中执行。

```bash
python3 ci/distribution/repositories/migrate_releases.py --output .ci-repository-migration --initialize
python3 ci/distribution/repositories/migrate_releases.py --output .ci-repository-migration --apply
```

迁移先检查源 Release 附件集合、上传状态、大小和 GitHub SHA-256 摘要，再下载并逐项核对。应用 APK 和增量 ZIP 保持原字节；JSON 中的下载地址与仓库身份改指新位置，摘要记录对应源码提交；资源目录地址和总校验清单随之更新。目标先通过创建接口取得草稿 Release ID，再上传附件；草稿可能尚无 Git 标签，读取和公开均使用 Release ID，不使用仅能定位已发布版本的标签查询接口。全部附件的远端大小及摘要核对完成后才公开，公开响应再次核对标签、状态和附件后才写入完成收据。已有完整草稿和已公开发行核对一致后复用，禁止覆盖不一致的目标。

源元数据保存为 `source-releases.json`，迁移计划为 `migration-plan.json`，各目标文件核对结果追加到 `verified-receipts.json`。迁移工具不删除源发行，也不删除主仓库源码标签。附件部分上传后中断会留下草稿；核对后处理该草稿再重跑，不改写已公开文件。

## 切换顺序

1. 在源码仓库配置 OPERIT_DISTRIBUTION_TOKEN，完成工作分支不发布的 Android Build 和 Android Tests
2. 创建两个目的仓库，配置源码仓库的跨仓库发布 secret，复制并逐项核对全部历史应用和固定资源
3. 确认补丁仓库有已公开的 `v1.12.2+14` 完整 APK，再以其为基础准备下一版增量；先用 `--prepare-only` 生成和还原补丁，不公开版本
4. 在切换发行提交中设置 `1.12.2+15` 和新的递增 versionCode，按正常 PR 流程合入 dev，再同步 main
5. 从 main 派发签名发行，填写可读更新说明并指定 `previous_tag=v1.12.2+14`，新版本只进入补丁仓库
6. 从群和频道分发新完整包，说明旧版更新检查及未下载资源的旧入口停用；已下载资源继续使用
7. 核对新公开包、增量、资源及迁移收据后，清理主仓库历史 Release，保留源码标签；后续主仓库只新增不带加号的正式版 Release

不需要用公开版本验证版本比较：自动回归使用内存构造的发行列表及测试 APK ZIP。`publish_release=false` 的 Debug 构建不会创建正式 Release；发布脚本的 `--prepare-only` 不创建任何标签、草稿或公开发行。

## 完整回归项

以下覆盖此次改址与既有更新行为。实际运行结果另填，不将准备的用例记为通过。

- U01：自动、手动检查共用新补丁仓库；版本说明、完整 APK、补丁和元数据链接均来自新仓库
- U02：关闭 Beta 时忽略所有带加号版本；开启时同时比较正式版和补丁版
- U03：版本按数字比较，`+10` 高于 `+9`；退出 Beta 不降级已有补丁版
- U04：更高基础版本正式版提供完整包；同基础版本存在成对补丁附件时提供增量和完整包
- U05：相同、较旧、空发行列表返回无更新；草稿、预发布、错误包名和非法标签不参与选择
- U06：可读 Markdown 原样展示，历史 JSON 正文仅提取更新说明；缺失补丁元数据时不提供增量安装
- U07：直接增量与跨多个版本的补丁链使用新仓库附件；校验基线、补丁和目标摘要
- U08：真实 Kong 包名、固定签名、递增 versionCode 和基线标签继续校验；跨基础或非递增增量拒绝生成
- U09：生成器保留未变 ZIP 原始记录，并逐字节还原目标 APK
- U10：补丁版只在补丁仓库创建 Release；正式版两个目的地都完成草稿上传后才依次公开
- U11：主仓库源码标签固定构建提交，禁止移动；新发行附件和文案链接对应源码提交与归档
- U12：只准备模式可生成完整产物和计划，无任何创建标签或 Release 的命令
- U13：历史迁移仅改目录与元数据，APK、补丁和资源 ZIP 字节不变；无 Git 标签的新草稿可核对并公开，已有完整草稿可复用，已公开且完整的目标不被改写；缺失、多余、损坏或无摘要附件明确失败，公开未成功或公开响应中的附件变化不写入完成收据
- U14：`resources-v1` 全部四组下载与导入导出正常；51 组新资源下载新地址，既有安装仍识别原资源版本
- U15：新资源产物只接受所选提交，目录、清单、文件大小和摘要完整；多余路径、重复项和符号链接拒绝
- U16：没有跨仓库凭据时发布预检明确失败；普通构建和 JVM 验证无需该凭据

## +15 一次性切换入口

Android Build 的 complete_repository_migration 默认为 false。本次从 main 发布 +15 时显式设为 true，并同时设置 publish_release=true、任务 :app:verifyCiPreviewRelease 和 previous_tag=v1.12.2+14。工作流先执行发布回归，再搬迁并核对全部历史附件，成功后构建和发布新版本，最后运行 cleanup_main_releases.py。

迁移会保留原始附件备份目录，生成包含源和目标文件摘要的 cleanup-receipts.json。清理脚本必须核对 +15 公开附件与本次 release-plan.json 完全一致、所有迁移目标完整公开、源发行集合和 ID 与快照一致、各源码标签提交匹配后，才按源 Release ID 删除；它不删除 Git 标签。收据和清理报告由工作流上传为独立 artifact。仅派发不表示迁移、发行或清理已经完成。

# 完整验证与发行顺序

1. 包管理四栏修复从独立工作分支派发 Android Build；旧的同主题 PR 更新后合入 dev
2. 核对 #49、#52、#55 的实际行为与已有构建结果，合入 dev；分仓分支基于最新 dev 整理为单个提交
3. 从分仓工作分支派发不发布的 Android Build 和 Android Tests；本地不运行编译、构建或测试
4. 合入 dev，通过发布同步 PR 将相同内容树同步 main
5. 从 main 派发签名发布，publish_release=true、complete_repository_migration=true、previous_tag=v1.12.2+14
6. 工作流迁移历史发行，核对源和目标全部附件，资源清单与源码中的新地址一致
7. 签名构建完成后生成并还原 +14 → +15 增量，上传完整配套产物并公开到补丁仓库
8. 重新核对公开 +15 的四项附件和本次构建提交，核对全部迁移收据、源发行 ID、大小、摘要、目标公开状态及源码标签；通过后删除主仓库旧 Release，保留所有源码标签

## 全量检查项

- P01—P05：四栏等宽、切换、模型上下文协议全称、长翻译和大字体，见[布局回归](../../fix/package-tabs-full-width/index.md)
- U01—U16：更新渠道、版本排序、完整包、直接与多步增量、APK 身份及逐字节还原、分仓、迁移和资源，见[分仓回归](../release-repositories/02-migration-and-verification.md)
- C01：普通文本、流式保存点和回滚均不露出隐藏协议；用户代码中的普通 meta 保留
- C02：聊天 WebView 挂载不抢焦点，交互后的网页输入仍可获得焦点
- C03：工具卡片在重试后不错误合并，完成后回放保持，后续块更新不反复解析长卡片
- M01：默认只读迁移不创建、上传或删除；显式迁移保留 APK、补丁 ZIP、资源 ZIP 的原始字节
- M02：完整迁移前、+15 未公开、公开附件损坏、源发行变化或目标缺失时，清理脚本拒绝删除
- M03：所有公开附件与构建计划一致时，仅删除迁移快照列明的主仓库 Release，源码标签保留

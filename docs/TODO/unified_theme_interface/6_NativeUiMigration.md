# 原生 UI 迁移

## 修改意图

按照依赖顺序把所有 Operit 控制的原生 UI 移入统一渲染契约。迁移期间只保留一个主题来源；每个已迁组件都从全局令牌、组件族和组件状态三层解析视觉样式，`MaterialTheme` 仅作为解析结果的原生投影服务尚未完成的页面。

## 顺序

1. 基础操作、输入、容器、列表、弹窗和反馈组件
2. 主应用外壳、顶部栏、抽屉、手机与平板布局
3. 设置首页、简单设置页和主题编辑器
4. 聊天消息、富文本、思考与工具结果、聊天输入区
5. 模型、角色卡、群组、市场和统计界面
6. 工作流、记忆、工具箱、文件和终端外壳
7. 启动、协议、更新、认证和普通错误界面

## 迁移规则

- 一个功能区域的页面、对话框、预览和特殊状态作为同一迁移单位
- 每次迁移同时删除该区域旧的视觉解析路径
- 新增页面必须登记宿主表面和主题契约
- 新增硬编码颜色、形状、动效和直接主题快照读取由静态检查限制
- 组件只能消费其契约登记的部件和样式属性，宿主继续强制语义、焦点、触控区域和事件生命周期
- 需要背景采样、液态或水材质的组件必须声明对应 Compose 宿主能力，主题激活前完成能力校验
- 外部内容保持内容所有者的视觉，Operit 宿主外壳使用主题契约

## 预期结果

- 所有登记原生路由使用统一主题上下文
- 业务层不直接依赖主题存储模型
- 内置主题迁移阶段保持当前视觉和交互行为
- 开发示例主题可以覆盖任意已完成的组件契约

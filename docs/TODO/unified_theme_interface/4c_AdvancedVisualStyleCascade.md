# 高级视觉样式级联与宿主能力

## 旧实现

`native_v1` 的 111 项已发布偏好覆盖背景、部分颜色、字体、聊天气泡和应用外壳，但组件圆角、边框、阴影、菜单、图标容器和玻璃参数仍分散在 Composable 中。现有组件目录只能描述状态和语义，不能声明部件可接受的视觉属性。

## 修改意图

建立 Android 无关的 Style API v1。主题只提供受限、可校验的视觉声明，Compose 宿主继续控制组件结构、触控、语义、焦点、状态来源和业务事件。Style API 的优先级固定为：

1. 全局语义令牌
2. 组件族样式
3. 单组件的部件、表面和状态样式

现有 111 项偏好仍由 `native_v1` 编译器读取、保存、重置、备份和恢复。它们不迁移到新存储，不改变字段、默认值、作用域或资源 URI。

## 样式模型

- 颜色：light/dark 成对 token、文字和图标前景、状态色、宿主 Material 角色引用
- 文字：字体资源、字重、字号、行高、字距和文本颜色角色
- 形状：矩形、逐逻辑角圆角和胶囊，支持 dp 与百分比角半径
- 边框：最多八层，支持内中外对齐、偏移、实色或渐变、虚线和透明度
- 阴影：最多四层外阴影或内阴影，具有颜色、偏移、模糊和扩散
- 材质：`solid`、`translucent`、`frosted`、`liquid` 和 `water`
- 模糊：内容模糊与背景采样模糊分别定义半径、裁剪和能力要求
- 图标容器：形状、材质、边框、阴影、容器尺寸、图标尺寸和前景色
- 菜单：面板、项目、选中、禁用、破坏性项目、分隔线、文字、图标、尺寸和内边距
- 状态：可用性、选择、交互、活动、校验、展开和内容轴；单条选择器最多四个等值条件

绘制顺序固定为外阴影、背景采样和材质、裁剪后的内容、内容模糊、内阴影、边框、整层透明度。组件不得自行重排这个顺序。

## Compose 宿主能力

能力按表面和版本声明。首批能力包括动态色、内容模糊、背景采样模糊、液态材质、水材质、内阴影、外侧边框和字体资源。`MAIN` 可声明完整材质能力；其他表面只登记自身实际提供的能力。

主题使用的能力必须在清单中声明，且宿主表面必须满足对应版本和范围。能力、组件部件、状态或数值不合法时，链接器产生结构化问题并拒绝安装或激活事务。

## 实施单元

1. Android 无关样式值、三层样式层、状态选择器、范围校验和结构化问题模型
2. Compose 宿主能力档案、样式链接顺序和运行时紧凑索引
3. `ThemeSurface` 绘制器及 solid、translucent、frosted、liquid、water 材质映射
4. `native_v1` 编译器和行为等价夹具
5. Theme Studio 的全局、组件族、单组件与状态编辑，以及生产同路径预览

## 验收

- 同一组件、部件和状态的全局、组件族、组件覆盖优先级可由纯单元测试证明
- 重复属性、循环令牌、冲突选择器、未知部件、超出范围值和未声明能力返回稳定错误码
- 复杂边框、逐角圆角、胶囊、透明度、文字角色、菜单、图标容器和五类材质均有目录场景
- 编辑器预览与生产渲染器对相同环境、状态和样式表产生相同渲染计划
- 未修改 `native_v1` 已发布字段和持久化行为

## 非目标

- 任意 UI 布局、Canvas 绘制命令、脚本、主题控制器或作者可执行代码
- WebChat、ToolPkg、Glance、Android View 和 WebView 内部内容的 Style API 入口
- 主题修改宿主的无障碍角色、最小触控区域、焦点顺序、导航、权限或事件生命周期

# 兼容基线

## 旧实现

已发布主题字段分散在默认值、持久化字段清单、类型化访问器、编辑器控件和运行时解析代码中。角色卡与群组使用固定前缀保存完整视觉快照，旧版全局数据只参与一次性迁移。

## 修改意图

建立 `native_v1` 字段契约，集中描述每个已发布字段的名称、类型、默认值、作用域分类和重置分类。现有 DataStore 键和值不迁移、不改名，现有读取与写入路径从该契约派生。

同时记录原生路由、独立 Compose 根、Canvas、Android View、Glance、悬浮窗和固定诊断面的表面清单，后续迁移必须更新该清单。

## 预期结果

- 已发布字段只有一个机器可读的定义来源
- 默认值、读取字段集合和兼容性测试引用同一份契约
- 旧记录解析为 `native_v1` 主题实例
- 新组件和新主题字段不能绕过契约直接加入持久化层
- 原生 UI 表面具备可检查的迁移状态

## 验证

- 对字段数量、名称、类型和默认值建立冻结测试
- 覆盖空作用域、旧版纵向重复字段、默认角色迁移、重置与删除差异
- 静态检查直接使用主题字符串键的新代码

## 实施记录

- `NativeThemePreferenceSchemaV1` 已登记 23 个字符串、49 个布尔值、13 个整数和 26 个浮点字段
- 默认值、目标元数据分类和四条已发布纵向字段关系已从模式派生
- 现有全局键、角色作用域读写、重置和迁移读取使用同一字段名称来源
- `ThemePreferenceSnapshot` 的类型化访问器已绑定字段描述
- 冻结测试覆盖字段名称、类型、默认值、元数据、旧字段关系和默认快照隔离
- 两次独立静态审查确认模式与上游 `main` 的已发布行为一致
- 初始实现的 `git diff --check` 已通过；Agent 未在工作树直接运行编译、构建或测试
- 推送后由 `operit-builder` 完成 release 构建，详细记录见 [验证与接口发布](./8_VerificationAndPublication.md)

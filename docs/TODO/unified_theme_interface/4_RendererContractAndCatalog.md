# 渲染契约与组件目录

## 旧实现

页面直接调用具体 Composable，视觉状态、业务状态和事件回调经常出现在同一个大型函数中。通用组件存在重复实现，聊天、工作流和工具界面还包含大量领域专用视觉逻辑。

## 修改意图

建立约 30 至 50 个稳定语义组件契约。每个契约具有固定 ID、独立版本、不可变状态、封闭事件、必需语义和受控插槽。颜色、间距、形状和时长属于令牌或组件样式，不单独形成扩展 ID。

宿主构造状态并执行事件，主题只获得有限的语义动作句柄。主题可以改变组件内部布局和视觉层级，但不能直接取得 ViewModel、导航器、权限服务、Android Context 或任意回调。

## 组件层级

- 基础令牌与宿主能力节点
- 通用操作、输入、导航、容器、反馈和数据展示组件
- 聊天、模型、角色、市场、工作流、记忆、工具箱和悬浮窗领域组件
- 应用外壳、页面内容、对话框和浮层使用少量固定插槽组合

## 预期结果

- 内置主题通过同一注册表实现全部契约
- 组件目录可渲染正常、禁用、选择、加载、错误、空白和流式状态
- 无障碍标签、角色、焦点顺序和最小触控区域由宿主强制提供
- 契约重大变更使用新主版本，增加能力使用兼容的小版本
- 安装阶段校验主题实现是否覆盖完整的必需契约集合

## 实施顺序

1. 建立 Android 无关的契约描述、版本、状态字段、事件、插槽、语义和目录校验
2. 以主侧边栏导航项验证宿主状态、封闭事件、受控图标插槽和 `native_v1` 参考实现
3. 扩展基础操作、输入、容器、反馈和数据展示契约
4. 登记应用外壳及聊天、模型、角色、市场、工作流、记忆、工具箱和悬浮窗领域契约
5. 建立可交互组件目录、完整状态矩阵和 Theme Studio 入口

首个最小单元见 [组件契约核心与导航项试点](./4a_ComponentContractAndNavigationPilot.md)，下一单元见 [基础组件契约与备份设置试点](./4b_FoundationContractsAndBackupPilot.md)。公开 Theme API v1 尚未冻结，本阶段新增类型均为内部草案。

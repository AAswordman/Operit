# 子代理归属恢复与数据库升级分离

PR #1484 的 23→24 迁移原来直接读取协作存储文件。任一 manifest 或引用文件损坏都会中断 Room 升级，导致普通聊天数据库也无法打开。

本次将迁移限制为添加三列和一个数据库内的待恢复检查点。聊天服务初始化后，在后台独立恢复子代理归属；只有存在检查点且有未填写归属的运行记录才读取协作文件，成功后与归属更新一起清除检查点，因此之后的冷启动也不重复读取。新建数据库没有旧记录需要恢复，不创建检查点。

恢复按持久化 run ID 与 child chat ID 双重匹配，仅填写两项归属都为空的记录，不覆盖已有归属、不修改正文。整批写入在独立事务内完成。协作文件继续严格校验；失败会记日志并显示错误，不清理原文件，也不标记为完成。修复存储后重新初始化或重启可重试，取消不会被当作存储失败。

验证覆盖结构迁移保留原记录、损坏或缺失的引用文件不阻断数据库打开、恢复失败后重试、匹配身份、重复执行及既有归属保护。实际真机由用户验收，本轮不安装到含旧文件夹预览数据库的手机。

# PromptHook 冷启动聊天绑定修正

[返回总计划](../README.md)

## 问题与范围

PR #1476 的最终审阅发现：核心服务改为订阅数据库更新流，PromptHook 却继续从以空列表初始化的懒加载 StateFlow 读取目标聊天。未打开主界面的后台冷启动请求可能无法取得已持久化绑定，使插件元数据使用错误的角色上下文。

## 实施

1. ChatHistoryManager 增加按聊天 ID 读取轻量元数据的挂起查询。
2. PromptHook 的绑定解析读取数据库单条快照，保持现有角色/角色组选择规则。
3. 回归用例覆盖初始空缓存、过期缓存绑定和已删除聊天，验证解析不读取界面缓存。
4. 同步本地 dev，提交并追加到原 PR #1476，保留维护者手动合并。

## 验证范围

本轮进行静态源码、差异与分支纯净性检查。新增 JVM 用例未在本地执行，未重跑 Android 构建或真机验证；此前已通过的 APK 不包含本修正。

已完成单条数据库快照查询和 Hook 读取路径替换，移除 Hook 对懒加载聊天流的读取。新增三个回归场景：空缓存下读取已持久化角色组、缓存旧角色卡时读取最新角色组、缓存残留时正确识别已删除聊天。回归夹具在用例结束后恢复管理器单例，不启动真实数据库或界面订阅。

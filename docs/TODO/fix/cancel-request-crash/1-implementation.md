# 实现与验证

## 代码变化

`MessageProcessingDelegate` 将发送准备、主请求、异常处理和收尾拆为独立的挂起函数边界。`ChatSendLifecycle` 专门处理取消与普通错误，并在不可取消的上下文执行收尾，避免在同一大型状态机中展开收尾和多次重抛取消。工作区钩子由最外层发送生命周期释放，准备阶段取消也会清理。

配置和角色信息读取显式传播取消，不把取消当作配置读取失败继续请求。取消入口继续等待发送与流任务结束，再保存已有部分回复及本轮统计。终态和完成通知检查发送任务及回合归属。

原 `+12` APK 的发送方法反汇编为 144696 字节、713 个寄存器和 1200 个异常处理入口，所有处理入口均以 `move-exception` 开始。拆分针对日志中的超大协程恢复与异常处理路径；未据此断言某个 DEX 指令无效。Android 原生退出是否消失仍需新构建确认。

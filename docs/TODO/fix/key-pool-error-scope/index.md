# 密钥池错误的实际请求范围

单密钥会话也累计每次请求失败，重试结束时被误套用密钥池文案。同一把密钥的六次请求因此显示为六把密钥。创建服务时还只判断池开关，空池没有直接使用单密钥会话。

- [x] 服务创建与配置检查统一识别关闭、空池及只有空白条目的单密钥模式
- [x] 只有实际选中过池内密钥的会话才能生成密钥池耗尽文案
- [x] 补充请求重试与配置验证回归代码，完成静态检查

## 改动边界

保留 HTTP 状态、服务端原因和异常链；不修改重试次数、等待时长及现有换钥规则。不为 409 增加密钥无效判断。

## 全量回归步骤

1. 关闭池开关，保留池内旧条目，请求连续返回截图中的 409。预期：按单密钥重试，最终提示保留 409 和原始原因，不含池文案。
2. 开启池开关，池内没有条目，单密钥有效。预期：配置检查通过并使用单密钥请求，错误不含池文案。
3. 开启池开关，池内只有空白密钥条目，单密钥有效。预期：与空池一致，不使用空白条目的可用性标记。
4. 单密钥与自定义透传密钥提供者连续失败六次。预期：发布五次重试通知，最终提示使用单密钥文案；异常链保留原始 HTTP 状态码和原因，不宣称试过六把密钥。
5. 开启池开关且含实际密钥，请求耗尽。预期：实际池会话仍可显示密钥池统计与最后错误，异常链中的原始 HTTP 状态码和原因保持一致。
6. 实际池密钥被标记不可用或禁用。预期：沿用原有筛选规则，不改变冷却及可用性记录。
7. 单密钥鉴权失败、余额不足、限流和服务器错误。预期：沿用既有终止或重试规则，原始原因不丢失。
8. 使用不支持密钥池的提供商。预期：继续使用该提供商已有认证路径。

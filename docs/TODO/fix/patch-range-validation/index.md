# 增量更新分段响应校验

旧镜像探测把任意非空 200–399 响应视为可用，六线程补丁下载却必须支持真正的 HTTP Range；更新页面和自动选择可能把不支持分段的站点选为可用。旧下载还通过额外普通 GET 的 Content-Length 取文件总长，分段响应合法但普通响应采用分块传输时会被误拒绝。

补丁镜像探测现在要求 206、匹配的 Content-Range 和完整采样。文件总长直接读取单字节范围响应，下载每段前检查范围与总长一致，写入严格限制在该段内，短读或多余内容明确失败。元数据仍使用原有普通下载，补丁和 APK 的哈希校验保留。

## 证据与限制

公开 `+11 → +12` 元数据的目标 SHA-256 与设备 `+12` APK 一致。调查期间 GitHub 和 Ghfast 对补丁及元数据返回有效 206 区间，另外两个抽查镜像发生连接重置或超时。原反馈当时的内部日志和所选镜像不可得，尚未复现其逐字错误，不能据此断言全部增量错误已解决。

已添加五项分段协议 JVM 回归，本地未运行构建和测试；提交后派发 Debug 与 JVM Tests，结果待工作流完成。

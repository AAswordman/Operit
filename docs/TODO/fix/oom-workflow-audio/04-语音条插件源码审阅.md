# 语音条插件源码审阅

审阅对象为 `com.operit.voice_bar`，版本 `0.5.5-four-provider-voice-library`，包文件 SHA-256 为 `ff29435b9625ee3483a2711d81e3a22f2d43a769938aa63986545a2d8d16bf19`。包内包含五份压缩 JavaScript 和 manifest，没有 TypeScript 原稿。本轮仅解压和静态审阅，未安装、执行、修改或重新打包插件。

## 实际调用路径

`dist/main.js` 注册 `<voice>` 标签，解析 `src`、`dur`、`text`、`hash`，生成固定 28 根装饰波形，并返回 `dist/ui/voice_bubble.ui.js` 的默认 `Screen`。宿主 `JsExecutionScriptBuilder.normalizeComposeResult` 会把带模块标记的函数转换为资源路径，再交给 `ToolPkgCommonBridgePlugin.parseComposeDslResult`；这里不是把函数直接误读成字符串路径。

`Screen` 为每条语音构造 HTML 和一个 WebView，HTML 中的 `<audio preload="metadata">` 直接引用本地 `file://` 文件。播放、暂停、进度和结束由 HTML 音频事件处理，没有 `AudioContext.decodeAudioData`、独立 MediaPlayer、音频整文件读取或定时器循环。播放器实际不经过 `MediaPoolManager`、宿主资源回调或本地网页服务器。

文字展开按钮向控制台输出 `VOICE_BAR_TOGGLE`，宿主派发 `onConsoleMessage` 动作，动作通过 `useState` 修改展开状态并重绘 `Screen`。HTML 本身不包含展开状态，因此正常展开不必重新创建或重新加载音频 WebView。

## 已确认并修复的宿主回调累积

宿主 `JsComposeDslBridge.createContext.registerAction` 为函数属性生成递增 ID，原实现将函数一直保存在 `runtime.actionStore`，没有在界面重绘后移除旧回调。`JsComposeDslRuntimeScript` 的动作响应和重新渲染会继续复用这个上下文。语音条每次执行 `Screen` 都创建新的 `onConsoleMessage` 闭包，因此展开收起会不断增加旧闭包，直到引擎销毁。

本轮修复将界面树回调标记为可按版本回收的资源。内部渲染响应携带上下文 ID、版本和回调计数；普通页面、弹窗和 XML 宿主在 Compose 提交后确认当前树，删除此版本之前已无引用的树回调。清理同时保留当前树、子节点、插槽、修饰符、state/memo 中缓存节点，以及已登记但尚未完成的动作。尚未提交的新版本、其他上下文和迟到确认均受版本边界保护。控制器独立注册的 WebView 接口回调继续按原上下文生命周期保留。

这项修复不要求插件更改 XML 或重新打包。它修正了一条实际可达的持续引用路径，但没有测量原反馈设备的内存，不能据此断言其解释了全部总结或语音条 OOM。

## 插件内独立问题

<details>
<summary>独立缺陷与证据边界</summary>

- `voice_bar.js` 的 `sayImpl` 内部完成函数为 `function r(e){t?t(e):r(e)}`。缺少 `__complete` 时会直接自递归；正常导出的 `say`、`say_fav` 都显式注入该回调，已读调用点没有证明危险分支可达，因此不将它列为原始 OOM 根因
- `probeWavDuration` 把 `2>&1 || true` 放入 `Tools.FFmpeg.execute` 参数。宿主接线到 `StandardFFmpegToolExecutor` 的 `FFmpegKit.execute(command)`，并不通过 shell，因此这些符号不具备 shell 重定向和条件执行语义。该命令还以 `-f null -` 形式进行输出处理，不适合仅获取媒体时长。精确运行错误和实际解码开销未执行验证
- URL 输出分支直接下载到 `.wav` 路径，没有依据 `sourceFormat` 转码。MOSS 明确请求 MP3 并返回 MP3 URL，因此路径后缀不保证实际编码是 WAV；只有 Base64 和 Buffer 分支显式执行复制或转码。播放、时长和收藏的实际影响需要单独验证
- MiniMax 十六进制音频分支使用 `Buffer`，ElevenLabs 使用完整 `contentBase64`，会在合成阶段处理完整二进制表示。它们与展示已有语音条是不同路径，尚无原始分配调用链证明这两个分支导致当前反馈

## 已排除的过度结论

WebView 的 `remember` 和宿主销毁逻辑确实存在；不能将正常重绘直接等同于重复创建 WebView，也不能因为音频元素未自行清空 `src` 就断言播放器永久泄漏。XML 引擎也有租约计数和身份校验释放。多个可见语音条各自具有 WebView 和执行引擎，其总体开销仍需测量。

总结入口没有自动播放音频，插件入口也没有注册总结 Hook。源码审阅没有发现 WAV 引用自动递归生成 XML 的路径。反馈中的同时发生仍需借助 OOM 堆栈、原始聊天与设备内存数据建立因果关系。

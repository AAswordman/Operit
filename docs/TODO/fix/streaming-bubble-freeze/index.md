# 流式气泡停更修复

基于 `refactor/package-layout` 的 `a284c65e218704e746977e9751d2e6dce7cd2198`，继续更新 PR #67，目标 `dev`。不从主分支或 dev 新建分支。

## 问题与目标

用户反馈流式消息中工具继续执行，正文却停留在早期内容；切换窗口后短暂恢复，工具状态刷新后可能再次退回，输出结束后显示完整。源码调查发现 PR #49 的显示过滤器在判断 Markdown 代码范围时扫描整段原文，将工具返回源码中的反引号误算为外部代码起点，后续协议块及正常正文可能一直缓存到 `finish()`。

修复需要让已闭合的工具、思考及其他独立 XML 内容不污染外部 Markdown 上下文，后续正文在上游结束前持续显示。保留真实代码示例、元数据隐藏、重试回滚、PR #55 的工具块边界和子流释放。

## 实施范围

1. 在 `core/chat/protocol/ProtocolMetaDisplayFilter.kt` 的代码上下文扫描中识别独立 XML 边界，处理属性引号、CDATA、注释、自闭合及同名嵌套；只影响 Markdown 上下文判断，不改写显示正文和持久化原文
2. 增加 JVM 回归，断言工具源码含未配对标记后，普通正文在 `finish()` 之前出现，覆盖分片、多个工具轮次、回滚和真实代码示例
3. 增加 Android 气泡回归，使用实际流式过滤、时间线与显示组件，在源流保持打开时切换界面、刷新状态并继续追加工具和正文
4. 更新完整验证记录、提交并推送原分支，派发 `assembleDebug` 与 Android Tests；不等待或轮询 CI

不会仅凭源码推导把用户的完整现场标为已复现。若设备用例不能执行，如实记录，仓库工作流与设备结果分别填写。

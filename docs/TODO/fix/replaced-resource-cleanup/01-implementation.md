# 保存与文件生命周期

## 旧行为与目标

资源选择器为每次导入生成新的私有文件名，主题保存和头像保存只修改配置中的路径。只有未保存的主题草稿会清理临时资源；已保存资源被替换、主题被重置或角色被删除时，旧文件仍可能残留。群组默认头像另有直接删除旧路径的逻辑，没有检查其他主题是否共用该文件。

目标是让文件生命周期与持久化引用一致：先保存新引用，再释放旧引用；保存失败保留旧资源；仍被其他配置引用的文件继续保留。

## 新增资源包

`app/src/main/java/com/ai/assistance/operit/data/resources/PrivateResourceCleanup.kt` 包含资源变更协调器和托管文件管理器。

`PrivateResourceCleanup.update()` 用同一把协程锁串行处理用户主题与全局显示配置的资源变更。它读取变更前的资源引用，执行原有 DataStore 保存，然后在 IO 上检查两份设置的全部持久化引用并清理旧文件。保存抛出异常时不进入删除阶段；保存成功后的清理在不可取消的协程区间完成，避免设置页退出留下本次替换的旧文件。引用读取、路径解析和文件删除失败会记录日志，已经保存的新配置仍然有效。

`ManagedResourceFiles.references()` 识别背景、头像、字体和气泡背景的资源字段，包含角色卡与群组的主题前缀及旧全局主题字段。`deleteUnreferenced()` 规范化文件 URI 和绝对路径，使不同写法指向同一文件时仍按同一个引用保护。删除对象必须是 `filesDir` 根目录下具有应用资源命名前缀的普通文件，并且在两份配置中都没有引用。文件夹、外部路径、内置资源和业务文件不会进入删除操作；不会遍历目录清理未知存量文件。

## 接入位置

`UserPreferencesManager` 的角色卡和群组头像保存、主题替换、主题修改、主题重置、主题复制、主题删除和旧全局主题迁移统一经过资源协调器。角色或群组删除原本就调用主题删除，因此其不再共用的图片、字体和头像会随配置引用一起释放。

`DisplayPreferencesManager.saveDisplaySettings()` 和 `resetDisplaySettings()` 使用同一协调器，覆盖全局用户头像的替换、清空字符串和显示设置重置。全局头像原有的即时保存方式不变；用户和 AI 头像、背景与字体仍在主题草稿保存后才释放原资源。

`CharacterGroupCardManager` 删除默认群组头像重建后的直接文件删除，改由头像保存入口检查引用统一处理。默认头像生成和成员变化的触发条件保持不变，共用旧群组头像的其他主题继续可用。

`FileUtils.copyFileToInternalStorage()` 在输入和输出流完整关闭后返回新资源 URI；复制失败清理本次创建的半成品文件。取消异常继续传播，选择器没有拿到新 URI 时不替换原配置。

## 兼容性

不修改 DataStore 键名、角色数据、主题格式、资源 URI 或文件保存位置，不增加设置项。已保存的资源继续使用原路径，在下次替换、清空或移除最后一个配置引用时按同一规则释放。

关闭资源启用开关不会清空路径，因此不会删除还可重新启用的文件。清理失败仅记录问题，不将已经保存成功的设置改回旧值。

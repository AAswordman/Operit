# 实现记录

本次按同一分支、同一 PR 交付，供同一安装包集中回归。以下描述实现行为，运行结果见 [验证记录](verification.md)。

## 1. 主题、布局和交互

标准页面顶栏与状态栏覆盖区统一使用不透明的主题背景色，并配对主题前景色。主题目标选择器、角色卡列表和页尾名称显式使用 `onSurface`。崩溃报告中的原因标签去掉红色背景容器，仅保留错误文字颜色。

记忆库控制区在可用页面高度内固定为 20%，空间选择、搜索、文件夹和操作合为三行。窄窗口和较大字体采用紧凑操作，控制区可滚动；搜索框使用最小高度约束，避免强制固定高度裁切文字。下方图谱或列表使用剩余空间。

语音服务的语速与音调改用已有 `WorkbenchSlider`，保留 0.5–2.0 范围及步进。聊天请求浮点动画移除气泡模式的向上偏移，增加顶部留白，主题预览同步调整。

## 2. 工作区

工作区入口序列只消费一次，打开文件时同步记录当前入口已经处理，防止可见性变化或旧的文件列表请求再次覆盖活动标签。已有标签继续复用内存内容。编辑器工具栏使用主题表面与前景配色，编辑器尚不可用时禁用撤销和重做。

文件浏览器在刷新右侧提供多选入口，支持勾选、全选过滤列表、复制、剪切、确认删除和退出。目录读取成功后才校正选择，避免初始空列表清空恢复的选择；切换目录或环境清除原选择。文件操作期间阻止目录导航，操作完成后刷新列表。

剪贴板保存完整来源列表，按环境和路径去重。同环境剪切使用移动；跨环境剪切逐项复制成功后再删来源。粘贴前检查整批目标不重名、不覆盖现有项目，也不进入来源目录自身或后代。成功的剪切项逐项移除，中途失败保留未完成项。批量删除捕获确认时的完整来源信息，成功一项便更新对应选择。

批量文件操作不提供整批事务回滚。复制成功后若来源删除失败，会保留错误、来源及已生成的目标，后续处理仍需遵守目标重名检查。

## 3. 媒体发送与预览

新录音直接生成在 `/storage/emulated/0/Download/Operit/cleanOnExit/`。语音条持有该 WAV 文件的引用；STT 读取同一录音，音频理解和直接音频请求创建请求期副本，结束后只清理这些副本。未发送录音继续按会话生命周期清理，已发送录音按原消息保存。

理解文字回写时保留音频输入类型和原文件信息，并用可选的 `resolved="true"` 标记明确区分缓存结果与钩子补充文字。当前轮次的文本请求复用已解析结果，直接音频请求可以携带原录音；后续用户轮次只保留历史转写文字。直接音频请求改用完整的音频加文本片段对应替换项，切换为文本输入时不重复附带原转写。首次请求的既有直接音频、音频理解功能模型、STT 处理顺序和取消行为保留。STT 语言使用当前应用语言。

请求解开语音条时，直接音频、音频理解和 STT 分支均附带同一原录音的文件描述，包含路径、文件名、类型和大小。原实现只返回音频池链接或识别文字，会丢掉语音条内唯一的原文件引用，导致对话模型收到文字却无法继续读取录音；普通附件列表本来为空，因此没有其他路径补上引用。文件描述仅进入请求，不写入转写正文，也不增加界面的普通附件标签；上下文估算同步计入该描述。

已发布的版本 1 文本型语音及未带缓存标记的版本 2 录音继续解析，不强制迁移旧路径。语音条仍通过专门显示层渲染，不增加普通音频附件标签。返回前台和播放前核对原文件，文件不存在时整条替换为文件标签并提示“文件已不存在”，其他播放错误继续显示播放失败。

图片、音频和视频在模型媒体链接后紧邻保存带路径、名称、MIME 类型和大小的原附件描述，属性统一转义。两种聊天样式将这两份描述视为同一附件，不重复显示媒体池标签。图片组、附件弹窗和语音条从原文件读取，回到前台及点击时复查文件；原文件缺失则显示可点击标签，不再留下透明空图。文件仍在但图片解码失败时使用“无法预览此媒体文件”标签，避免把损坏文件误报为已删除。

历史媒体设置板块及对应偏好读写、草稿字段、校验、重置逻辑和九语种资源已删除。正式发送与上下文估算共同调用 `currentTurnMediaHistory`：只保留历史末尾与当前输入相同的用户消息，其他消息移除模型媒体链接，语音条转为已存文字；没有新输入的续写移除全部历史媒体。比较兼容群聊用户前缀，避免已回复同文消息和角色桥接消息被误认成当前用户输入。处理只作用于请求副本。

上传原文件和新录音使用 `cleanOnExit`。发送用图片与音视频池继续承担编码和本轮工具处理；新上传媒体的预览不依赖池的容量与淘汰。没有原附件描述的已发布旧池消息保留原格式读取，无法恢复已经丢失的文件。应用现有启动清理仍会实际清理 `cleanOnExit`，预览持续至原文件真实被清理为止。

## 4. 总结阈值和本地化

总结消息条数范围统一为 1–50，默认仍为 16。草稿、保存接口与设置工具使用同一上限。已有配置不在读取时被重写，兼容接口修改其他总结字段时可保留原阈值；新输入受范围校验。

用户协议新增英语、日语、韩语、西班牙语、马来语、印度尼西亚语、巴西葡萄牙语和罗马尼亚语八份正文，均直接撰写，不依赖在线翻译。中文原文保留，Android 根据应用语言选择对应 `raw` 资源，语言变化后重新读取。语言选择器使用当前界面语言显示语言名称，跟随系统项继续使用本地化资源。

工作区多选、媒体文件缺失及无法预览提示提供九种语言资源，总结阈值范围同步更新九种语言；删除已不再使用的历史轮次设置及过期计数文字。

## 5. 编译修正

语音请求显式导入 `VoiceTextSource`，使已解析结果分支使用正确的来源类型。记忆库在 `BoxWithConstraints` 接收器内先计算控制区高度，再传给内部 `Column`，避免 Compose DSL 接收器屏蔽外层 `maxHeight` 导致 Kotlin 编译失败。

[DONE]

## 6. 工具图片引用与时间提示

`ConversationMarkupManager` 抽取工具结果图片前核对对应图片池数据，只将可用引用移出工具正文。`MediaLinkParser` 支持按指定 ID 集合移除图片链接，未注册的源码示例保持原样，避免被当成真实图片单独显示；真实图片继续输出一次，纯文字及其他媒体保持原有处理。

九种语言的 `chat_generated_at` 统一改为 `time: %1$s`，继续使用消息完成时间及既有日期格式。媒体绑定和特殊文件名回归样例显式提供 `AttachmentInfo.fileSize` 必填元数据。

[DONE]

## 7. 过期图片合并标签

`SentImageGroup` 按同一条用户消息统计原文件缺失的图片，使用 `ExpiredImageGroupTag` 显示一个紧凑标签，不再逐个列出失效文件名。标签右上角以小字显示过期数量，点击提示“文件已不存在”。气泡和光标样式共用该组件，仍存在的图片继续显示原图片组；尚存但无法解码的图片继续使用无法预览提示，避免误报为文件缺失。过期数量提供九种语言资源。

后续测试包统一使用现有 Debug 变体，应用 ID 为 `com.ai.assistance.operit.debug`，不再派发 Release 变体作为开发测试包。

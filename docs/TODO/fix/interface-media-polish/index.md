# 界面与媒体交互修复

1.12.2+11 的实际使用反馈显示，部分页面顶栏会透出聊天背景，主题编辑目标名称没有继承前景色；协议正文、语言名称、记忆库布局和工作区交互也存在不一致。此次在同一工作分支实现，集中提供一个面向 dev 的 PR，便于使用同一安装包回归。

## 处理范围

- 顶栏与状态栏区域使用当前主题表面色，主题目标名称使用当前前景色
- 用户协议完整正文按应用语言选择资源，语言列表使用当前界面语言显示名称
- 记忆库上方控制区根据可用窗口高度约束，兼顾 360dp 与 590dp 配置
- 崩溃报告原因只保留红色文字，去掉文字背后的红色块
- 工作区打开文件后统一切换到对应标签，调整编辑器工具栏配色，增加多选及批量复制、剪切和删除
- 语音条转写同时保留可供音频理解的文件，文件位于 Download/Operit/cleanOnExit，消息通过语音条展示，不额外显示文件标签
- 对话轮次触发总结阈值上限由 20 提高到 50，读写和界面约束一致
- 语音服务的刻度滑块改用项目现有 WorkbenchSlider
- 下移聊天请求期间的浮点动画，并保持主题预览一致

## 媒体发送与预览

删除历史媒体保留轮次设置及其读写、校验和资源。图片、音频、视频与语音条只在当前用户轮次携带媒体内容；后续对话、手动续写及上下文估算移除历史模型媒体链接，保留普通文字，不改写聊天存档或删除原文件。同一轮内工具调用继续使用本轮请求上下文。

上传附件及新录音使用 `Download/Operit/cleanOnExit` 中的原文件提供预览。新消息保存媒体链接紧邻的原文件描述，两种聊天样式只生成一个预览入口；请求池的容量淘汰不影响原文件。同一条消息内原文件已缺失的图片合并为一个可点击标签，右上角显示过期数量，点击提示“文件已不存在”；其他媒体缺失仍使用文件标签；图片解码失败显示无法预览标签，避免留下空白缩略图。

`cleanOnExit` 仍执行应用现有的启动清理，预览有效期以原文件真实存在为准。未保存原文件描述的旧池消息继续按旧格式读取，已丢失的旧池文件无法由新规则恢复。

## 工具结果与消息时间

工具结果中的源码可能包含图片协议示例。只有图片池中存在真实数据的引用才作为图片抽取；未注册的示例留在工具正文中，避免在折叠工具结果之外出现单独 XML 卡片。真实图片仍按原有方式提供给模型。

消息完成时间前缀在九种界面语言中统一显示为 `time: `，日期格式继续使用 `yyyy-MM-dd HH:mm:ss`。

## 兼容性与验证

保留已发布数据、历史消息及设置的兼容性。保持变更局限于反馈涉及的功能。按用户约定不执行本地构建和测试；完成代码及相称静态核对后，在工作分支派发仓库工作流，再创建统一 PR。工作流受理与构建通过分别记录。

代码改动已完成，工作流中的语音类型导入与记忆库高度接收器编译错误已在源码中修正；新的构建结果待确认。代码行为见 [实现记录](1-implementation.md)。完整回归项目和待填写结果记录于 [回归清单](verification.md)。仓库工作流结果与 Android 界面回归尚待记录，当前状态不表示已通过构建或发布。

# Gemini 模型列表使用配置的服务地址

## 问题

Google 和 Gemini 通用共用的模型列表地址生成逻辑按域名字符串分类。普通中转地址会被直接替换成 Google 官方 v1beta/models，导致列表请求与用户配置的服务不一致。带 Vertex 字样的代理域名也可能被错误分类。

## 修复

解析用户提供的 HTTP URL，保留协议、域名、非默认端口、网关路径前缀及已有 API 版本。已有 models 路径用作目录地址；完整生成或流式生成地址截取到 models；版本根地址补 models；服务根地址补 v1beta/models。保留 Vertex 项目、区域和发布方路径。网关查询参数保留，流式传输参数 alt=sse 和 URL 片段不用于模型目录请求。

无效 URL 直接报错，模型列表不再切换到其他服务。现有请求鉴权继续由请求构造阶段将配置的 API Key 写入 key 查询参数。

## 验证

新增 9 项 JVM 回归代码，覆盖 Google 和 Gemini 通用、官方与自定义域名、端口和前缀、明确版本、生成端点、查询参数、Vertex、无效地址及其他协议路径。本地不执行编译、构建、测试或带用户 Key 的模型请求；更新 PR #158 后通过远程工作流验证。

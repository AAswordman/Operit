# 实现与边界

本次补录：用户确认目前 Bug 均已修复，本页待填写的验收说明已按用户确认同步。验证来源及现有 CI 记录见[验证结果补录](../../chore/distribution_integration/06-验证结果补录.md)。

插件页的首次加载标记改为跟随当前 JS 引擎，而不是从上一个已销毁的页面恢复。普通页面重建后会重新触发 `onLoad`；声明 `keepAlive` 的页面继续使用原有保活规则，不因切到 AI 对话而主动重载。

页面和插件弹窗的建树、重建树与首次 `onLoad` 使用 30 秒的执行边界，超时通过既有错误界面反馈。页面的初始渲染直接归属 `LaunchedEffect`，阻塞脚本等待使用可中断 IO，并继续传播生命周期取消；用户主动触发的长任务沿用原有调用行为。

聊天草稿由独立的 `ChatDraftRepository` 按聊天保存文字与选区，输入时异步写入私有 SharedPreferences，切换或重建所有者后读取同一份草稿。发送、手动清空及聊天删除清理对应草稿，分组与角色卡批量删除后只核对有草稿的聊天。Android 恢复已有 Activity 时跳过“启动新聊天”，保留原聊天的恢复入口。

MCP 启动批次返回实际 Job，启动页等待它结束，取消启动页初始化任务时同时取消批次。所有插件验证完成后先通知加载结束，再生成缺失的 AI 描述；模型响应不再计入启动页等待。完成及失败都终止启动页超时计时，保留实际结果。

<details><summary>修改依据与验证范围</summary>

- 页面原来只恢复 `hasDispatchedInitialOnLoad`，脚本、界面树与执行引擎却重新创建，导致新页面跳过数据初始化。现在加载标记与引擎生命周期一致。
- 原先页面脚本等待没有超时，且初始渲染另启 `rememberCoroutineScope` 任务。现在建树和首次加载有结束边界，离页取消能中断对应等待。
- 先前按聊天保存的草稿只有进程内 Map，无法跨进程恢复。新增持久层保持文字、换行、空白和选区，不保存输入法的临时 composing 状态。
- 原先 MCP 批次在独立 scope 启动，上层提前结束初始化保护；且通知完成前会等待 AI 描述。现在实际批次可等待、可取消，插件就绪与描述生成按顺序分别处理。
- MCP 连接、桥接和具体插件自身的网络超时设置未调整。本轮不能证明所有外部插件的超时都由上述路径造成。
- 新增 4 项草稿单元用例：重建所有者后恢复、不同聊天隔离、清空后不复活、空白文字原样保存。使用内存 SharedPreferences 替身检查持久层契约，不代表已完成 Android 进程恢复验证。
- 本地只做源码、调用点和差异检查，不执行编译、构建或测试。Android Build、Android Tests 由个人分支工作流执行；结果与设备回归另行记录。

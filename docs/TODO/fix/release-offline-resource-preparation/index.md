# 签名发行准备当前源码资源

## 背景与范围

+21 签名候选在 verifyCurrentOfflinePackSources 失败。固定资源来自旧源码快照，当前 super_admin 与公共类型已有变化；普通 Debug/JVM 的固定快照校验通过，不能代替发行时的当前源码校验。

在既有签名入口中准备当前白名单扩展和模板，核对并复用已公开的共用引擎与 OCR，生成同轮目录及源码快照，再执行原有严格校验。正式发布在公开 APK 前核对本轮准备记录、源码提交及 APK 内的目录，再公开资源；资源失败不创建应用 Release。权限预检同时核对更新和资源仓库。准备证据使用现有 Android reports 上传路径，正式发行元数据附带资源公开结果。

生成目录只替换当前 runner 的打包输入。普通 Debug/JVM、独立 publishOfflineResources 入口、应用版本 1.12.2+21 / 77 和固定签名继续使用既有规则。

## 实现步骤

1. 新增当前源码资源准备及发行核对脚本，保留严格校验和不可变发布器 [DONE]
2. 在已有签名入口于 Gradle 前准备资源，正式发布入口先公开资源再公开应用 [DONE]
3. 补充当前资源准备、APK 目录对应、发布失败阻断及资源仓库权限回归 [DONE]
4. 静态检查后在工作分支派发签名候选及 Android Tests，通过个人 PR 同步开发与主分支，再派发正式发布

## 完整回归清单

- R01：只修改并提交公共类型；旧严格校验拒绝，准备新目录后严格校验通过
- R02：更新白名单扩展及构建产物；APK 使用本轮目录与新扩展指纹
- R03：共用引擎/OCR 下载内容损坏或大小不符；停止且不覆盖原固定输入，不发布
- R04：缺少白名单构建产物；明确失败，不使用旧扩展
- R05：publish_release=false 的签名候选；准备和校验通过，不上传资源
- R06：publish_release=true；资源公开并核对成功后才创建和公开应用 Release
- R07：严格校验或资源发布失败；不创建源码标签或应用 Release
- R08：派发提交、准备记录或源码快照与当前 HEAD 不同；拒绝发布
- R09：构建改写工作树 JS；指纹仍来自本轮已提交索引与源码快照
- R10：相同输入重复准备；资源指纹稳定，已有正式资源不被改写
- R11：普通 Debug/JVM；继续校验开发固定快照，不自动发布资源
- R12：检查 Android reports；目录、快照、校验清单和准备摘要对应本轮 APK
- R13：资源仓库发布权限不足；在昂贵构建前明确失败
- R14：完整 APK 与 +20 增量；固定签名、版本递增、资源 URL 与还原校验仍成立
- R15：APK 内目录与本轮生成目录不一致；拒绝资源及应用发布
- R16：--prepare-only；核对 APK 与准备记录，不写资源或应用发行仓库

# UI 准确率改进与验收

## 用户目标与证据边界

先提高首次点击正确率，再优化速度。单次点击正确率目标至少 90%，尚无覆盖目标设备与应用的实测结果。启动、导航、识别、输入、提交和结果确认需要分别记录。哔哩哔哩硬核会员题目可作为首项真实任务验收，UI 操作正确与知识答案正确分别计分，不将考试通过作为唯一 UI 指标。

用户提供的 DSH-Go 截图显示工具报告“没有可读文字”，页面可见“Lv6 硬核会员／进阶试炼”宣传图与确认浮层。截图没有包含该工具的实际调用记录，因此不能认定它使用 OCR，也不能据此认定 OCR 已失败。节点树、截图和 OCR 是不同的信息来源：图片或 Canvas 文字可以肉眼可见而不在无障碍树中；OCR 得到文字也不等于得到可操作的控件。截图本身尚未展示题干与选项。

## 代码现状

截至 dev e9bb154a，外层 run_ui_subagent 把 intent 交给 PhoneAgent；内部截图、调用 UI_CONTROLLER、解析动作并注入输入，循环到完成或 max_steps。默认步数为 20，外层直到任务结束才返回汇总。基础工具已经提供截图、点击、输入、长按、滑动和按键。

尚未合入的 PR #148，提交 061bedbb，增加主屏节点观察与执行：

- 外部无障碍提供者返回 XML，在宿主解析、筛选可见节点，生成带 screen/ref 的紧凑摘要
- 节点派发前重读页面，检查包名、唯一目标、可见性、焦点和观察版本
- 节点点击最终仍转换为中心坐标，经所选输入通道投递，并非提供者原生 ACTION_CLICK
- 节点动作后固定等待 300 毫秒，再读取页面；输入逐字回读，点击是否达到目标页面仍需后续判断
- 动作后快照可在 1000 毫秒内供下一轮使用，Inspect 和 Observe 显式切换图像、节点观察
- 当前提供者为预编译 accessibility.apk 1.5；原生节点点击、提供者限时采集、事件订阅均未接入

#148 已有启动受理状态、同任务重复 Launch 拦截、无进展停止及点击投递反馈，不能将这些现状写成已发布版本能力。宿主读取仍依赖远程 Binder 完成，外部计时预算不能硬中断该调用。尚无各阶段真机耗时，不能断言节点读取是全部延迟的来源。

## 建议实施顺序

### 一次动作一次工具调用

主对话负责目标、页面进度和下一步，执行器一次只做一个明确动作，立即返回动作信息及观察。启动、点击、输入、滑动和按键分别调用，不把搜索、进入详情和答题继续隐藏在一个内部任务循环。一次输入不隐含点击搜索或提交。返回的是可读的行动说明与结果证据，不依赖展示模型内部推理。

保留显式屏幕会话、display 标识和应用上下文。UI 模型可以为单个语义目标做图像定位，不在这一调用内自行执行下一步。实际替换外部接口前，需明确已发布接口的兼容边界；这份方案尚未实施接口更换。

### 观察必须说明来源和覆盖范围

返回包名、显示屏、观察时间、页面版本、控件区域、节点可见性，以及使用的节点或图像来源。识别不到节点文字只表示该观察来源未提供文字，不能直接推断页面无题目或请求用户抄题。页面存在大块图像或 Canvas 时，显式图像观察应能覆盖题干、选项和操作区。

截图、OCR 文字框与控件框统一坐标系，记录缩放、旋转、状态栏和窗口偏移；屏幕选择、截图和输入必须对应同一个 display。节点标签应包含附近标题、所属卡片和可点击祖先，避免把“规则观看”和“开始答题”仅当成相邻文字。

### 目标定位与点击分别校验

具备原生可操作节点的控件，应在提供者侧明确支持通过有效节点执行 ACTION_CLICK 并报告受理状态。图像控件使用可见区域内的坐标点击。两种动作都检查唯一目标、遮挡、当前观察及实际可用区域；保留“指令已投递”与“页面达到预期状态”的区别。

原生节点点击涉及提供者接口和构建产物，当前宿主不能仅凭已有坐标接口宣称具备这一能力。

### 页面进度与动作后条件

动作必须对应可检查的后条件：点击开始后出现题干与选项；点击选项后出现选中状态；点击下一题后题号或题目变化；点赞后确认状态变化。不要只用整页像素变化或手势受理作为目标达成证据。

记录同一页面、同一目标和后条件结果。没有进展时禁止继续机械重复同一点击，应重新观察并检查按钮是否可用、规则阅读或勾选条件、弹窗和遮挡。已知动作可能执行但结果未知时，先核对现状，不能自动重发可能重复提交的动作。

### 分阶段计时后优化等待

分别记录节点采集、XML 解析与摘要、截图和图片传输、模型首字与完整动作、输入投递、页面稳定、结果校验耗时。统计各阶段中位数和 P95，以发现真实瓶颈。

提供者端应支持有界采集、窗口变更事件和带版本的缓存；动作后等待相应状态出现，避免把固定 300 毫秒或固定长延时当成页面已就绪。输入前仍需确认目标有效，不以减少读取次数替代正确性检查。

## 首轮验收记录

- 基础操作：冷启动与后台恢复、搜索框定位、输入、搜索、打开指定结果，核对真实目标
- 页面边界：明暗主题、滚动、键盘、系统弹窗、悬浮层、加载动画、相似按钮、图片和 WebView 文字
- 真实任务：进入哔哩哔哩试炼，识别并完成进入答题的前置条件；识别完整题干和全部选项，按已知答案选中并确认，进入下一题，保持题目和进度对应
- 样本记录：至少 100 次有明确预期目标的点击，分布于不同控件与页面；记录首次命中、错点、重试、拒绝派发、人工接管和完整任务成功率
- 点击指标：首次正确点击数除以已派发点击数；拒绝率、人工接管率和观察覆盖率另列，不能通过只执行简单按钮掩盖失败
- 耗时指标：记录每步及各阶段 P50/P95、首次动作到任务完成的总耗时，不使用最终回答中的 token 数推断耗时原因

这份方案是后续实现与真机验收的依据，单步工具、原生节点点击、事件等待和 90% 点击正确率均未在本次启动修复中完成。

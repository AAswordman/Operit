# 工具生命周期大结果内存开销修正

日志中的致命异常发生在 `ToolPkgToolLifecycleBridge` 把 ADB 结果编码为 JSON 文本时。失败分配约 10.3 MiB，进程堆上限为 512 MiB；此前悬浮球绘制的 ANR 采样与该致命异常属于不同堆栈，不能据此认定绘制代码是内存耗尽根因。

## 范围与实现

- 无工具生命周期订阅时，不创建、排队或序列化事件载荷；同步拦截直接允许工具继续执行
- 事件队列保存延迟载荷，实际投递时检查订阅并只构建一次，避免排队期间保留提前生成的结果文本和结构化副本
- 使用序列化 JSON 节点直接转换事件字段，保留 `__type`、文本、布尔、数值、数组与空值；大字符串复用原引用，不先生成整段转义 JSON 文本
- 保留原工具结果、插件事件字段、工具输出全文及现有投递顺序；不通过捕获 OOM、增加堆上限或截断工具结果处理异常

## 验证

新增四项 JVM 回归，覆盖大 ADB 输出引用及完整性、Unicode 与转义字符、布尔值、嵌套类型和判别字段。仅交由仓库 Android Tests 执行，本地不运行构建或测试。未获得该设备的堆转储，尚不能量化全部内存占用或确认该设备已不再出现 OOM。

## 完整设备回归清单

1. 无工具生命周期插件时执行普通和大输出命令，工具结果完整，应用可继续使用
2. 启用生命周期插件后执行普通命令，开始、结果、结束事件顺序正确
3. 执行含中文、引号、换行的大输出命令，事件 `resultJson.output` 与原输出一致
4. 同时启用多个订阅，每个订阅均收到一致的结果字段
5. 有排队事件时停用订阅，已无接收方的事件不再构造结果载荷
6. 在悬浮聊天中运行原统计命令，检查响应、结果及进程内存；重复操作不出现同一路径的致命异常

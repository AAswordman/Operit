# Gemini 空内容序列化回归

## JVM 覆盖

GeminiContentsSerializationTest 引入上游全部 13 个用例，覆盖普通与工具协议下的纯思考助手消息、正常文本与角色、保留思考、工具调用及结果配对、工具调用相邻正文、过期签名、有效图文、失效图片、空白和有效系统提示、全空请求及最终请求体约束。每条 Content 必须有 Part，每个 Part 必须有有效 data 成员，文本不能为空。

本地未运行 JVM，用例结果由仓库 Actions 确认。

## Android 与端点检查

- G01：正常文字多轮对话；请求保留正文原文和消息角色，响应正常
- G02：历史助手消息只有思考正文；过滤空模型轮次，后续问题可发送
- G03：启用工具调用并包含纯思考助手消息；无空 Part，工具协议仍有效
- G04：保留思考历史；有效思考与正文按现有选项保留
- G05：发送工具调用和对应结果；调用参数、签名及 functionResponse 配对不变
- G06：发送图片与正文；有效媒体和文本同时保留，顺序不变
- G07：历史图片链接失效且无正文；跳过空 Content，其他历史保留
- G08：系统提示为空白或正常文字；分别省略 systemInstruction 或保留原正文
- G09：历史全部为空、仅有思考或只剩系统提示；本地给出空内容错误，不发送请求、不重试同一内容
- G10：最新用户轮次只有失效图片；记录该轮会被跳过，检查剩余历史仍可能产生回复的边界

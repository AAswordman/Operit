# 工作流失败原因与节点名称

运行报告原先保留问题分类，但没有保存节点的失败原文和执行动作。用户只能看到超时等通用提示，难以定位具体失败的调用。

执行器现在把节点名称、工具动作和真实原因写入节点报告。失败摘要使用节点名称；没有自定义名称的执行节点使用实际工具名。异常原因链一同保存，详细堆栈仍保存在原有诊断日志。

报告展示动作、分类和可选择复制的具体原因，过滤 Java、JavaScript、Python 堆栈，并将已知节点引用改为名称；HTTP 状态码、耗时和服务返回文字保留。旧运行记录可以继续读取，缺少的新字段不推测补写。

## 作用域

- 执行结果与持久化节点报告增加失败原文、动作名称
- 通用错误格式化与报告界面展示
- 九种语言的新增文案与 JVM 回归

## 回归检查

| 编号 | 做什么 | 预期行为 |
| --- | --- | --- |
| W01 | 命名节点执行 HTTP 401、429 或服务拒绝请求 | 显示节点名称、实际动作、状态码及服务原因 |
| W02 | 节点抛出带内层原因的 Java 异常 | 保留各层原因，不展示异常类前缀或堆栈行 |
| W03 | 工具返回 JavaScript 堆栈或 Python traceback | 显示实际错误文字，不展示调用栈和源码行 |
| W04 | 引用失败节点，错误同时包含状态码和耗时 | 引用显示节点名称，状态码和耗时不被误替换 |
| W05 | 无自定义名称的执行节点失败 | 使用真实工具名标识节点，报告仍显示执行动作 |
| W06 | 启动失败且没有失败节点记录 | 显示整体失败的具体原因 |
| W07 | 读取旧版节点报告和只有日志的旧运行记录 | 正常读取，不伪造缺失的节点原因与动作 |
| W08 | 查看成功、跳过、取消和多节点执行记录 | 状态、耗时、成功摘要及历史切换正常 |
| W09 | 切换语言并复制多行具体原因 | 文案占位符正确，原因可以选择复制 |

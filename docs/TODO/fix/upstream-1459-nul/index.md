# 同步 NUL 消息读取修复并适配结构化存储

同步上游按 BLOB 字节读取消息的修复，并适配本仓库 sections/searchText 双字段。正文、搜索文本和候选消息按 64 KiB 有界分块读取，再统一 UTF-8 解码，避免 NUL 截断和跨字节边界乱码；PDF 提取结果写盘前清除 NUL。

## 实现范围

- 在 ChatContentDao.kt 的消息和候选查询中将 sections/searchText 以 BLOB 字节分块读取，保留现有双字段、事务、运行窗口与选中候选查询，不恢复上游旧 content 列；此前按 TEXT 长度截断会丢失 NUL 后内容。
- 同一 DAO 对四条字段分块查询校验实际字节数，拼接完成后统一解码，防止中文或表情被分块切开时产生乱码；单个字段的数据库返回行仍以 64 KiB 为界。
- 在当前 util/document 包的 PDF 直接提取和 OCR 写入路径清除 NUL，历史数据库中的原始文本仍完整读取，不做数据迁移。
- 移植上游 Room + SQLite JDBC、PDF 清理回归，适配结构化实体，并增加双字段独立跨 UTF-8 边界和运行窗口选中候选回归；现有 sqlite-jdbc 测试依赖继续使用。

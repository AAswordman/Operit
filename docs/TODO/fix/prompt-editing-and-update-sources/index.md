# 提示词编辑状态与更新下载来源适配

角色卡、提示词群组和标签的长文本此前主要由 String 承载，字段离开视口或进入全屏编辑后，选区与内部滚动位置容易丢失。更新页面虽能探测多个来源，但实际传输只绑定选中的一个地址，探测成功也不能保证完整文件下载成功。本轮在既有模型服务缓存与 BLE 修复之后，补充维护者指定的三项上游改动。

## 作用域与兼容性

保留角色卡分页、语音设置、主题文字描边、独立发行仓库、增量链解析、补丁及目标 APK 的哈希检查和严格 Content-Range 检查。既有角色卡与更新配置的存储格式不变。年度报告和插件悬浮窗不在本轮范围，不调整版本或正式发行流程。

现有列表、DSL 和页签滚动保存继续沿用。本轮补充每个提示词输入框自己的文字、光标选区及内部视口；保存状态用于编辑过程和 Compose 状态恢复，不表示关闭编辑对话框后将未保存草稿写入角色卡数据库。语音设置继续使用原有 String 回调，和提示词字段共用全屏草稿组件。

## 1. 源码换行规则 [DONE]

同步上游 `959b1afb` 的 [.gitattributes](../../../../.gitattributes)，使 Shell、Bash 和 Dockerfile 使用 LF，并标记常见二进制文件。Android 应用的开发和 CI 会在不同桌面系统上处理脚本，规则避免 CRLF 影响 Linux 解释器。不执行全仓重新归一化，不改聊天文字的换行行为。

## 2. 提示词编辑状态 [DONE]

适配上游 `f1a57f7f` 和 `41d882b4` 尚未覆盖的表单部分，在角色卡、群组、标签的表单层持有每个字段的 TextFieldState 和 ScrollState。切换字段或隐藏输入框时不重新创建这些状态；不同角色和字段按身份隔离。

全屏编辑使用独立草稿和独立视口，避免不同高度的窗口相互改变滚动上限。保存时回写文字与选区，取消不修改来源字段。程序替换开场白时显式更新字段状态，保存及导出读取同一份文字。

状态式 Material3 输入框接入现有 ThemeBasicTextField 与文字描边路径；按项目 Compose BOM 对应的 Material3 1.4.0 源码核对参数。保留紧凑输入框和语音设置现有调用接口。

移植上游 4 项设备回归源码，并补充描边切换后文字、选区和内部视口的回归源码，共 5 项；尚未编译或执行。

## 3. 更新下载来源与文件校验 [DONE]

适配上游 `7fbc7cdd` 的来源模型、排序和传输组件。来源按速度、延迟和稳定键排序，手动选中的来源先尝试，其余已探测可用来源继续保留。全量 APK、补丁元数据及各步补丁附件分别按候选列表下载，失败记录具体来源与原因。用户取消继续向上传播，不作为来源失败后继续尝试。

全量 APK 和补丁二进制的探测要求 206 与合法 Content-Range；元数据使用顺序下载，允许正常的 200 JSON 响应。HTML 错误页不参与下载。传输复用本地严格的区间解析，逐段限制写入长度，拒绝不匹配的总长度、缺失字节和超出区间的字节。

发行解析仍使用 `3316891527/Operit-Kong-patch`，将对应附件的公开 SHA-256 摘要及完整 APK 大小送入下载器。存在摘要时校验 SHA-256；旧附件未提供摘要时，保留对应的大小及原有补丁协议校验，不能把这种情况描述为取得了摘要验证。保留从已安装 APK 真实哈希寻找可达补丁链的逻辑，以及补丁与重建 APK 的原有哈希检查。

浏览器下载仅移交选定 URL；候选来源逐一尝试和文件校验由应用内下载器负责。换源时重置当前传输进度，并保留已收集的失败记录。

新增或移植 36 项来源排序、摘要、探测和传输 JVM 回归源码，在既有独立发行解析回归中再增加 2 项摘要与大小传递用例，共 38 项新增 JVM 回归源码；尚未编译或执行。

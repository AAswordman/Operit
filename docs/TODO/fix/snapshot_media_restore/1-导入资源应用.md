# 导入资源应用

## 原有实现

恢复端仅从 `manifest.resources` 构建资源计划。release 快照通常只包含原始 `files`、`datastore` 和数据库目录，偏好里的 URI 保存了原包名或原 Android 用户的绝对路径，换安装导入后文件虽然恢复，配置仍指向旧位置。

旧的通用 protobuf 重写先把任意 length-delimited 字段当作 UTF-8 字符串，随后进行 URI 子串替换。Preferences 的 map entry 和 Value 也是嵌套字段，因此目标路径变长时，内部长度可能失效。

## 实现

`data/backup/RawSnapshotMediaRestore.kt` 读取归档中的真实 `PreferencesProto.PreferenceMap`，识别全局及角色、群组主题的媒体键。它读取当前引用而不枚举文件名猜测用途，覆盖全局用户头像、自定义用户和 AI 头像、背景图或视频、用户和 AI 气泡图片、主字体及两种气泡字体。

恢复计划同时处理独立资源目录和原始目录中的媒体：

- 带资源映射的快照使用映射给出的恢复位置；同一文件的绝对路径与 `file://` 引用均改写
- 原始目录中的引用按 manifest 原包名识别 `/data/data`、`/data/user/<用户>`、`/data/user_de/<用户>` 以及 Android 外部文件目录，将相对路径映射到当前安装
- 只为归档中存在、且目标位于允许目录内的文件建立引用替换；缺失文件计入跳过结果
- 原始主题开关、角色选择、字体类型、缩放、透明度等参数保留；关闭的资源仍可在重新启用后使用
- 多处共享同一资源时分别改写引用，资源恢复按目标文件去重计数

`RawSnapshotBackupManager` 在覆盖应用目录之前构建全部资源计划并重写解压目录中的偏好。Preferences 只修改字符串和字符串集合的值，protobuf builder 负责维护各级长度及其他字段；XML 使用转义后的单次替换，避免重复转义和映射连锁替换。偏好解析或写入失败会终止导入，避免成功提示与实际引用状态不一致。

正常备份设置入口在恢复成功后显示资源计数并立即重启，下一进程直接加载已恢复配置，防止旧 DataStore 缓存回写。数据救援入口使用同一恢复实现并显示成功、跳过计数，沿用救援页的重启入口。日志开关与恢复计数的五个提示键覆盖九组语言。

## 边界

外部 `content://` 授权 URI 不会自动获得新设备授权。内置 `android_asset` URI 保持原值。旧快照的原始资源路径按 manifest 包名匹配，且不能穿越源归档或当前应用目录；未引用媒体不因导入而自动启用或替换当前引用。

原有导出整理、未引用媒体过滤、日志开关和引用收集失败时保留原始媒体的行为继续保留。

## 验证

新增 10 个 JVM 回归用例，覆盖旧快照的九类引用、不同 Android 路径、编码文件名、缺失资源、路径安全、共享资源别名、真实嵌套 Preferences、主题开关和其他类型保留、替换边界及损坏偏好。原有 JSON 引用重写用例改为真实 PreferenceMap 数据并使用不同长度的目标路径。

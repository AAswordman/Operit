# MCP 手动启动反馈与斜杠菜单

## 背景与改动

MCP 管理页点击启动后原先只更新加载状态，没有明确的操作结果。手动启动现在通过 OKToast 提示正在启动、全部成功、部分失败、全部失败、异常原因或取消；没有启用服务时说明无需启动。所有启用项的现有运行会话均活跃时，提示“已启动，无需重复启动”并跳过启动批次，不依据工具缓存或历史时间戳认定成功。启动结果只汇总一次，后续描述生成不重复覆盖结果。

页面无法取得 Activity 生命周期时也提示启动失败。启动按钮在无启用项时允许点击并返回说明，执行期间仍禁用，防止重复启动。应用自动加载沿用静默模式。

聊天输入框的建议菜单只由 `/` 触发，支持输入查询和选择。输入 `@` 不再打开该菜单；现有已插入引用的解析和删除行为沿用原实现。

## 验证

本轮仅做相称的静态检查，不执行本地编译、构建或测试。Debug 和 Android Tests 交由工作分支 Actions 执行，运行结果与设备验证分别记录。

- M01：手动启动有效 MCP 服务；出现正在启动提示，完成后提示成功及数量
- M02：所有启用服务已有活跃会话时再次点击；提示已启动，无需重复启动，不再次执行启动批次
- M03：同时配置可用和不可用服务；提示部分失败，并显示成功、失败数量
- M04：所有启用服务均连接失败；提示失败及数量，不报成功
- M05：没有已安装服务或所有服务禁用；点击后提示没有需要启动的服务
- M06：启动发生异常或在结果产生前取消；分别提示失败原因或取消，恢复可操作状态
- M07：服务验证已结束，后续描述生成失败或被取消；不再次覆盖已反馈的启动结果
- M08：应用自动加载服务；不因本次改动弹出手动操作 Toast
- C01：聊天输入 `@`、`@名字` 和邮箱；不拉起建议菜单
- C02：聊天输入 `/`、`/查询` 并选择条目；菜单、筛选和插入正常
- C03：输入 URL 或词内斜杠；不因词内 `/` 误开菜单
- C04：普通输入、发送和已有引用删除；原行为正常

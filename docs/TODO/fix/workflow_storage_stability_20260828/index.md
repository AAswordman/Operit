# 工作流存储稳定性

## 原本状况

工作流 JSON 直接写入公开下载目录下的文件。多个 `WorkflowRepository` 实例可能同时读写同一批文件，应用异常退出或并发刷新时，工作流列表会读到半写入内容或被较旧的加载结果覆盖。

工作流文件格式错误、目录异常等存储问题只进入日志或被统一折叠成加载失败，用户在列表和详情页缺少可见提示。

## 意图与结果

工作流文件写入必须以单文件原子提交完成，并由仓库层共享互斥锁串行化工作流 JSON 读写。

列表刷新和详情刷新只允许最新请求更新界面状态；工作流存储警告需要按包管理界面右下角错误提示样式显示。

## 作用域

- `WorkflowRepository` 的工作流 JSON 读写、删除和格式错误提示
- `WorkflowViewModel` 的列表/详情加载请求时序控制
- 工作流列表页和详情页的错误 snackbar
- 中英文工作流存储错误文案

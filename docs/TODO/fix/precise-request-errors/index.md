# 请求错误细分与后台提示保留

现有 5000—5006 依靠异常消息关键词归类，普通 IOException 同时覆盖连接、服务端错误、协议与解析失败。收到 200 后失败时缺少阶段信息，首字等待为五分钟，后台无可见窗口时请求错误提示会被丢弃。

本次将通用请求错误移入独立的 `api/chat/error/`，按明确异常类型、系统错误与请求阶段细分编号；应用主动发现的问题在发生位置构造带类型的异常。无法识别的错误保留原始信息，不强行归为网络故障。原有 JSON 字段继续保留，新增域、阶段和请求信息，旧日志不重新解释。

## 实施顺序

1. 建立唯一编号目录、带类型异常与请求阶段记录，删除旧的通用消息匹配分类器
2. 接入 OpenAI、Responses、Claude、Gemini 的请求边界与解析失败位置，保留服务端错误字段，区分缺少响应体、缺少结束标记和 JSON 解析失败
3. 将首字等待上限改为十分钟，并验证原取消、换钥与预算行为仍有相应用例覆盖
4. 后台及宿主切换保留请求错误，回到可见窗口后展示；普通操作提示保持原有短时队列语义
5. 补充编号说明、完整回归清单和独立结果表，提交工作分支并派发 Android Build、Android Tests 后创建目标为 dev 的 PR

## 验证记录

本地只做源码、差异、编号唯一性、资源和链接检查，不执行编译或单元测试。行为回归由仓库工作流执行；派发与通过分别记录，不持续轮询。

## 范围边界

本次包含错误模块自身的路径整理。全项目包路径重构、计费系统对账与网络故障责任归因不包含在此变更中。旧的宽泛编号不重新分配给新含义，原有明确编号保持原含义。

# 实现与依据
## 数据读取

`ChatHistoryDelegate` 原来为了划分展示页，先读取并还原最多 80 条完整消息，再截取一至两页。改为 `MessageDao` 只查询发送者与时间戳，沿用五条用户或总结消息触发分页的规则；确定首屏或更早页的范围后，才由 `loadChatMessagesWindow` 还原范围内正文及候选，避免页外长工具结果的 JSON 解码。向更新消息翻页仍使用原有入口。


`MessageSectionStorage.decodeStored` 对当前 JSON 数组先构建完整 `JsonElement` 树，再转换成 sections 对象。改为直接反序列化规范数组；已有开发版 envelope 和旧文本继续使用原有读取路径。目标是减少长工具结果加载时的中间对象。

`MessageSectionBackfill` 在启动时回填旧记录，原来每批 32 条的解析、JSON 编码和索引生成都发生在写事务内，而且每批重新扫描 `sections = ''`。改为在事务外准备数据，按主键向后读取；更新时要求目标行仍未回填，避免覆盖并发编辑，每批检查取消并让出协程执行机会。

## 分块渲染

`rememberChatTimelineEntries` 原来把恢复出的消息正文重新交给普通 Markdown 解析器。改为把静态消息的显示 sections 交给结构化解析入口，工具、思考和状态直接生成对应节点，正文仍使用 Markdown 解析，协议片段保持隐藏。

Cursor 与 Bubble 的静态消息原来在分块复用判断前调用 `displaySections()`，导致已持有节点的每个块仍先拼接或解析整条消息。改为在分块上下文直接复用节点；独立消息按正文及 sections 缓存显示片段，sections 渲染入口按片段缓存正文字符串。内容编辑或候选切换时重新准备，不缓存流式增量。

## 资源导航

`OfflineResources.withAvailable` 原来在缺失资源时直接启动 Activity，后台语音初始化也会触发导航。移除该自动导航，仅返回原有资源缺失错误；设置中的资源管理入口继续可用。后台调用不得自行打开资源页。

## 验证边界

补充分页元数据的三项边界用例和 JSON 数组的两项读取用例，覆盖五轮分页、总结分界、空历史、长转义文本和未知字段；沿用已有结构化节点及协议隐藏用例。只进行源码及 diff 核查，本地不运行构建和测试；提交后派发个人仓库的 Android Build 与 Android Tests。工作流结果和设备性能分别记录，不能以静态检查代替帧率、启动及分页耗时结论。

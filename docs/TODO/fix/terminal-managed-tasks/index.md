# 终端命令生命周期与托管任务

## 背景与目标

当前终端调用将请求等待、命令执行和会话清理绑在一起。快速完成事件存在订阅竞态；超时调用可能中断其他排队任务；读取通道故障、显式关闭和初始化取消缺少统一收尾。本轮参考 CATMIAOZHI 的终端执行层修复，在个人应用当前引用的终端核心上适配。

应用分支 `feat/terminal-managed-tasks` 从个人 `dev` 的 `559633f959da872e82e22eaa6235c9cf4604c700` 创建；核心分支 `fix/terminal-command-lifecycle` 从应用固定引用 `aad54161c1b5e10ae9c5e393735119e01dd8e40a` 创建。两份源码使用隔离工作树，不操作主工作区已有修改。

## 实施顺序

1. 修复订阅握手、初始化脚本原子写入和 JNI waitpid 错误处理
2. 增加按命令 ID 取消、关闭所有权与所有等待方完成事件；保留既有命令完成标记和真实退出码
3. 补齐进程身份识别、独立退出监控、读取故障退役和初始化取消清理
4. 新建托管任务包，实现 start、poll、cancel，分别处理单次等待和命令执行期限
5. 接入原生工具、JavaScript 桥、TypeScript 类型和 super_admin 工具包，维护兼容接口、来源记录及完整回归表
6. 本地静态检查后提交到个人仓库，在工作分支派发 Debug 与仓库检查，再创建关联 PR；不等待或轮询 CI

## 兼容边界

现有 `Tools.System.terminal.exec`、流式执行和旧结果格式继续可用；新增托管任务入口以 `runId` 标识命令，查询不会排入探测命令或取消正在运行的任务。super_admin 继续提供既有调用方式，并提供明确的托管启动、查询和取消入口，避免已发布脚本收到未预期的返回形态。

托管任务由应用进程内的独立作用域持有，应用进程退出后不承诺恢复任务 ID；记录淘汰和 ID 失效必须显式报错，不自动重跑命令。正常完成、非零退出、取消、执行超时和会话丢失分别记录，未知命令退出码不得解释为成功。

保留个人版本的规范模式交互判断、UTF-8 连续解码、输入排序、进程组清理、环境维护和宿主初始化。JNI 只调整已有 waitpid 调用的状态初始化、EINTR 重试及返回值检查，不更换原生终端实现或工具链。

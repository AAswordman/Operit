# 取消后确认原 shell 恢复

## 问题与改动目的

本地命令和打印唯一完成标记的 `printf` 分两行注入 PTY。Ctrl+C 可以清掉尚未消费的标记行，shell 已回到提示符时，命令记录仍可能保持运行。原取消路径只等待旧标记，期限到后会关闭整个会话，丢失目录和 shell 变量。

## 恢复确认

1. 按当前 commandId 创建一次取消请求，暂停队列推进，生成独立随机令牌。
2. 会话输入消费者核对命令 ID 和取消请求实例，再发送 Ctrl+C；PTY 写入继续在生命周期锁外执行。
3. 中断发送后收到本地 OSC 目录提示符，才向同一输入队列加入 `builtin printf` 确认行。提示符本身不完成命令，确认行不切换目录、不启动子 shell，也不写入环境变量。
4. `printf` 生成 OSC `777;operit-cancel;<token>` 回复。输入行只包含转义文本，PTY 回显不能构成回复。解析器支持控制序列跨块并保留正文、提示符与回复的先后顺序。
5. 只有当前取消请求、当前命令和随机令牌全部匹配，才发出一次取消完成事件。旧回复、重复回复及会话关闭后的回复均不能结束下一条命令。
6. 原完成标记先到时继续保留真实退出码；仅由恢复回复确认结束时，命令退出码保持未知，终止原因是 `cancelled`。取消协程清除当前取消状态后才推进后续队列。
7. 限时内既没有完成标记，也无法确认 shell 已重新处理输入时，仍使用原会话退役和进程清理路径；退役前复查完成状态。

该确认只用于本地可见会话的取消阶段。普通执行、托管 poll、人工输入及 SSH 的完成协议不变。

## 状态报告

可见终端结果新增可选 `contextPreserved`，在取消清理返回后观察原 sessionId 是否仍存在且未关闭。`super_admin` 的 `context_preserved` 使用该观测值，包含长输出保存及结构化失败结果；不再将 `timedOut` 取反来推断会话是否丢失。旧版本缺少观测值时保持未知。

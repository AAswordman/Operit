# 对话历史长列表滚动重叠

## 现象与证据边界

维护者提供的四张滚动关键帧中，对话卡片遮住其他行，卡片边缘露出半截标题和图标，角色分组标题与对话视觉位置错乱。附件仅通过消息图片查看，未读取附件文件路径，未获得原始视频或相同设备的可复现场景。

源码中 FolderTreeList 已使用包含 scope、行类型及稳定 ID 的 key，不应将截图直接解释为数据库中的文件夹关系变化。可见风险是所有混合高度行均挂 animateItem，同时启用位置与退场动画：行的绘制位置可以暂时偏离 LazyColumn 的实际测量位置。当前没有动态证据证明它是用户现场的唯一根因。

## 修改

移除 FolderTreeList 行上的 animateItem 及未使用的 tween 导入，使角色标题、文件夹和对话直接使用当前列表布局坐标。重新排序、展开和删除后立即呈现列表最终位置；拖动浮层、边缘滚动、侧滑编辑/删除、玻璃背景、稳定 key 与数据库排序逻辑保持原实现。删除标题自身的溶解效果仍由 DissolvingChatTitle 执行。

仅修正历史列表自身的动画路径，不修改全局玻璃渲染或停用用户的主题效果。若后续相同场景仍有重叠，应继续核对实际绘制层，不能据静态差异认定现场已完全修复。

## 内置扩展更新说明

+17 的安装保留逻辑将已安装与清单最新内容分开：旧版保留可用，当前 APK 固定清单内容不同时离线资源页显示“有更新可用”和更新入口；内容相同不重复下载。用户点击后按当前清单固定地址下载并校验安装，更新失败不会先移除旧版。

PackResources.catalog 从 APK assets/offline-packs.json 读取并缓存，不联网查询资源仓库最新 Release。维护者仅发布新的资源版本，不更新 APK 自带清单，现有应用不会自动发现，也不接受任意新版本 ZIP。离线资源页刷新安装状态不等于联网检查扩展新版本。

本轮不增加远程更新协议或按钮。若以后需要独立于 APK 更新扩展，应另行设计稳定的远端清单入口、版本兼容约束、可信身份与摘要验证，再复用现有安装流程；单独增加“检查更新”按钮无法实现这项能力。

# 应用升级保留外置扩展安装

## 已定位原因

+15 的固定资源目录为 resources-v2-27aa8eec7b5c78a17629，+16 为 resources-v2-f67fc0082a8e638c6cc2。40 组扩展的资源版本值全部变化，其中 33 组文件清单逐项相同、7 组文件内容变化。资源版本身份包括 SDK 源码指纹，而运行时只根据最新版本目录判断已安装，因此元数据变化也会让已有下载不再被发现，随后插件扫描与启用状态清理继续使用这份缺失视图。

这证明了一条升级后批量不可用的路径，不等于现场文件被实际删除。MCP 配置独立存储，本轮未找到按应用版本删除 MCP 的路径，不把该反馈记为已复现或已修复。

## 实现

- 在现有 packs 包增加 ResourcePackInstallations，分离已安装清单与 APK 最新清单。根据资源 ID、扩展种类、入口及包名匹配身份，核对安装标记、完整文件集合、大小和 SHA-256 后才接受安装；当前已完整安装的版本优先。
- APK 附带 +15 与 +16 的 80 条固定扩展安装清单，用于首次识别已经留在旧目录中的安装；仅增加 JSON 元数据，没有把插件文件重新放进 APK。当前固定资源清单和远端归档保持不变。
- 校验成功的安装在应用私有资源组内原子登记版本清单，使后续升级仍识别已安装版本。匹配包身份、版本路径和逐文件校验继续执行，普通外部目录不能自行变成内置扩展。
- 文件内容相同的版本不重复下载；实际内容变化时继续保留已安装插件，离线资源页显示已安装、有可用更新，提供显式更新操作。安装目的地始终使用待安装版本，不能把新文件写入旧版本目录。
- 导出、导入和资源读取使用实际安装的受支持清单。用户明确删除时删除整个对应资源组与登记记录，避免删除后旧版本重新出现；运行占用继续阻止删除。升级识别不删除或移动旧载荷。
- 启用列表清理保留 APK 已声明的内置包配置，暂时未就绪不等于用户主动停用；真实不存在的普通外部包仍按既有规则处理。

## 验证与边界

新增 16 项 JVM 回归源码，覆盖元数据升级、内容更新、跨多次升级的安装登记、当前版本优先、损坏与缺失、未知版本、身份变化、备份、删除、占用和路径校验。测试尚未执行，本地不编译或构建。静态核对、远端 Debug/JVM 受理和动态结果分别记录。

# 离线语音试听回调崩溃

设备日志记录了离线 TTS 在音频回调处查找 `invoke([F)Ljava/lang/Integer;` 失败，随后 JNI 带未处理异常进入后续调用，引发 SIGABRT。普通 Kotlin 异常捕获无法阻止该原生终止。

在 Sherpa Kotlin 绑定中为两个回调生成入口统一包装显式回调类，声明 FloatArray 到 Int 的 invoke 方法，并保留 JNI 可见方法。原有语音样本、返回值和停止合成判断不变，不修改模型、原生库或下载协议。

修改保留现有 Kotlin 调用接口，只改变交给 JNI 的运行时对象。修复随 APK 交付，已下载模型和现有离线资源可以继续使用。

验证记录：静态差异检查；本地未运行构建或测试。工作分支派发 Android 构建，结果待工作流完成。设备试听、停止、连续试听仍待新 APK 验证，不能据源码检查记为通过。

## 配套设置修正

离线语音合成的 Speaker ID 改用可搜索的选择面板。打开面板时，在 IO 线程创建独立的模型查询实例，通过现有 getAvailableVoices 和原生 numSpeakers 读取有效编号，查询结束后释放实例。单说话人模型只提供编号 0，多说话人模型按引擎枚举；没有可靠名称映射时显示模型名和编号，不猜测音色名称。加载失败显示错误并允许刷新，不提供任意编号输入。

现有 speakerId 字符串配置和工具接口保持兼容；空值继续表示默认编号 0，无效旧编号可以通过面板重新选择。切换模型时清空上一模型的枚举列表。旧 VITS/Piper 自定义包入口保持原协议，本次只改 Sherpa 离线模型。

语音设置已有完整的内嵌试听区，因此删除重复的独立演示页面、包装器、Screen 对象、隐藏路由注册和专用导航回调，并移除各语言中仅由该页面使用的字符串。共用 TTS 服务、语音档案和内嵌试听继续使用。旧的 hidden.text_to_speech 页面标识不再注册。

新增 JVM 回归源码检查 JNI 需要的精确回调签名、原样转交采样数组和 1/0 继续/停止值。本地不运行测试，执行结果以仓库工作流为准。

## 完整设备回归

1. 选择单说话人模型，打开列表应仅有 0；多说话人模型应列出引擎实际支持的全部编号。
2. 选择音色后离开并返回，配置应保留；切换模型后应显示新模型的列表。
3. 没有模型时应引导先选模型；模型不可用时应显示错误且不列出旧结果。
4. 短文试听应正常发声且不闪退；连续试听、停止和长文停止应保留原有行为。
5. 设置页只保留一个内嵌试听区；独立文本转语音演示页面及隐藏路由不再存在；语音设置和唤醒设置仍可正常打开。
6. 旧 VITS/Piper 包配置和在线、系统 TTS 的配置及试听应保持原有行为。

结果：以上设备用例均待新 APK 验证；未记录为通过。

## 按实际实现显示语速与音调

语音设置分别判断两种调节项，不再对所有引擎同时显示两个滑块。系统 TTS 调用 Android setSpeechRate/setPitch，Sherpa 使用合成 speed 与播放 pitch，豆包发送 speed_ratio/pitch_ratio，均保留两项。MiMo 把两个值写入提示词，保留滑块并提示实际效果由模型决定。

OpenAI HTTP、Realtime、硅基流动和 MiniMax 已接入语速，未接入音调，故仅显示语速；旧 VITS/Piper 使用 length_scale 调整语速，pitch 只被记录而未参与推理，故也只显示语速。自定义 HTTP 按实际使用的模板分别显示：POST 检查正文，其余方式检查 URL，另检查编辑中的请求头是否引用 {rate}/{pitch}，匹配忽略大小写。远程接口和系统引擎实际执行效果仍由服务/引擎决定，不能仅因请求发送参数就记为已实测。

隐藏滑块不重写已保存的参数，不改变现有请求或合成协议。清理规则编辑器独立保留，无滑块时不留下空滑块行或分隔线。

维护者本轮反馈：已成功使用本地模型，语速和音调调节有实际效果。仅据此记录离线模型的这项实测，不推断其他引擎或全部回归用例通过。

追加设备检查：逐个切换十种引擎，对照上述规则确认滑块数量；HTTP 分别使用 GET/POST、加入和移除大小写占位符及请求头占位符，确认仅显示参与请求的项；隐藏再显示参数应保留原值；MiMo 显示提示；所有引擎清理规则可编辑。结果待验证。

## 设置卡顿与分句停顿

中文默认试听文案改为“你好，这是一段语音试听。试着调整一下语速和音调，听听现在的声音。”，不含英文名称。此改动不增加中文模型的英文词典或跨语言合成能力。

Sherpa 的模型初始化、校验和合成已经在 Dispatchers.IO 中。卡顿风险来自设置侧生命周期：TTS 草稿每次改变都会淘汰旧试听状态，原先在 Compose DisposableEffect 中同步 shutdown，可能在主线程等原生推理锁和释放；自动保存、档案切换、新建与删除也在主线程同步重置 TTS/STT 单例。试听状态现在先取消命令并解除界面引用，由独立 IO 清理协程等待命令结束并释放服务；协程不依赖页面存活，避免离页取消导致模型引用泄漏。工作区的单例重置显式在 IO 线程执行，并等待完成后继续档案操作。

STT 测试区的原生识别初始化已有 IO 调度，但清理阶段原先在主线程调用 shutdown，本地实现中的 runBlocking 仍阻塞调用线程。现在取消、释放以及录音启停放到 IO，保留只取消本测试发起录音的共享引擎规则。该判断来自源码，维护者尚未实测 STT，不记为已复现或已通过设备验证。

句号没有固定三秒延迟。原来按句号、问号、感叹号和换行分段，每句完整合成后播放，等待该句音轨排空，再开始合成下一句；逗号和分号不走这条分段路径。改为无缓冲通道连接串行合成与顺序播放，当前句播放期间预合成下一句。最多保留播放中的当前句与正在生成或交接的下一句 PCM，不缓存整篇音频；停止或取消会取消生产协程并沿用原生回调的取消检查。模型自身的静音、标点和音色不裁剪，不承诺固定句间时长或缩短首次模型加载。调试日志记录分句序号、字数、合成耗时与音频长度，不输出文本内容，便于分清计算等待和模型产生的静音。

验证：修改文件 Kotlin 语法与 XML 解析、git diff --check；本地未执行构建或测试，提交后派发工作流。未取得现场帧率或原生线程跟踪，因此只能确认移除了上述同步阻塞路径，不能声称已在设备上消除所有掉帧或已测得停顿缩短量。

追加设备回归：不试听直接连续拖动离线模型语速/音调；试听准备中、播放中、结束后分别拖动；切换档案、标签、离页和退后台；长文本含句号、逗号、分号及换行并反复停止/重播；STT 初始化、录音中切换配置与离页。期望界面不等待原生释放、停止不播放旧分句、录音只取消本测试拥有的会话，静音与顺序保留。全部待验证。

# 历史摘要协议负载过滤

## 问题与目标

普通聊天的显示链路已隐藏模型协议元数据，历史摘要仍直接保存、展示并回填原文。使用 Responses 摘要模型时，`openai:responses_reasoning` 等 meta 块会出现在摘要弹窗中，并随旧摘要进入后续聊天和下一次总结请求。

摘要附带的对话回顾还会先删除 XML 标签，再截取正文。这个顺序会留下失去标签的协议负载，导致后续无法再按 provider 识别。

本次让生成的摘要、历史摘要显示和请求上下文统一使用已有的协议显示投影。覆盖 `openai:responses_reasoning`、`openai:responses_output_item` 与 `gemini:thought_signature`，同时保留已闭合代码示例和普通 meta。

## 实施范围

- `core/chat/context/ConversationService.kt`：先过滤上次摘要再构建系统提示词和钩子参数；在请求发送前过滤最终准备历史；在结果钩子前后过滤模型返回的摘要，继续执行原有思考内容清理
- `core/chat/AIMessageManager.kt`：对话回顾在删除 XML 和截取前过滤协议；读取最后一条历史摘要时过滤协议，过滤后为空的摘要不生成空上下文消息
- `ui/features/conversation/chat/modules/messages/style/cursor/SummaryMessageComposable.kt`：摘要详情展示过滤后的文字，编辑入口也接收同一份文字并同步 sections；气泡和 Cursor 样式共用此入口
- `core/chat/AIMessageManagerSummaryTest.kt`：新增上下文组装回归，覆盖三类 provider、多段长负载、未闭合块、纯协议摘要、代码示例和普通 meta；同时断言存储原文与普通助手协议回放内容保持一致

已保存摘要在读取与展示时过滤，无需迁移数据库。此次不改供应商的助手消息协议回放、数据库格式或聊天备份格式。已经失去 meta 标签的任意字符串无法可靠识别，本次不按字符串形态猜测删除正文。

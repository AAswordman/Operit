# 多工具交错参数完整性

用户反馈多个工具调用就可能出现空参数，没有固定次数门槛。源码存在独立的交错流缺陷：Chat Completions 在工具索引切换时直接关闭前一个 XML 调用，后续到达的参数会落到闭合标签外。Responses 的 arguments.done 也没有接收该事件携带的最终参数，只有最终快照的调用会变成空参数。

当前修复按索引保留累计对象并串行输出 XML，仅在完整 JSON 或明确结束时关闭当前调用；其他调用继续缓冲。Responses 最终快照补齐尚未接收的后缀，若与已发送前缀冲突则报告错误，不静默重写。非流式转换保留损坏原文为 _raw_arguments，不将解析错误变成空对象。

结构日志记录调用索引、工具名、参数长度和当前调用数，不输出参数正文。该修复针对有原始参数却在转换时丢失的情况；不能据此证明模型或中转服务发送空对象的现象也已解决。

新增九项真实 SSE 解析回归，覆盖八工具逐字符交错、参数先于名称、单工具、无参工具、截断参数、Responses 仅最终快照、快照补齐、非流式损坏原文及上游真正空参数。Kotlin 临时副本语法解析与 git diff --check 通过；未执行本地 Android 编译或测试，仓库工作流另记。实现完成 [DONE]。

JVM 回归在每项运行前保存并关闭 AppLogger 的系统与文件日志开关，结束后恢复原值，避免真实供应商解析路径触发 Android 日志桩；保留九项 SSE 和非流式断言。修正已完成，云端重跑结果待确认。

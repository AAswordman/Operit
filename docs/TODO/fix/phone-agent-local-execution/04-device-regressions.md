# 04 抖音首页停滞与 Android 参数解析修复

## 已取得的证据

初版测试包执行“打开抖音并搜索关键词”时，用户看到七个控制器轮次停留在首页。第一次运行的完整动作回执未保留，不能确认每一轮的实际失败原因，也不能直接归因于模型。

另一次运行的异常截图指向参数绑定阶段的 PatternSyntaxException。参数替换和模板目录分别使用了未转义右花括号的正则，JVM 可以接受的表达式在 Android ICU 上初始化失败。设备日志还记录了截图远程服务的 DeadObjectException、主线程约 26 秒未响应警告，及两轮观察累计约 35 秒；这证明读屏存在执行端问题，尚不足以解释全部 ANR 原因。

## 修复边界

- [DONE] 参数占位符显式转义两侧花括号；参数绑定与模板目录复用同一参数名扫描函数。无障碍边界解析也显式转义闭方括号。
- [DONE] 本地序列起步只比较当前唯一目标的包名、标识、文字、类型和状态。无关视频字幕或计数变化不会拒绝搜索按钮；目标本身变化、目标歧义、App 切换仍拒绝执行。
- [DONE] 点击前再次读树定位同一目标，使用新的可用边界。读树和派发仍不是原子操作，不能声称竞态消失。
- [DONE] 本地计划失败或没有经过验证的动作后，下一轮附新截图和动作回执。点击须达到新后条件，输入须读回实际变化才算有效动作；Wait 和重复输入原值不算推进。
- [DONE] 连续三段本地计划没有有效动作时停止并报告任务未完成。Inspect 不清空停滞计数；传统单步操作沿用现有轮次和动作预算，其执行会重置本地计划窗口。
- [DONE] 明确完成状态由控制器 finish 指令和运行结果决定，停止或错误不会因英文消息未含 Error 而被工具摘要标成成功。执行摘要区分控制器轮次和动作尝试数，悬浮层在观察及派发开始时更新状态。
- [DONE] 主屏直接使用现有主屏截图工具，避开主屏 Shower 同步截图调用；后台虚拟屏保留对应显示区图像通道。未增加截图重试或其他兜底路径。
- [DONE] 中英文内部协议要求先识别并操作当前真实可见的搜索入口，观察搜索页后再输入，不猜尚未出现输入框的资源 ID。

## 验证与设备复测

已补写相应用例源码，本地未执行编译、构建或测试。本次静态检查、PR Check 和新 Debug APK 构建的完成结果在 PR 中单独记录；旧测试包构建成功不代表本次修复已验证。

设备验收应重新执行打开抖音、点击右上角搜索入口、进入搜索页、输入关键词和检查结果。确认无正则初始化异常，首页视频内容变化不会阻断固定搜索控件；失败回执会带来新截图和计划调整，连续无进展时明确停止。分别记录冷启动和热启动耗时，检查暂停、取消及后台虚拟屏路径。Android instrumentation 用例及修复后的完整真机流程尚待执行。

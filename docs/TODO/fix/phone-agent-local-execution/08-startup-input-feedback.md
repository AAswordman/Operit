# 启动观察分离、点击派发与反馈动画

## 设备反馈与目标

用户报告抖音启动超过 3 秒，首次节点读取失败后模型重新 Launch；坐标正确的点击偶发无响应；涟漪和手势反馈掉帧。本轮仅处理这三项，不将用户页反复规划归因于模型或设备，也不扩展 App 专用流程。

## 实施计划

- 将启动请求已受理、目标窗口已出现和界面观察可用分别记录。节点读取失败只更新观察状态；已有启动证据时阻止向同一 App 再发 Launch，直到观察到其他 App 或明确离开
- 主屏取消固定 3 秒即视为就绪的假设。在共享启动观察预算内检查前台及按间隔重读暂不可用的页面，预算耗尽后保留启动证据；读取中的 Binder 调用不能被该预算硬中断
- 节点点击和截图点击使用当前会话选定的同一输入通道。Shower 点击采用实际按压间隔和同步派发确认，注入拒绝或异常返回调用方，不自动重复点击
- 手势开始前让悬浮卡片的触摸穿透布局生效，单个工具调用只维护一套点击反馈，避免底层工具和控制器重复创建效果
- 反馈窗口在主屏调用内复用，动画进度在 Canvas 绘制阶段读取，静态文字不随每帧重组；启用硬件加速并移除窗口自带过渡动画

## 边界与验证

独立无障碍提供者源码和接口保持不变。只有 Shower 通道能够在本轮修改注入完成语义；无障碍通道仍需依据返回页面检查效果。系统完成注入也不等于目标控件已响应，不因没有页面变化自动重发。

补充启动状态和观察等待的纯 Kotlin 回归源码；进行源码审阅、差异格式、仓库规范、本地化及文档链接检查。沿用原 PR 提交、推送并立即派发远程 Debug 构建，CI 并行检查，不执行本地编译或测试。动画流畅度、真实冷启动和偶发漏点仍需设备复测。


## 实现与审阅记录

主屏启动不再固定等待 3 秒后假定页面已就绪。启动请求受理后记录独立证据，前台查询与首次节点观察共用约 15 秒预算；仅对缺失或尚未出现的目标窗口间隔重读，最多 7 次。超时、节点上限或解析错误都不会撤销启动证据，也不会触发同包名重新启动。新任务会清空这一任务内状态，观察到其他 App 或执行 Home 后允许返回原 App。

Shower 点击使用同一指针的真实 50～80 毫秒按压间隔，DOWN 与 UP 等待系统派发完成，注入拒绝或反射异常通过 Binder 反馈给调用方。UP 未完成时仅发送 CANCEL 清理触摸流，不重试点击。节点与截图点击通过统一入口按会话能力选择通道，Shower 失败不改走另一个通道；未使用 Shower 的主屏无障碍仍按提供者受理语义报告。

进度卡片的穿透布局更新在后续帧完成后再允许注入。主屏调用持有反馈窗口，事件之间只清理内容并隐藏，调用结束才释放；底层通用 Tap 动画由这一所有权抑制。涟漪和滑动进度移到 Canvas 绘制阶段，静态标签不按动画帧重组，同时启用窗口硬件加速并移除 Toast 过渡。

新增 PhoneStartupObservationTest 的 11 个纯 Kotlin 回归用例，覆盖超过 3 秒的冷启动、预算耗尽、后续恢复、普通观察错误、不可重读的错误、读取时间计入预算、取消及启动证据保留。尚未运行这些用例，也没有本轮真机漏点率或帧率数据。

实现部分 [DONE]，本地仅进行静态检查；远程构建与 JVM 检查结果分别记录。

# 01 节点观察与等待

## 原实现与变更

直接 UI 工具已经通过 UIHierarchyManager 读取独立无障碍提供者的 XML。PhoneAgent 原来每轮只截屏，等待 UI_CONTROLLER 完整输出后执行一个 do 动作。

主屏会话在开始时检查已有无障碍授权，明确选择节点观察能力。第一轮同时发送截图与节点，成功完成本地序列后主要发送新节点；控制器使用 Inspect 请求新截图。普通单步指令后继续发送截图。无障碍读屏失败时给出 UI_STATE_ERROR，不用主屏或另一显示区的数据冒充有效观察。

节点包含完整资源 ID、文字、描述、类型、边界与输入、焦点、可用、勾选状态。密码文字和描述不进入节点提示。内部最多读取 5000 个节点、XML 最多 200 万字符，模型提示最多 120 个节点、约 12000 字符，截断标记明确显示。定位和条件判断仍在完整的受限快照上进行。

## 显示区边界

现有 IAccessibilityProvider 没有显示区参数，所以本轮节点能力只属于主屏。后台 Shower 会话继续使用对应显示区的图像与输入通道，不使用主屏树。后台截图不隐藏主屏悬浮层，因而减少原有每轮 200ms 等待；视觉动作原有 500ms 等待及启动等待仍保留。

## 等待方式

本地序列按目标条件读取节点，未满足时每 100ms 检查一次，满足即继续。预算为每步 100～5000ms，默认 2000ms。它不是 Binder 调用的硬中断时限。暂停时间不消耗条件预算，取消信号继续传播。

暂停和取消控件在读树与等待阶段保持可操作，只在截图和实际输入时短暂隐藏。每次实际输入前重新核对目标，隐藏结束后用不可取消的恢复段还原控件。

无障碍提供者暂未暴露按选择器执行节点 ACTION_CLICK 的 AIDL；本轮按新树解析目标后，仍通过现有 performClick 点击节点中心。输入使用原有 setTextOnNode。读树和派发不是原子事务，极短的竞态窗口仍需后续提供者协议工作解决。

# 05 可见操作反馈与通用控制器命名

用户在 App 启动后等待约一分钟，没有看到后续界面变化，随后主动取消；这一分钟不能记作任务完成耗时。用户要求先补齐可见操作反馈，本轮只检查和修改相关源码，没有继续读取设备日志或执行手机复测。

## 实施

- [DONE] 节点点击、主屏 Shower 点击及传统坐标点击在派发后使用实际屏幕坐标显示涟漪、中心标记和坐标标签。派发未确认时明确显示未确认，不将输入受理等同于界面结果成功；校验阶段拒绝的节点不会画成已点击。
- [DONE] 点击标记保留约 2.5 秒，异步动画不增加动作等待。传统工具已经安排的短动画清理不会提前移除新的标记；下一次输入前移除旧反馈层。
- [DONE] 按反馈视图在屏幕上的实际原点换算坐标，取消固定减去状态栏高度的假设，兼容横屏、全屏及不同系统栏位置。
- [DONE] 读节点与模型规划不再隐藏边框和进度卡片。输入时卡片保持显示并临时允许触摸穿透，截图时才短暂隐藏自动化浮层并可靠恢复；浮层不向无障碍树暴露提示文本。
- [DONE] 观察、等待 UI 控制器和每个本地步骤显示不同状态。Android 12 及以上的三个可穿透自动化窗口按系统合成遮挡透明度限制分配，避免标记本身阻碍后续输入。
- [DONE] 工具开关名称改为 UI 控制器子代理，更新中文、英文元数据及对应脚本副本；工具与包的内部 ID、已保存开关和模型绑定不变。

## 验证

本轮未执行本地编译、构建或测试。静态检查、远程 PR Check 与新 Debug APK 构建分别记录，源码变化不代表速度和准确率问题已解决。

设备验收需确认节点与坐标点击的中心和坐标标签一致，失败派发不显示为界面成功；没有真实派发时不出现点击标记。分别在普通页面、抖音视频页面、横屏和系统栏变化时检查位置。连续本地点击不等待动画结束，截图不包含旧标记，下一次点击不会被反馈浮层阻挡。读树和等待模型时可看到阶段并可暂停或取消，后台虚拟屏操作不在主屏画出错误坐标。真实效果尚待安装新包验证。

# 02 受检查的连续操作与复用

## 协议

现有 runUiSubAgent 工具参数、UI_CONTROLLER 模型绑定和 do()/finish() 指令保持兼容。仅为主屏节点会话附加中英文内部提示，允许 answer 中使用一个 JSON 对象：Sequence、Replay 或 Inspect。

Sequence 包含最新 screen、当前 package 和 1～6 个步骤。Tap 有唯一目标与点击后才满足的 expect；Type 有稳定目标和 text，要求输入框已聚焦、可编辑、启用且非密码，输入后自动读回文字；Wait 只有 expect。选择器为 id、text、desc、class、editable、focused、enabled、checked、selected 的精确组合。不支持坐标批次、脚本、任意 Shell 或跨 App 序列。

完整 JSON、所有步骤及全部参数在第一步前校验和绑定。开始时比对模型观察与新树指纹；随后每步按新树定位。目标缺失、重复、App 改变、输入读回不符或超时都会停止。Tap 的 expect 在点击前已经满足时拒绝执行，避免把旧状态误认为本次点击成功。

剩余动作预算在序列开始前检查，每个步骤均计数；原有 max_steps 同时保留模型轮数上限。失败的动作不会在本地自动重发。反馈区分动作受理与 last_action_may_have_run，异常或超时不能解释成动作一定未发生。发送、付款及删除等最终提交仍在提示中要求单步检查结果。

## 模板

模型可通过 save_as 提议保存成功序列，所有步骤条件通过才写入应用私有 phone_sequences 目录，最多 32 份、每份最多 64KiB。键包含 App 包名、版本码和最后更新时间；App 更新或重新安装后旧模板不出现在目录中，也不能直接复用。

模板保留选择器、输入占位符及检查条件，不保存本次 arguments 对象。保存的 Type.text 必须为完整参数占位符；静态选择器文字仍属于模板内容，动态选择器应使用参数。Replay 每次绑定新参数，并执行与首次序列相同的检查；不会把上次成功直接当作本次成功。

## 模型历史

发送模型时只保留最近两份完整节点快照，较早的快照保留已观察到的文字、描述及状态，省略旧资源 ID 和类型。原始任务、动作结果、完整执行记录均保留；截图仍沿用既有历史清理规则。

# 03 耗时记录与验证

## 记录

PhoneAgent 日志及 runUiSubAgent 返回的执行摘要增加 performance 信息，包括观察轮数、截图数、模型请求数、动作尝试数、本地序列数，以及 observation_ms、model_ms、execution_ms、condition_wait_ms、paused_ms。condition_wait_ms 是 execution_ms 的子集，不能重复相加。初始服务预热及清理不包含在这些循环分段里。

## 源码回归

现有 40 项 JVM 回归，覆盖整段协议校验、参数内容隔离、未知指令、坐标批次、预算、过期快照、歧义、点击前已存在的条件、App 切换、输入读回、密码与焦点、超时后不重发、派发异常、暂停与取消、模板版本隔离及历史文字保留。用例使用纯 Kotlin 状态和假的驱动，不依赖不完整的 Android Context mock。新增内容检查无关视频更新、目标实质变化、坐标刷新、无变化输入、Wait、部分序列成功后的失败及无进展计数。另有 3 项 Android instrumentation 源码，使用设备上的真实 Regex 实现检查普通选择器绑定、参数扫描及节点边界；这些设备用例不能用 JVM 通过结果代替。

本轮未执行本地编译、构建或测试。静态检查与远程 CI 的受理、完成、通过需分别记录。

## 设备验收

同一设备、同一 App 版本、同一模型与网络，分别记录修改前后打开搜索、填写关键词、切换设置、陌生视觉页面和后台虚拟屏任务。每项至少记录多次端到端耗时、模型请求数、截图数、成功率、误点或重发次数，单独记录冷启动和热启动。

主屏检查独立无障碍提供者开启、未开启、运行中断开三种状态；后台检查目标 display 没有混用主屏节点。还需实测暂停、取消和设备旋转。纯 JVM 结果不能代替这些设备验证。

## 预期口径

速度估算使用 T = 模型请求累计时间 + 观察和传输 + 本地动作与等待。若模型每次约 3 秒、原流程 8 次请求、改后 3 次，仅模型部分可少约 15 秒；具体总耗时取决于条件等待、读树和服务启动。未进行设备前后对照，不能把工程估算写成已取得的提速或准确率数据。

# 06 输入进程生命周期与坐标证据

## 设备证据

设备物理屏幕为 1260×2800。09:57 运行的截图显示点击未确认，坐标为 679、215。App 日志对应 Shower tap 的 DeadObjectException，服务端日志明确显示 09:57:32 因 15000ms 无活跃客户端退出；该次预热在 09:57:16 完成，模型回复和点击请求发生在退出之后。此前 1200、126 的请求也因同类异常失败，不能把所有无反应归结为搜索按钮坐标错误。

同次汇总为五次模型请求、约 51.6 秒模型耗时，一段本地计划，且节点计划尝试与有效动作均为零。可以确认进入过节点执行器，但尚不能确认那段计划的具体拒绝原因。图片中的标记表示请求坐标；派发未确认不能当成已经在目标 App 上点击成功。

## 修复

- [DONE] 增加成对的 Binder 输入客户端注册与注销，沿用已有事务编号并在末尾追加。服务端按客户端令牌及死亡通知持有任务生命期；有活跃输入客户端时不按 RPC 间隔退出，任务释放或宿主死亡后恢复原有空闲退出策略。
- [DONE] PhoneAgent 在主屏输入准备后获取令牌，公开运行入口的 finally 覆盖预热失败、完成、取消和异常退出，释放绑定的原服务；不发送心跳按键、不自动重发点击。
- [DONE] 模块 preBuild 从同一工作树编译 Java 服务端并用 D8 生成运行 JAR，移除旧预编译资产，避免只更新客户端却仍打包旧退出策略。正常 Gradle 构建和 CI 都生成同一份服务端输入。
- [DONE] 保留既有 0～999 归一化坐标协议和按物理屏幕宽高换算方式；拒绝越界、额外字段及无效屏幕尺寸。明确向控制器说明坐标单位，记录原始坐标、物理尺寸、换算结果和输入来源，没有添加猜测缩放系数。
- [DONE] 状态卡区分节点读取、截图，以及节点读取成功数量或失败；点击标签区分节点定位和坐标单步。读取成功不代表目标选择正确，输入受理也不代表任务完成。
- [DONE] 主屏 Shower 点击派发未确认时立即返回任务未完成，不继续让模型在同一失效输入通道上空转。

## 验证

补写六项 JVM 坐标回归源码，覆盖截图中的映射值、右上入口、独立横纵比例、旋转、范围、畸形参数和无效尺寸。本轮未执行本地编译、构建或测试。静态检查与新提交的远程 CI、Debug APK 构建分别记录。

新包设备验收应让控制器等待超过 15 秒，确认仍能派发输入；结束、取消和宿主退出后观察客户端释放，空闲时按原规则回收。对照同轮原始坐标、截图、实际标记及动作来源判断定位问题。679、215 的偏离尚不能仅凭截图定性为坐标缩放错误，修复服务存活也不能代替准确率验证。

# 实现与兼容性

## 结构化结果直接生成 JSON

`JsNativeInterfaceDelegates.serializeToolResultData` 对普通结构化结果不再执行 `toJson()` 和 `parseToJsonElement()`，改用 `JsToolResultJson.encodeStructured` 直接生成 JSON 树。结果中的原始字符串直接由 JSON 节点引用，避免先转义成完整字符串、解析出第二份正文，再序列化外层信封。

普通 `ToolResultData` 保留 `__type` 多态字段和既有 JSON 配置。`SandboxScriptExecutionResultData` 继续使用具体类型序列化器，保持原先没有多态字段的形态。布尔、整数、字符串、短二进制 Base64 和大二进制句柄仍走各自原有分支；成功、错误、`dataType` 和最终结果内容不变。

修改位置为 `JsToolResultJson.kt` 和 `JsNativeInterfaceDelegates.kt`。

## 固定回调入口传递参数

初始化阶段通过 `runtime-native-result.js` 注册两个固定入口：工具结果按原有 window 命名空间调用，IPC 按原有全局命名空间调用。`JsEngine` 通过已有 QuickJS `callFunction` 路径传递 JSON 参数，不再为每个结果生成 JavaScript 源码。

`JsNativeResultBridge` 预分配参数缓冲容量。对象、数组和 JSON 字符串保持原有工具回调类型；普通文本和错误信息进行 JSON 转义，数字、布尔、null 形式的普通文字继续保持字符串。IPC 的 JSON 信封始终作为字符串交付，回调 ID 沿用原先的清理规则。

移除 `buildToolResultCallbackScript` 和 `buildStringResultCallbackScript`，避免完整结果插值之后再执行 `trimIndent()`，同时避免将正文交给 JavaScript 源码解析器。流式中间结果与最终结果共用新入口，异步队列、取消清理及错误标记沿用原有逻辑。

修改位置为 `JsNativeResultBridge.kt`、`JsInitRuntimeScriptBuilder.kt` 和 `JsEngine.kt`。

## Issue 1370 的关系

[Issue #1370](https://github.com/AAswordman/Operit/issues/1370) 展示的是 `AnrMonitor.captureFullThreadDump` 通过 `joinToString` 拼接线程栈时扩容失败。它与本轮同属内存压力下的字符串分配失败，但业务调用链不同，不证明是工具结果桥接造成的同一根因。该 Issue 已有独立修复讨论，本轮不修改 ANR 监控器。

## 验证边界

本轮消除两条实际存在的重复分配路径，不截断结果、不改变工作流并发规则，也不改变插件的 XML、公开工具调用或 IPC 接口。原图中工作流堆栈缺少业务调用帧；本轮修复覆盖工具结果回传中的大字符串 `trimIndent()` 路径，但不能仅凭部分堆栈断言所有工作流 OOM 均已消失。

# 上游 PR #1411 完整性审查与迁入

来源：[PR #1411](https://github.com/AAswordman/Operit/pull/1411)，提交 c9f99186e020dab6816efc3affd29de19cdaf7c4；关联 [Issue #709](https://github.com/AAswordman/Operit/issues/709)。抓取时 PR 仍开放、未合并。作者报告的编译和六项 JVM 测试是上游验证，不是本仓库的本轮执行结果；作者也未运行设备 UI 测试。

## 结论

可迁入，但不能把它视作所有输入框与复制场景的完整修复。它补齐 DSL 列表宿主状态和设置页页签保存域，不修改消息复制窗口，也未处理所有文本编辑器的选区、内部滚动和输入法焦点定位。普通重组并不必然丢状态，rememberScrollState 与 rememberLazyListState 自身已使用可保存机制；仅替换为显式 rememberSaveable 不能证明键盘触发的跳顶已修复。

## 实际迁入

- DSL 页面、对话框及嵌入式入口持有列表状态 Store，LazyColumn/LazyRow 按路径、规范化类型和显式 key 取状态；生成器、模板同步，附带上游六项 JVM 回归源码。
- 世界书列表、表单、分组、复制及导入页区分列表身份，TS 与现有 dist 同步。本仓库额外在条目表单、分组编辑/删除及复制视图 key 中加入对象 ID，避免不同对象共用同一视图位置。
- 设置页按三个页签保存内容状态，角色卡和标签列表按稳定 ID 绑定条目。
- 本仓库角色卡已移到 management/settings 并使用 ContentSizedTabbedDialog；共用容器已在各页之外持有 ScrollState，所有页也保留组合。没有覆盖这套新实现，也没有照搬上游旧角色卡对话框的改动。

## 尚未证明或不在此改动范围内

- 系统输入法弹出、选区拖动、获得焦点时的自动定位是否导致原生输入框跳顶，需要设备验证，不能用状态 Store 的六项 JVM 测试替代。
- DSL key 仍包含节点路径；节点因兄弟插入或结构变化而换路径时，显式 key 相同也不保证取回原位置。无显式 key 的不同视图同路径仍会共享状态。
- DSL autoScrollToEnd 的主动滚动逻辑保留，开启此属性的界面仍可能按原有规则滚至末尾。
- 本次对象级 key 使已编辑对象的状态在宿主生命周期内保留；没有实现无限历史或跨安装持久化。
- 世界书是外置资源。源码与 dist 更新后仍需在后续整合生成 ToolPkg、更新固定资源清单并发布新资源，当前安装包尚未获得这项修复。

## 本轮验证

源码和迁移适配审查、git diff --check、生成器 Python AST、世界书 dist JavaScript 的 node --check 通过。未执行 Kotlin 编译、TypeScript 类型检查、六项 JVM 测试或设备验证，未推送、创建 PR、派发工作流。

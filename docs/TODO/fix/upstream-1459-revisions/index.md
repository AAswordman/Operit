# 同步流式重试修订与 Waifu 撤回

模型流中途重试时，原有消费者可能使用不同坐标撤回文本，或在流结束前遗漏最后一次修订，导致界面、保存的历史和外部接口最终结果仍包含失败尝试。现在统一使用生产者记录的原始输出坐标，并在结束、失败与取消时补齐修订；Waifu 同步撤回失效气泡和待发送句子。

## 实现范围

- OpenAI、Claude、Gemini 提供商的修订事件记录原始偏移和丢弃长度，TextStreamRevisionTracker 按区间重建正文，解决事件与文本先后到达及连续重试时错删内容的问题。
- EnhancedAIService 统计整次回复实际输出长度，RevisionEventRelay 对后续工具轮次平移坐标，并在流终止时转发尚未消费的修订事件，避免删除前轮内容或漏掉最终回滚。
- 新增 ui/common/a2ui/CardReferenceStream，在引用展开层重新记录修订范围并恢复解码状态，避免模型原文坐标直接裁剪展开后的卡片；保留现有语音请求包装与恢复接收状态。
- MessageProcessingDelegate 与聊天渲染流按完整事件历史生成终态正文，适配现有协议过滤和持久化逻辑；ConversationService 的总结及翻译消费者也统一使用显式坐标并处理终态修订。
- WaifuStreamUpdates 基于最新快照管理句子、打字等待和撤回；ChatHistoryDelegate 只撤回本轮失效消息，不触发用户删除操作的取消钩子，避免重试撤回把请求自身取消。
- 保留本仓库首句即时预览与限频保存，预览和定稿复用消息身份，定稿后再朗读；撤回时删除对应预览或气泡，后续有效句子重新协调朗读。
- Waifu 原生块快照暂存尚未闭合的代码、表格、图片、公式和 XML，继续保留已注册的可见 XML 插件，并对齐上游内部控制标签排除集合。
- 聊天工具、PhoneAgent、HTTP SSE 完成载荷与 A2A 终态改为从修订历史收集完整结果，避免把已发送的旧增量继续拼进最终输出。
- 提取 HTTP 请求体按字节完整读取的现有逻辑，并同步分段读取回归源码；logging/ChatTrace 提供跨处理阶段的长度、摘要和受限预览诊断。
- 同步上游提供商、修订跟踪、转发、Waifu 与 HTTP 回归源码，并新增卡片展开和首句预览的适配回归，提供完整可填写结果表。

# 终端非零退出码统一判为失败

用户在联调版本中确认正常输出可用，但不存在的命令返回 `127`、子进程语法错误返回 `2` 时，工具仍显示成功。原因是终端执行器只将超时或未完成判为失败，没有检查命令完成后的非零退出码。

## 本轮修改

普通执行与流式执行的最终结果统一使用 `exitCode == 0` 作为成功条件；非零退出码全部返回失败，并使用现有中英文错误文案展示实际退出码。输出内容、会话 ID 和超时字段继续保留。

`super_admin:terminal` 与 `bash` 别名通过原工具桥接接收失败；终端包装层保留失败对象的数据，继续交给现有脚本失败协议，使测试窗口和 AI 收到失败状态，并保留原始终端输出与退出码。同步修改 TypeScript 源码、示例 JavaScript 和内置包脚本。

`sleep` 用户随后反馈已恢复正常，本轮仅调整退出码判定。终端调度、完成事件、超时取消、崩溃页与离线资源不在修改范围。

## 验证

本轮不执行本地 Android 编译、构建或测试。静态语法与差异检查后，在修复分支派发 Android Build 的 `assembleDebug` 和 Android Tests；实际受理状态以交付记录为准，最终结果待确认。

本修复以已有统一联调分支为基线，保留其六个分支的合并内容。设备验收继续使用 [完整回归与结果表](01-regression.md)。

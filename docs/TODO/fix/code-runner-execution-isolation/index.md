# Code Runner 运行隔离与命令收尾

## 背景与目标

内置 Code Runner 通过持久隐藏执行器调用 Ubuntu 语言工具链。原脚本在多次终端调用之间共享固定的临时代码和编译产物，代码写入依赖固定 `EOF` 分隔符，`cd` 会修改隐藏执行器上下文，清理也沿用普通命令的长超时。这些行为可能造成代码被覆盖、写入截断、工作目录遗留或收尾长时间等待。

本次只修正脚本层已经确认的缺陷。此前低概率卡住的具体触发点尚未复现，不能据此认定已经消除所有卡住情况。

## 改动范围

- 源文件：`examples/code_runner.ts`
- 同步脚本：`examples/code_runner.js` 与 `app/src/main/assets/packages/code_runner.js`
- 回归源码：[Code Runner 回归](../../../../ci/test/code_runner.test.cjs)
- 工作流：[PR Check](../../../../.github/workflows/pr-check.yml) 与 [Android Tests](../../../../.github/workflows/android-tests.yml)

公开工具名称和参数继续沿用原定义；ES5 脚本继续在脚本沙箱执行。隐藏执行器标识、Python 持久虚拟环境和 Node 持久依赖工作区保持可用。

## 实现

### 命令与上下文隔离 [DONE]

每次终端调用先在子 Shell 中切换到 `$HOME`，再交给独立 Bash 解析完整命令。外层命令的结束标记会避开正文中的同名独立行，命令自己的标准输入重定向到 `/dev/null`。因此 `cd`、环境变量修改和引号未闭合不会继续影响持久执行器的后续命令，非交互脚本读取标准输入会立即得到 EOF。

Node 脚本继续以持久 Node 工作区为当前目录，其临时代码位于该工作区的独立子目录，`node_modules` 的上级查找和 `NODE_PATH` 仍然可用。其他语言以 `$HOME` 为命令起始目录，需要项目目录的编译步骤在本次子 Shell 内显式切换。

### 独立临时文件与可靠写入 [DONE]

需要临时源码或编译产物的入口使用 `mktemp -d` 创建独立目录，避免并发运行覆盖同名脚本、二进制或 Rust 项目。临时目录输出必须为绝对路径，并符合生成目录的名称格式，拒绝根目录、父目录和多行输出。

代码正文通过固定格式的 `printf '%s'` 和单引号参数写入，正文中的 `EOF`、引号、变量、反引号与 `$()` 不会参与外层 Shell 展开。写入、复制、文件存在检查和编译步骤均检查退出码，失败后不继续运行；用户提供的源文件始终保留。

### 有界收尾与错误信息 [DONE]

普通命令继续采用 120 秒默认超时，Rust 生成的可执行程序保留 30 秒限制。目录创建、源码写入、文件检查等轻量前置步骤采用 10 秒限制，Python 环境创建与依赖安装仍使用普通命令超时。

临时目录在 `finally` 中清理，清理单独限制为 5 秒；清理失败记录错误，不覆盖代码执行原本的成功结果或异常。超时返回值会明确报错，并保留原始终端数据；SDK 抛出的异常数据也由导出层传出。

成功或失败只依据终端退出码与超时状态，输出包含 `failed`、`error:` 等普通文本不会再被误判为失败。

## 仓库验证接入 [DONE]

PR Check 在 ToolPkg 或 CI 路径变化时执行 `node --test ci/test/code_runner.test.cjs`，失败会使快速检查及 Candidate checks 失败。Android Tests 增加同一命令的独立回归任务，支持在工作分支上直接派发，不依赖 Android 编译任务先完成。

回归源码包含 20 项测试。Bash、Python 与 Node 的短场景由仓库工作流真实执行，其他语言入口通过终端替身验证命令分支、独立目录和清理时限，不将这些断言表述为编译器实测。

# 共享流结束原因

## 旧实现

`HotStream.share` 把上游异常作为 `Completion` 的 cause 发送，所有 `collect` 都会重新抛出该异常。

## 新实现

共享流公开只读的 `completionCause`。默认行为仍然向收集器传播异常；聊天消息共享流关闭传播，消息处理订阅和旁观订阅者都只接收已缓存内容并正常结束。聊天发送链路在 provider 流式收集阶段记录终态异常并结束流，不把该异常转换为用户侧报错。

## 验证

- `HotStreamTest` 保留默认异常传播测试
- 新增关闭传播测试，验证部分内容和结束原因同时保留
- 聊天发送链路不再主动抛出共享流结束原因

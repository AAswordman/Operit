# 硅基流动音频格式、请求重试与临时错误显示

硅基流动的 Qwen3-Omni 对话音频接口要求 `audio_url`，现有兼容适配却统一生成 OpenAI 的 `input_audio`。报告中该内容类型被拒，外层 HTTP 为 503，之后已有 STT 完成识别。需要修正直接音频格式，同时阻止同一无效内容重复换钥发送，并避免既有转写路径成功后留下被放弃尝试的临时错误卡片。

实现范围为硅基流动音频内容组装、请求重试策略、语音响应编排、已解析语音输入及相应回归。不改动 STT 的 multipart 上传参数或持久化模型能力开关，不新增处理路径。本地不构建或运行测试，验证交由仓库工作流。

## 实现

- `OpenAIProvider` 提供完整音频内容部分的组装入口；`QwenAIProvider` 在服务商为硅基流动时生成 `audio_url.url`，保留录音 MIME 类型与 Base64 数据。OpenAI、阿里云各自的 `input_audio` 格式继续由既有实现生成
- 请求重试策略将明确的 `unsupported content type` 识别为请求内容错误，即使网关外层返回 503 也不重复换钥发送相同音频；普通 503、限流和传输故障保留原有重试策略
- 语音编排在收到音频回答正文前暂存该尝试的重试通知，采用音频回答时再发布；进入既有转写路径时不把已放弃尝试的通知留在聊天中。文字请求自己的通知和最终异常仍正常报告
- 已持久化转写的语音在历史和手动重试时直接使用文字；未转写录音仍遵循实际模型配置的音频开关。只有附加钩子文字时不视为已识别

# 总结发送路径回归清单

自动化项由现有 Android JVM 测试覆盖，含原有协议过滤、历史总结及回顾标题用例。设备项用于观察本次触发路径和现有总结操作，不预填结果。

## 操作与预期

| 编号 | 做什么 | 预期行为 |
|---|---|---|
| V01 | 从调用线程进入真实总结入口，在首次历史读取记录线程 | 历史预处理在其他线程执行，取消异常继续向调用方传播 |
| V02 | 取消协程后调用总结入口 | 不读取历史，不发起模型请求 |
| V03 | 未闭合外层 XML 中分块追加协议负载 | 普通 XML 原文保留，协议负载持续隐藏 |
| V04 | 分别处理三个已识别协议提供方 | 协议块全部隐藏，前后正文保留 |
| V05 | 在每个位置切分含协议块的输入 | 所有切分位置的显示结果一致 |
| V06 | 逐字符追加协议块 | 每次追加都不公开协议开始标签或负载 |
| V07 | 分块追加 256 KiB 协议负载 | 闭合前后均隐藏负载，只显示正文 |
| V08 | 输入未闭合协议块、已识别开始标签及普通半截文本 | 协议部分隐藏，普通未完成文本保留 |
| V09 | 输入普通 meta、自定义 provider、相似标签及转义文本 | 原文保留，不误删普通内容 |
| V10 | 输入混合大小写、单双引号及属性内的角括号 | 正确识别协议标签并隐藏负载 |
| V11 | 输入重叠开头、相邻协议块和自闭合协议标签 | 不泄漏负载，周围正文保留 |
| V12 | 输入行内代码中的协议示例，后接真实协议块 | 代码示例保留，真实协议块隐藏 |
| V13 | 使用不同长度反引号和波浪号围栏，含末尾闭合围栏 | 完整代码块保留，分块输出一致 |
| V14 | 未闭合行内代码或代码围栏中输入协议块 | 不在流式输出或结束时公开协议负载 |
| V15 | 回滚到协议负载内部的原文保存点后继续 | 按原文重建隐藏状态，后续正文正确 |
| V16 | 回滚到半截协议开始标签后继续 | 正确续接标签，不泄漏协议内容 |
| V17 | 在转义代码标记后输入真实协议块 | 转义标记不把真实协议误判为代码示例 |
| V18 | 连续追加普通文本 | 立即显示，不等待流结束 |
| V19 | 处理 2,048 个嵌套工具 XML，含注释、CDATA、属性角括号和内部代码 | XML 和后续代码示例保留，后续真实协议块隐藏 |
| V20 | 在未闭合 XML 和内部反引号后分块追加协议 | 分块和结束结果均隐藏真实协议 |
| V21 | 清理带三个提供方协议的旧总结，再组装后续请求 | 请求中的总结只保留显示正文，存储原文和 AI 回放不变 |
| V22 | 组装带未闭合协议的旧总结 | 未闭合负载不进入下一次请求 |
| V23 | 组装只有协议负载的旧总结 | 不新增空上下文轮次 |
| V24 | 组装包含协议代码示例及普通 meta 的旧总结 | 代码示例和普通 meta 原文保留 |
| V25 | 使用空自定义回顾标题 | 沿用默认标题 |
| V26 | 使用含空白和冒号的自定义回顾标题 | 标题规范化，并保持本地化分隔符 |
| V27 | 在长对话取消请求，阈值调整为 80%，再次发送并触发总结 | 界面持续响应，显示总结进度，不因历史预处理触发主线程 ANR |
| V28 | 总结预处理或模型请求期间取消，然后重新发送 | 旧总结停止，不把已取消结果插入历史；新发送正常进入对应路径 |
| V29 | 对已有消息手动插入总结 | 总结生成并插入原定位置，输入状态恢复 |
| V30 | 群聊中触发自动总结 | 角色名称和回顾顺序保持正确，界面持续响应 |
| V31 | 达到上下文限制后触发总结并自动续写 | 总结完成后按原逻辑继续，不阻塞界面 |
| V32 | 未达到总结条件时正常发送 | 不额外生成总结，正常处理请求 |
| V33 | 总结期间切换会话 | 不把旧会话总结写入新会话，相关状态按原会话清理 |

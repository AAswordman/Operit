# BLE 写入属性、MTU 分片与会话串行化

旧实现固定使用带响应写入，不支持仅允许无响应写入的特征；完整数据没有会话级写锁，也没有按无响应写入的 MTU 负载限制分片。

来源为[上游 375ce5ff](https://github.com/AAswordman/Operit/commit/375ce5ff40087d33f0cc3cb2158d0c6643a75932)。工具名称、参数和返回结构不变，只移植写入、MTU 跟踪及配套回归；本地读取超时继续报失败。

## 实现 [DONE]

BleSession 以协议初始 MTU 23 开始，成功的 MTU 回调更新该会话数值。写入按特征属性选择无响应或带响应模式，没有写属性时直接报错；两种属性都存在时使用无响应模式。

无响应写入按 MTU-3 分片，每片等待独立写入回调，片间按上游实现间隔 15ms。带响应模式保留原有完整负载提交行为。同一会话的写锁覆盖整段传输，避免并发片段交错或覆盖等待者；不同会话保持独立。

提交失败、回调错误、超时或取消会中止后续片段并释放回调与锁，只有全部片段完成后返回原始负载长度。成功回调表示 Android 本地 GATT 写入完成，无响应模式不表示外设已经处理命令。

## 回归源码

BluetoothSessionManagerTest 包含 12 项 JVM 回归源码：

- 无响应特征写入完整 11 字节命令
- 初始 MTU 下 41 字节分为 20、20、1，每片等待独立回调
- 成功 MTU 回调更新上限，失败回调保留原值
- 空负载、单字节及恰好一片的边界
- 仅带响应特征和同时声明两类属性的模式选择
- 不可写特征与非法 MTU 拒绝提交
- 提交失败、回调错误和超时释放等待者与锁
- 等回调和片间取消后停止提交，并允许后续写入
- 同会话并发写入完整串行，不同会话隔离
- 保留本地读取超时的明确失败与等待者清理

## 验证边界

本地只执行静态检查，没有运行 Kotlin 编译、JVM 测试或连接蓝牙设备。现有 JVM 写入用例主要走旧版 Android 的 GATT 接口，真实设备及 Android 13 以上的新接口行为仍需核对，不能将回归源码数量视为通过结果。

实机待核对：仅支持 write_no_response 的外设；默认与协商 MTU 的长负载；同会话并发、取消、断连；读取超时后再次读取。完整预期行为以[工具协议](../../../doc-src/toolpkg_developer_documentation/04_modules/tool-types.md)为准。

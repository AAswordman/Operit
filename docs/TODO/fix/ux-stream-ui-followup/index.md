# 提示、插件配置入口与 Waifu 首次展示修复

用户在 PR #67 的 Debug 包上反馈大部分常用功能正常，同时发现四项体验和兼容问题。本轮继续在 `refactor/package-layout` 修复，目标为 `dev`。大部分常用功能正常是用户概括反馈，没有逐项设备记录；WASM、桌面小组件及部分复杂路径仍未测试。

## 原状与改动

- `OKToast` 根据文本长度展示 2.8—10 秒，长提示至少 5 秒，请求错误无法点击关闭。改为短提示 2 秒、长提示 3.5 秒，并继续采用 Android 无障碍建议时长。请求错误正文和卡片支持点击关闭，也提供无障碍关闭动作及 `Notice.cancel()`。关闭仅针对该提示对象，排队中的其他错误及请求执行不受影响；拖动长正文仍可滚动。
- 角色卡、群组、标签的保存、复制、导入结果使用自绘底部 Card/Surface。改为在操作结果处调用 `OKToast.success/error`，导入错误保留详细信息，清除原有显示状态和定时器。
- 既有插件调用旧模块注册方法时，空操作吞掉了 Compose DSL 配置声明。旧命名空间、全局与 NativeInterface 入口现在与新模块共用归一化和收集链路，配置显示在插件详情；旧 `surface=toolbox` 导航继续忽略。省略 runtime 仍使用 `compose_dsl`。同一 ID 不应同时通过旧、新方法重复注册。
- Waifu 仅在产生完整稳定句子后添加气泡，首句缺少标点或结构尚未稳定时没有可见正文；每次分句又把历史快照逐字送入原生解析器。增加首句实时预览，同一气泡定稿、复用时间戳，后续预览刷新间隔至少 100ms，定稿完整写入且只朗读一次。后续句子保留打字延迟，读取与解析仍独立进行；快照改为一次原生解析，保留类型和块边界。XML、代码、图片、表格和块公式维持完整块收集规则。

首段预览只展示清理后可渲染的正文，不会显示未完成的内部推理或 XML。模型生成尚无可见正文时不会制造占位内容；本轮没有测量特定模型的实际首字耗时。

## 作用域与兼容

实现位于 `ui/common/oktoast`、角色卡设置页、ToolPkg JS/Native 注册桥、`WaifuMessageProcessor` 与消息处理委托。SDK 只更正旧方法的说明，方法签名和插件载荷不变。固定资源必须按新 SDK 索引输入重新生成并发布，不放宽指纹检查。

旧工具界面与动态虚拟形象继续删除。图片头像、Waifu 分段、工具执行器、后台错误保留与请求证据沿用现有能力。旧清理清单和验证文档仍代表各自固定快照，不改写为本轮业务修复的结果。

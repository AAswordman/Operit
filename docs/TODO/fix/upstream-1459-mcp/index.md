# 同步 stdio 工作目录与启动失败诊断

本地 stdio MCP 服务此前会忽略导入配置中的 cwd，并可能在启动失败后只显示通用验证失败。现在保留并使用配置目录，按运行文件位置决定是否部署，并将桥接进程、握手及远程连接的具体失败原因传到管理页。

## 实现范围

- data/mcp 的导入解析器、配置模型和启用切换保留 cwd，目录变化会重置会话；修复配置导入后从错误目录启动相对入口的问题。
- 新增 McpStdioConfigResolver，统一外部绝对入口、显式目录与应用管理目录的安装和启动规则，已配置的本地服务进入启动列表。
- MCPStarter 仅在需要时检查 pnpm，注册和验证结果携带失败原因并更新服务器状态，修复普通 node/sh 服务被无关依赖阻止及失败原因丢失。
- 桥接 TypeScript 和 Android 内置桥接脚本同步提前结束失败的启动等待，并提供命令、参数、目录及环境变量键名；MCPBridge 日志遮蔽环境变量值和敏感参数。
- 适配现有 MCPConfigScreen 与 McpLoadingState，在服务列表和加载状态展示具体原因；保留当前后台加载和手动启动反馈流程。
- 同步编辑器包的 cwd 配置传递、解析器回归源码与桥接场景脚本，提供完整操作清单。

# 实现与验证

## 原有问题

`EnhancedAIService.sendMessage` 用“是否已经开始收集 provider 流”决定是否上报和抛出错误。已进入流的异常会被吞掉，调用方收到正常关闭的流，聊天状态也可能被收尾改成完成。

普通发送与重新生成还分别在状态监听和异常边界弹出错误，两条路径可能重复提示。普通发送读取异步镜像的状态判断成功，存在最后一个 Error 尚未被监听协程处理的时序窗口。

共享重试入口原先没有区分请求参数错误与暂时故障；单密钥的失败次数包含首次请求，导致第五次失败时少重试一次。密钥池最后一把鉴权失败的密钥也可能再次被选中。

## 实现

- `EnhancedAIService.kt`：移除收集阶段标记，非取消异常设置 Error、结束本轮前台服务计数并抛出；仅执行上下文失效后的 Socket closed 按取消关闭处理。异常回合跳过成功完成链路。
- `MessageProcessingDelegate.kt`：普通发送与重新生成在共享流结束后读取 `completionCause` 和服务终态。终止异常或 Error 进入异常边界；普通发送保存错误终态、保留中断输出并禁止完成通知，重新生成失败不发布完成变体。两处状态监听不再弹窗，普通发送由发送边界提示，重新生成由现有 ViewModel 调用边界提示。
- `ApiRequestRetryPolicy.kt`：新增 STOP、ROTATE_KEY、RETRY 三类请求策略。余额、配额和限流优先于通用 invalid_request 文本；鉴权和模型访问失败按密钥处理；参数、上下文长度与确定的 4xx 请求错误停止重发；408、409、425、429、5xx 和传输故障保留重试。
- `ApiKeyRequestSupport.kt`：在申请下一次重试前执行请求策略，停止参数错误；鉴权与模型失败没有可用候选时立即结束，不再重复请求同一密钥。终止错误保留服务端原因，非网络错误不包装成传输故障。
- `ApiKeyRetryPlanner.kt`：鉴权与模型访问错误立即排除当前密钥，即使它是最后一把。单密钥允许首次请求后最多五次重试；池模式保留候选数量预算及二十次上限。
- `ApiKeyFailureClassifier.kt`：识别被请求层异常包装的内层余额和鉴权信息。

## Android 回归清单

以下保留完整回归清单，各项结果依据用户对统一版本的全部通过确认记录；API 与故障条件项目不记为代理本地执行。

1. 单密钥返回 401：首次失败后停止，只提示一次终止错误，不发送完成通知
2. 密钥池依次返回鉴权失败：逐个排除失败密钥，最后一把不被重选，最终只提示一次终止错误
3. 参数校验返回 400 或 422：不重试、不换钥，显示服务端参数原因
4. 单密钥返回余额或配额不足，分别使用 400、402、403 和通用 invalid_request 类型：保留首次请求加最多五次重试，预算耗尽后提示一次
5. 单密钥持续出现 429、503、连接超时或首 token 超时：完整使用重试预算，重试期间保持处理中，最终提示一次
6. 暂时故障后重试成功：正常完成，仅保留重试过程提示，不出现终止错误弹窗
7. 已输出部分文字后连接失败且重试耗尽：保留已输出文字，退出加载状态，不标记为成功、不发送完成通知
8. 重新生成返回参数错误或无效密钥：停止对应重试，不发布完成变体，只由重新生成调用边界提示一次
9. 重新生成成功：正常生成并切换变体，退出加载状态
10. 请求或重试过程中点击停止：走取消流程，不显示请求终止错误，不发送完成通知
11. 连续两个回合分别失败：每回合均能独立提示一次，上一回合的 Error 不在新回合重放弹窗
12. 普通发送成功并触发已有异步总结：回复、总结和完成通知按原有流程完成

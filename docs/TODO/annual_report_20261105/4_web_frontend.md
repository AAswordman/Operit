# 4. 前端子项目与手绘渲染

## 旧实现情况

仓库已有 `web-chat/`：一个 Vite 子项目，构建后由同步脚本复制到 `app/src/main/assets/web-chat/`，产物不进 Git，由 CI 构建。年度报告沿用这个模式。

## 意图

### 技术栈

- Vite 加 TypeScript，不引入 UI 框架；报告是线性的翻页叙事，按场景拆模块
- 运行时依赖只有 [Rough.js](https://roughjs.com/)，MIT 许可，负责把直线、矩形、圆、多边形和任意路径画成手绘笔触
- TypeScript 严格模式，`verbatimModuleSyntax` 加 `erasableSyntaxOnly`，模块之间带 `.ts` 后缀导入，徽章生成脚本可以在 Node 里直接复用前端模块

### 手绘渲染层

```text
annual-report/src/sketch/
	pen.ts
	drawIn.ts
	boil.ts
	glyphs.ts
	glyphPath.ts
	handwriting.ts
	artText.ts
	doodles.ts
	logo.ts
	defs.ts
```

- `pen.ts`：把 Rough.js 的图形转成普通 path，颜色只能取 CSS 变量里的色板，深浅色由样式表切换
- `drawIn.ts`：按笔画长度换算时长，一笔一笔描出来
- `boil.ts`：同一图形用不同随机种子画几遍，低帧率轮换，形成手绘动画里线条微微颤动的效果
- `glyphs.ts` 与 `glyphPath.ts`：代码定义的手写字形，包括数字、常用符号、年度报告月日天次个万亿和 `Operit`；控制点串成平滑曲线，加确定性的抖动
- `artText.ts`：系统字体逐字微倾斜、上下错落，配合 SVG 墨迹滤镜和马克笔高亮
- `doodles.ts`、`logo.ts`：闪光、星星、箭头、波浪线、纸胶带，以及用画笔重新描过的 Operit 图标
- 纸张是点阵加 `feTurbulence` 生成的颗粒，全部写在 CSS 里

### 场景与交互

每一页的数据都要先完成交互才会出现。揭晓之前上滑会被拦下，页面晃一晃并提示要做什么。

项目篇：

1. 封面：图标、`Operit`、年度报告和年份依次手写出来，上滑翻开
2. 提交：按住墨水瓶，12 个月的柱子随按压逐根画出，松手会回落；写出总数后翻开三张便利贴
3. 版本之路：拖着纸飞机沿路飞，经过的版本插旗、补丁版本冒出小点；版本号在顶部分两行排开，用铅笔引线连到小旗
4. 星空：点三下，每次点亮三分之一的增长曲线，最后写出年初和现在的 star 数
5. 留言簿：翻开封面，新贡献者的名字一个个贴上去，按字母序，不排名
6. 插件市场：划开封箱胶带，纸箱打开，三张数据卡弹出，再翻开人气榜
7. 过渡页：按住指纹解锁；同时等待用户数据，失败时显示原因和重试按钮

个人篇按数据决定出现哪些页，页码按实际顺序编号：

1. 相识：往下撕掉台历的一页，露出安装日期和相伴天数
2. Token：刮开涂层看全年用量，再翻开调用次数、输入占比和花费
3. 模型：三张牌依次翻开，最后画出环形图
4. 日历：用手指在 12 个月的小日历上来回涂，涂到三分之一后自动补齐；点某一天能看到当天数字
5. 时钟：拨动指针转一圈，24 小时的花瓣依次绽开，揭晓高峰时段和称号
6. 第一句话：点开蜡封，信纸从信封里抽出来
7. 便利贴墙：对话、消息、最久的对话、最常聊的角色、重新生成、收藏
8. 工具箱：打开盖子，最常用的工具依次出来
9. 沙漏：翻转沙漏，沙子落下时写出 AI 工作时长
10. 罐子：点每个罐子，纸片落进去，写出新记忆、新角色卡、新工作流
11. 缘分：登录 GitHub 的用户才有，点开第几颗星、贡献者身份和插件市场作品
12. 海报：按下印章生成海报，可以保存、分享或从头再看

今年完全没有对话和 token 记录的用户，个人篇只有相识、一页安静的话和海报，海报换成项目篇的数字。

### 动效

- 翻页：整页绕顶边向后翻走，跟手拖动，松手按角度和速度决定翻过去还是弹回；回到上一页时从上方翻下来
- 揭晓：手写笔画描出、贴纸带过冲弹入、纸屑迸发，配合原生触感反馈
- 遵守 `prefers-reduced-motion`，减弱动画时直接显示终态

### 数据加载

- `project-<year>.json` 在构建时打包，加载时逐字段校验
- 用户数据和个人市场数据通过 `fetch('/report-data/...')` 获取；开发时由 Vite 中间件返回 `fixtures/` 下的模拟数据，App 内由原生拦截返回真实数据
- 用户数据和项目篇并行加载，读到过渡页时通常已经就绪
- 加载或校验失败时进入错误页，显示原因，并用 `console.error` 记录

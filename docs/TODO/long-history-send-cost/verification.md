# 长会话发送性能回归清单

本次优化保留原有历史范围及模型协议规则。检查重点是有效上下文相同，以及数据库读取和请求日志不再承担无用工作。

## 自动检查

Android JVM tests 工作流执行新增的 9 个回归用例，并运行仓库已有的模型协议、工具历史、思考配置和多媒体单测。

- `RuntimeChatMessageSnapshotTest`：空历史；总结、用户、基础回答与选中候选的完整字段；超长选中正文；缺失选中候选的原有错误行为
- `RequestBodyLogFormatterTest`：发送对象保持完整；15,194 条历史只读取有界日志样本；日志不序列化原始请求；深层及大量字段仍有界
- `OpenAIRequestBodyObjectTest`：完整长文本及既有 Chat Completions 请求结构

Android build 工作流执行 `assembleDebug`，验证 Kotlin 与 Room 查询生成及应用打包。

本地不执行构建或单测；工作流结果记录在 PR 的验证方式中。没有报告人的会话数据和模型条件，本次不提供首字耗时的实测结论。

## 使用回归

1. 新会话发送普通文本。预期：输入、回复、流式显示和取消行为正常。
2. 关闭总结，在长会话发送消息。预期：模型仍收到原有完整运行态历史；发送前跳过总结检查专用预读。
3. 开启总结并达到阈值。预期：原有总结生成规则正常，下一轮从最后一条总结开始读取。
4. 有总结的会话发送消息。预期：最后一条总结及后续原文保留，总结之前的记录仍能浏览。
5. 存在多个候选但选择基础回答。预期：使用基础正文，候选总数与原有值相同。
6. 切换到后续候选再发送。预期：使用选中候选完整正文、角色和模型统计字段，其他候选仍能切换。
7. 从历史消息重生成回答。预期：上下文截止位置与原规则相同，不带入后续消息。
8. 使用思考、工具调用和工具结果的历史继续对话。预期：既有清洗、调用配对和协议转换规则相同。
9. 切换角色或使用群组编排。预期：角色隔离和跨角色桥接规则相同。
10. 启用提示词钩子或消息处理插件。预期：按既有阶段执行，并取得原有有效上下文。
11. 使用历史图片、音视频或文件附件。预期：原有媒体保留范围及 Provider 能力适配正常。
12. 分别使用 OpenAI/Responses、DeepSeek、Gemini、Claude、Qwen、豆包、Kimi、NVIDIA、XAI、OpenRouter 和 OpenCode。预期：原有模型参数、思考设置和工具协议正常。
13. 查看长会话发送日志。预期：请求正文日志为有界预览，包含省略标记；发送请求本身完整。
14. 浏览旧消息、编辑消息、导入和导出。预期：历史条数及候选数据保留，界面分页规则相同。

# Activity 重建时保留导航

原先路由栈只存在于 Compose 的 remember 中，Activity 重建会重新打开默认页，
原始通知或分享 Intent 也会再次消费。

将路由栈及待处理外部请求交给 Activity ViewModel，配置重建时保留完整返回栈、
路由实例与原参数。状态只保留在当前进程内，不向系统 Bundle 写入页面正文。

已消费的通知、快捷方式和分享不重放。尚未选择目标的分享仍能继续处理。
用户明确取消离开页面后消费该次跳转；重建中断的请求仍可继续。
保留原有通知打开聊天入口。

验证包含路由身份、返回顺序、复杂参数及待处理请求保留测试。
配置变化、通知和分享交互需在安装后手动验证。
进程被系统终止后的持久化恢复另行设计，不属于本次范围。

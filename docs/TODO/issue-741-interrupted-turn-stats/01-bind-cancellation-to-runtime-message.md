# 绑定中断快照与运行态消息

## 旧实现

取消收尾从 Room 重载聊天记录，并要求目标 AI 消息的 `contentStream` 非空。`contentStream` 标记为瞬态字段，不属于数据库实体，重载后的所有消息都不满足该条件。

## 修正

1. 在 `ChatRuntime` 保存当前流式 AI 消息及 Waifu 分段列表。
2. 取消任务前读取该对象和统计快照，任务停止后将两者一起交给收尾逻辑。
3. 收尾逻辑只从数据库读取匹配的用户消息，不再用数据库对象识别流式 AI 消息。
4. 通过回合编号与取消互斥保证旧取消请求不会清理新回合。
5. 正常完成与取消完成后清理运行态消息引用。

## 验收

- 中断消息写入部分内容、`completedAt`、Token 和耗时。
- 中断前已写入的用户消息获得相同的回合统计。
- Waifu 模式下已持久化的分段消息获得相同统计。
- 流式消息身份不依赖 Room 中不存在的字段。

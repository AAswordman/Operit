# 替换资源后的私有文件清理

背景、头像和字体通过 `FileUtils.copyFileToInternalStorage()` 保存为 `context.filesDir` 根目录下带随机名称的副本。原有配置保存只更新 URI，已经失去引用的旧副本会持续占用空间。主题编辑器能清理未保存的草稿文件，但已保存资源被替换后的释放没有统一入口。

本改动在新配置成功持久化后释放旧副本。清理检查全部角色卡、群组主题、旧全局主题字段和全局用户头像的引用，共用资源在最后一个引用消失后才删除。用户选择的新资源成功保存后立即按已有设置流程生效，无需额外清理操作。

## 实施范围

- [保存与文件生命周期](01-implementation.md)：专用资源包、两份 DataStore 的保存入口、群组默认头像和复制失败清理
- [完整回归清单](02-regression.md)：自动化结果、全部真机操作与预期、独立结果表

涉及背景图片与视频、用户头像、全局用户头像、角色卡和群组头像、全局字体、用户和 AI 气泡字体、气泡背景图片。

只处理本次变更前仍被配置引用的应用托管资源。历史上已失去配置引用的存量文件没有扫描删除；仅关闭背景或自定义字体的启用开关时仍保留其路径，以便重新启用。外部选取文件、应用内置资源、目录以及其他私有业务文件保持原有生命周期。

## 当前证据

专用清理实现和测试文件已通过隔离 JVM 编译，`PrivateResourceCleanupTest` 的 12 个用例全部通过。实际头像保存与文件复制方法使用 Android/DataStore 替身进行前后对照：基线替换后旧头像仍存在、复制中断留下一个半成品；修改后旧头像释放、新头像保留、复制中断没有半成品。

这些结果覆盖文件清理和方法逻辑，Android 界面与完整应用构建由仓库工作流和真机清单分别验证。本轮没有执行本地 Android 应用构建或 Gradle 测试，也没有新增真机通过记录。

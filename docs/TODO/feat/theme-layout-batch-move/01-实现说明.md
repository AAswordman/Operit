# 实现说明

主题设置中新增第五个「布局」页签，原独立的设置首页入口、导航回调、`Screen.LayoutAdjustmentSettings` 和 `LayoutAdjustmentSettingsScreen.kt` 已删除。布局页直接展示两组卡片，不保留装饰性标题、英文眉题或引导段落。

## 布局草稿与存储

`data/preferences/layout/ChatLayoutSettings` 表达五项全局数值；`UserPreferencesManager.chatLayoutSettings` 从现有五个键统一读取，`saveChatLayoutSettings` 在一次 DataStore 编辑中统一保存。原来的单项 Flow、写入接口和全局键继续保留，聊天设置按钮、消息区域和 Markdown 渲染的消费者无需迁移。

`ThemeEditorSession` 独立管理全局布局的当前值与保存基线，布局不加入 `ThemePreferenceValues`，不变成角色字段。只改布局时不会创建角色主题；普通保存和应用全部角色都只保存一次全局布局。撤销及离开、切换角色和语言前的确认同时保护布局草稿；保存过程中继续调整的值保持未保存。当前角色主题重置保留全局布局，布局恢复默认只重置五项数值。

## 布局 UI 与预览

`theme/layout/ThemeLayoutTab.kt` 保留设计稿的「聊天间距」「AI 回复排版」、细滑块、可点击数值和单项恢复默认；输入支持浮点数和负字距，校验有限数值及原范围。整体布局恢复默认有确认，所有操作先修改草稿，再通过主题底部保存。

`ThemeLayoutPreview` 在预览子树注入 `LocalAiMarkdownTextLayoutSettings`，复用主题背景、气泡、头像和输入框渲染，AI 消息使用正式 `MarkdownTextComposable`。按钮右边距和消息左右留白也使用布局草稿；实际聊天保持读取已保存的全局偏好。

## 对话批量移动

`ChatBatchActionBar` 在锁定与删除之间增加第五个「移动」按钮，无选择或已有批量任务时禁用。`ChatBatchMoveDialog` 显示根目录和全部已有文件夹，嵌套位置以完整路径区分；点击目标后执行移动，取消不改变数据。

`FolderChatHistoryPanel` 捕获本次所选 ID，移动中禁用重复提交和多选切换，成功后反馈数量并清除已移动选择；失败时在窗口内保留选择和错误提示。普通、搜索、角色及归档列表共用该入口。

`ChatFolderRepository.moveSelectedChats` 在同一 Room 事务中按文件夹 ID 更新归属。超过 900 个 ID 时分批绑定参数，但完整操作仍受同一事务保护；目标不存在或有选中对话被删除时抛出错误并回滚。SQL 仅更新 `folderId` 与兼容旧工具接口的 `group` 字段，标题、角色绑定、归档、锁定、置顶、排序、时间与消息内容保持原样。

## 重试状态调查

源码中，`EnhancedAIService.sendMessage` 收到可重试错误后发布“正在重试请求”；恢复“接收响应”仅在 `isFirstChunk` 分支执行。中途重试时该标记已经为 false，后续重新收到内容不会恢复接收状态，直到执行工具、处理结果等阶段再发布新状态。`MessageProcessingDelegate.keepRequestUiAlive` 也会发布重试状态。

这与反馈的提示延迟消失一致，属于需要恢复流式接收状态的遗漏。本轮按约定先完成两项功能，未修改重试与请求处理链路。

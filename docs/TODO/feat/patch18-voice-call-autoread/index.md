# 补丁 18：自动朗读入口与语音通话朗读

普通聊天的自动朗读移到语音服务工作区的 TTS 页签，保留已发布的 `enable_auto_read` 存储值。Agent 与 Classic 输入菜单删除整个“行为”分组、参数传递、折叠状态和不再使用的各语言资源。

语音通话开启后始终朗读 AI 回复，普通自动朗读开关不参与通话路径判断，进入和退出通话不写入该开关。手动朗读继续沿用原入口。

## 源码调查

PR #12 调整 Agent、Classic 的空白发送与附件菜单中的通话入口，没有修改合成提供方或通话播放实现。

现有全屏通话通过界面监听消息触发 TTS。waifu 发布的是不带流的静态分句，该分支只更新文字；每次处理新消息又无条件停止播放，较慢的云端请求可能在返回前被后续消息停止。朗读与界面流收集绑定也让消息定稿、预览和展示生命周期影响请求生命周期。

## 实施范围

1. 在 TTS 页签增加全局自动朗读开关，沿用原存储并说明通话独立；清理输入菜单和资源
2. 为聊天运行时绑定独立的朗读条件和回调，由现有消息处理链路发出普通流式分句、尾句和 waifu 定稿分句
3. 全屏界面仅负责文字展示；朗读由独立控制器清理文本、初始化服务、按提交顺序交给提供方，并跟踪所有未完成任务
4. 通话收音等待生成、尚未提交的朗读任务、云端队列与播放全部结束；停止、打断、退出和关闭取消旧任务
5. 保存相称的静态核对、完整回归表和四项累计源码快照

## 最终实现

普通朗读开关位于 TTS 页签顶部，继续读写 ApiPreferences 的 enable_auto_read，切换档案不改变它；九种语言保留用于设置页的标题与说明，移除 agent_menu_behavior、两个旧流式标签与 auto_read_active。Agent、Classic 和 AIChatScreen 的菜单状态、参数传递及无调用的切换方法已经清理。

ChatServiceCore 的 MessageSpeechBinding 将是否朗读和实际提交回调成对绑定到当前聊天运行时。普通聊天继续使用原偏好，通话使用 isWaveActive 条件；全屏底部文字输入模式使用普通偏好与本地静音状态。进入、退出、停止通话和关闭窗口不修改普通偏好。

全屏使用消息处理层现有的流式分句、尾句和 waifu 定稿事件，waifu 预览不提交音频。文字界面跟踪流对象和正文变化，仅更新预览，不再在消息切换或定稿时停止 TTS。重新打开窗口展示历史不会触发朗读。

MessageSpeechPlayback 独立持有 TTS 提供方，不使用主聊天的单例。同一轮固定档案、清理规则、语速和音调快照，下一轮刷新档案；变更时在 IO 释放旧服务。初始化和文本清理期间已经登记待处理任务，云端同步入队后放行后句，播放仍由公共预取队列保持顺序。系统和本地引擎沿用各自提供方的合成实现。

停止取消全部待处理任务，并等待其结束后停止提供方；新的提交先等待停止完成。尚未启动就取消的任务也会释放提交顺序。关闭窗口解绑消息回调，停止并释放自有服务；清理不依赖已销毁界面的 Job，旧窗口不会释放新窗口的独立实例。主聊天或悬浮球释放语音识别管理器也不会再初始化或停止主聊天 TTS 单例。

语音通话的恢复收音和空闲退出同时检查消息处理状态、初始化/提交任务及提供方朗读状态，云端请求尚未返回时不会仅凭文字已经定稿就恢复收音。失败提示只由当前有效轮次触发，用户停止和旧轮次的迟到结果不会误报当前失败。

## 审查结论的边界

接手前逐字节对比上一份三项快照，47 个文件完全一致，刚才那一轮只有查询，没有新代码可归责。实际修正的是既有通话链路的静态分句漏播、消息更新无条件停止 TTS，以及共享实例被其他入口重建/释放的生命周期冲突。PR #12 的四个文件已通过 GitHub 文件差异核对，只有入口与说明，没有提供方执行逻辑变更。源码缺陷不能直接等同于已经复现粉丝环境中的实际故障。

## 完整回归操作与预期

1. 分别打开 Agent、Classic 输入菜单并切换主题：整个“行为”分组和旧自动朗读入口消失，其余菜单继续工作
2. 用九种语言打开 TTS 页签：显示自动朗读开关和通话独立说明，无缺失资源或旧行为文案
3. 分别使用旧版本已开启、已关闭的偏好后升级并重启：TTS 开关保持原值，切换 TTS 档案不改变它
4. 关闭普通自动朗读发送常规聊天，再手动长按朗读：自动回复不发声，手动朗读仍正常
5. 开启普通自动朗读接收流式回复：逐句读出，尾句保留，定稿不重读全文
6. 开启普通自动朗读接收非流式回复：完整消息读一次，无漏句或重复
7. 关闭普通自动朗读开启语音通话，使用普通模式流式回复：AI 回复仍自动朗读
8. 关闭普通自动朗读开启语音通话，使用普通模式非流式回复：AI 回复完整读出
9. 关闭普通自动朗读并开启 waifu 通话：首句打字预览不读，全部定稿分句按顺序各读一次
10. 开启普通自动朗读并开启 waifu 通话：仍只走通话一次提交，不重复播放
11. 开启普通自动朗读并使用普通模式通话：流式、尾句和定稿之间不重复播放
12. 模拟云端首句慢于整条文字回复完成：界面定稿不取消请求，返回后仍可播放
13. 使用多段 waifu 回复且云端响应较慢：新分句、工具消息和预览更新不取消前句
14. 让后句请求乱序返回：保持原文顺序，首句准备后继续预取所有已知后句
15. 让档案读取或服务初始化较慢：初始化和待入队任务完成前不恢复通话收音
16. 让最后一句云端请求延迟：等待该句播放结束后恢复收音，不把网络等待当作结束
17. 云端请求中或播放中点击中心头像打断：取消本轮全部任务，停止完成后再收音，迟到音频不播放
18. 请求中退出通话或关闭窗口：旧请求和音频停止，普通开关保存值保持不变
19. 快速关闭再打开语音通话：旧窗口清理不停止新窗口实例，历史消息仅展示不重读
20. 分别在普通开关原为开启、关闭时进入退出通话：原值保持，下一条普通消息按该值朗读
21. 让云端请求、初始化或播放器失败：当前轮次提示一次，停止不误报失败，下一轮可重新朗读
22. 设置正文清理规则、音色、语速及引擎支持的音调，再在一轮中变更档案：本轮参数固定，下一轮使用新档案
23. 分别选择系统 TTS、已可用的本地引擎和七类云端引擎：通话回复可朗读，主聊天与设置试听的释放不取消通话
24. 从全屏底部输入模式切到通话再退出，并触发唤醒问候与空闲超时：普通模式遵循开关及静音，通话默认朗读，问候可停止，待播放任务不被空闲退出截断

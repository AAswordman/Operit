# 禁用状态与工具执行边界

## 已确认的问题

详情头部以当前可运行的界面列表决定是否展示“打开”。停用插件后该列表清空，按钮消失，启用胶囊随之移动。应使用已安装扩展声明的界面数量决定是否保留按钮，用有效启用状态控制是否可点击。

自绘开关使用默认 `toggleable` 点击指示，点击反馈绘制在大于轨道的矩形触控区域，出现矩形阴影。保留现有动画、语义及触控尺寸，关闭这层点击指示。

详情中的工具卡片和运行弹窗未接入启用状态，运行弹窗直接进入 `JsToolManager.executeScript`，该原生入口也没有拒绝已禁用的包。原界面隐藏执行入口时未暴露此路径，完整详情页使该缺口可以直接触发。

## 本轮范围

- 保留有声明界面的扩展头部“打开”按钮，停用时置灰并禁止点击，启用胶囊保持原有位置
- 通用开关取消默认点击指示，继续使用现有轨道和拇指动画
- 本地扩展图标随有效启用状态显示彩色或灰色，市场详情不使用本地禁用态
- 脚本及插件子包的工具运行按钮接入有效启用状态；运行弹窗的运行按钮同样受控
- 原生同步和流式脚本执行入口在读取执行数据前检查启用状态，在取得执行引擎后再次确认；流式调用在收集时检查实际状态
- 使用 `PackageManager.isPackageEnabled` 的既有父子关联判断，拒绝禁用包时返回 `Package not available (disabled): <package>`，不执行脚本、不记录为插件使用

## 回归与验收

补充 JVM 回归覆盖原生同步拒绝、流式拒绝和创建结果流后禁用再收集；补充 Compose 设备回归源码覆盖保留置灰的打开按钮与禁用工具运行按钮。原有展开／收起和工具执行断言继续保留。

本地进行源码核对及四项提交级静态检查；远程 PR CI 负责 JVM 回归和设备用例源码编译，Debug 构建单独产出。设备验收覆盖关闭后按钮占位、开关按压反馈、图标灰度、脚本与子包运行置灰、重新启用后恢复，以及旧运行入口在包已禁用时拒绝执行。

# 脚本分类与扩展详情页面

## 目标与边界

保留包管理现有四标签总体排版，将用户界面中的“沙盒包”统一命名为“脚本”，市场使用相同名称。脚本标签仅展示独立文件脚本，ToolPkg 插件及其子包由插件入口管理。脚本的既有分类继续有效，ToolPkg 的 `category` 不再决定其在脚本分类中的展示。

插件详情由模态弹窗改为完整详情页面，脚本详情使用相同页面组织方式。保留现有总开关、子包开关、配置界面和执行生命周期的关联，不增加设备空间或可用位置功能，不改变服务器接口、存储格式和插件加载协议。

市场详情调整为默认收起的介绍，保留顶部独立“简介／评论”标签。核对顶部标题、统计及操作区在主题和背景图下的文字对比度；介绍保留 Markdown 渲染。管理相关开关采用滑动过程中拇指伸长、两端恢复圆形的动画。

## 实现与兼容性

`ScriptPackageListing.kt` 仅为管理列表提供过滤投影，四条加载及刷新路径共用此入口。ToolPkg 容器及子包继续存在于执行运行时，不更改其注册和执行行为；独立脚本仍使用现有 `category`。现有 `.js`、`.ts` 和 `.hjson` 独立文件导入能力继续保留。

新增 `Screen.PackageDetail(packageName, title)`，通过既有路由反射机制持久化和重建参数。详情宿主直接调用 `PackageManager.enablePackage`、`disablePackage`；子包继续使用 `setToolPkgSubpackageEnabled`，父插件停用时子包开关禁用。启用操作完成后重读实际状态，并在结果不符合请求时显示错误。详情恢复为当前页面时重新读取启用及子包状态，返回管理页触发列表刷新。

“界面”分区复用原配置入口和参数，继续把容器、模块、标题和 `keepAlive` 传给 `ToolPkgPluginConfig`。运行监控、检查更新、删除及脚本执行保留原有能力。

`ExtensionSwitch` 使用统一进度驱动位置和拇指宽度，滑动中段伸长为胶囊，两端恢复圆形，兼容 RTL、禁用状态和至少 48dp 的交互区域。主开关和子包开关带可读名称。

市场简介与评论分别保存滚动位置。介绍默认折叠，展开时仍使用现有 Markdown 渲染。吸顶标签保持独立简介／评论入口，页面标题使用扩展名称。头部采用明确的表面和前景色，长标题及统计标签允许换行，统计在窄窗口下支持横向滚动。

## 验证与验收

本地进行源码审阅、差异、资源及仓库静态检查，不执行编译、构建和测试命令。新增两项分类过滤回归和一项路由重建回归，交给 PR CI 执行。源码实现 [DONE]，远程检查与设备体验独立记录，不作为已完成验收。

设备验收覆盖四个标签及市场命名、脚本列表不包含 ToolPkg 子包、脚本分类、插件总开关与子包记忆状态、配置界面打开和返回、脚本执行、删除返回列表、明暗主题及背景图、开关中段形状、长介绍折叠展开、评论切换与返回滚动位置。

# 资产准备与来源核对

默认 APK 仅保留固定资源目录，完整内置脚本和 ToolPkg 都按需下载。JVM 工作流不需要生成内置扩展；生成资产时排除 `packages/**` 和 `templates/**`，精简脚本允许包目录不存在。完整源码及显式完整构建入口继续保留。

分发集合取自 `tools/example_packages/packages_whitelist.txt`，当前为 30 个脚本和 10 个插件目录。`prepare_hub.py --packages` 接收该集合的真实构建产物，拒绝缺项或多余扩展；ToolPkg 统一归档时间与顺序，保留代码、子包、资源与清单。逆向插件本体与四个 JAR 同组准备，插件内部仍通过固定外置资源声明定位这些 JAR。

扩展清单记录入口、逻辑包名、源码来源及源码指纹。`verify_hub_catalog.py` 核对完整集合与 Git 索引中的源码快照。构建重生成工作树中的 JS/dist 文件不会改变这份快照；暂存后的真实源码变化仍会改变指纹，届时必须发布新固定版本。准备资源前应先暂存对应源码，确保生成与验证使用同一份索引输入。发布脚本在公开发行前核对本地与远端所有文件大小及 SHA-256，不改写已公开的固定版本。

本轮使用成功构建 [40271233381](https://github.com/3316891527/Operit/actions/runs/40271233381) 的真实资产，其扩展源码与功能分支一致。独立发行共 51 个 ZIP 和两个清单文件；原有引擎与 OCR 内容保持一致并逐文件复核。13 项 Python 资源回归通过 `verifyOfflineHubDistribution` 接入现有 JVM 测试任务，由仓库工作流执行，本地没有执行测试。

其中 4 项指纹回归覆盖脚本重生成、插件 dist 重生成、已暂存 TypeScript 变化和已暂存 JavaScript 变化。已发布目录的 40 个内置扩展指纹与索引快照逐一匹配，资源文件无需改写。

# 明确修复与原件保全

## 旧实现

SQL 执行器允许任意修改，但没有针对数据库问题的保全和修复流程。

## 修改意图

- 根据最近一次健康报告生成确定的修复计划
- 仅处理无法解码的 Preferences 文件重置、SQLite 索引重建和已在隔离副本验证通过的 Room migration 等明确操作
- 修复开始前把配置文件以及 DB、WAL、SHM 和 journal 原件分别写入独立 ZIP
- 修复完成后重新执行完整健康检查
- 无法确定处理的数据损坏保持原文件不变，并向用户展示原因

## 期待结果

每次修复都有可追踪的原件副本和修复后报告，不会因为自动化操作覆盖唯一的数据救援来源。

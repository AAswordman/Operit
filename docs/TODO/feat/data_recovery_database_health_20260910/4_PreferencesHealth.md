# Preferences 配置文件检测与修复

## 旧实现

数据救援界面能够导入导出完整快照，但无法单独判断 Preferences DataStore 配置文件是否已经损坏。PR #1006 将配置恢复绑定到应用启动流程，作用域过大。

## 修改意图

- 只在数据救援界面由用户手动触发配置检查和修复
- 将每个已存在的 Preferences 配置文件复制到隔离目录后验证可读性
- 不替换现有 DataStore owner，不向正常应用启动链路增加检测或修复
- 只把确定无法解码的配置文件列为可修复问题
- 删除无法读取的配置文件前先保存为独立 ZIP，下一次正常访问时由现有 DataStore 创建干净配置
- 路径异常、文件复制失败和无法确认进程状态时不修改原文件

## 期待结果

用户可以从同一个“配置和数据库检测”入口确认配置文件与 Room 数据库状态。配置修复不会在后台或启动期间执行，且任何重置都有可追踪的原件副本。

## 资源导入与结构化失败归并

- ER-01：派发工作分支 Debug 构建和 JVM 工作流：StandardFileSystemTools 的应用 R 引用可解析，单测编译不再被该导入阻断
- ER-02：运行结构化文件失败归并回归：最终 ToolResult.error 已是带来源的一份说明，独立输出为空时 result 不重复承载该说明，消息与模型历史一致
- ER-03：运行多步失败归并回归：前序失败、成功进度和最终失败分别保留来源，前序独立命令输出不被丢弃
- ER-04：运行失败补丁及包激活回归：文件差异和独立上下文保留，结构化错误只有一份；来源由数据字段决定，不受来源名称白名单限制

## 流式完成与连接中止定位

- SF-01：输出较长正文并正常结束：保留全文和完成状态，不因 Token 数量产生 5003
- SF-02：运行已完成回答后尾部 Socket 中止回归：保留回答，不进入错误重试或撤回
- SF-03：运行 Chat Completions 的 finish_reason 后追加 usage 回归：实际用量保留，读完用量后结束，不继续等连接关闭
- SF-04：运行 Responses completed 事件后无 DONE 且连接未关闭的回归：处理最终事件与用量后立即完成
- SF-05：运行 Responses incomplete / max_output_tokens 回归：保留已接收文本、用量和原输出上限标识，不等待后续 DONE
- SF-06：在没有有效完成事件时中断正文、发送空 finish_reason 或正常 EOF：保留原中断或未完成错误，不把部分内容当完整成功
- SF-07：完成前触发系统连接中止并查看完整错误：5003 和原异常仍保留，可见本次请求的读取字节、解析进度和取消状态
- SF-08：在补读尾部时主动取消，或等待首输出超时：保持取消语义，首输出十分钟超时仍为独立 5004
- SF-09：完成原因后触发服务端错误、JSON 错误或用量回调异常：继续报告真实错误，不被尾部传输结束处理吞掉
- SF-10：运行响应进度拦截器回归：UTF-8 正文、类型和长度保持一致，已读字节只统计一次，异常原样传播且源能关闭
- SF-11：运行失败上下文回归并比较两个并发请求：进度快照相互独立，未接入流式计数的协议不伪造零输出，客户端取消可观察
- SF-12：在停止执行后对照外层汇总与内部板块：记录具体差异和截图；并行总耗时按区间并集核对，不以内部耗时相加判定错误

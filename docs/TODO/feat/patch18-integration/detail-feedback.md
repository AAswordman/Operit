# 补丁 18 第二轮体验反馈

用户反馈其他功能基本正常，本轮聚焦删除警告不可见、亚秒耗时无法判断、普通工具错误重复和图片识别失败被标为成功。未提供逐项验收结果，不把其他 150 项批量标记通过。

## 删除警告

资源详情原有 OKToast.warning(...).show()，但父级 clickable 包着禁用 TextButton，禁用按钮自己的手势节点仍会消费点击。本轮将说明点击改为位于禁用按钮上方的独立无涟漪覆盖层，按钮保持灰色禁用，忙碌时移除说明点击。覆盖层提供自己的无障碍操作，避免同一删除入口重复暴露。

资源详情注册当前窗口根视图；OKToast.registerWindow 在切换到新面板前处理已有提示，再使用面板根视图的窗口 token 显示 PopupWindow。面板窗口层级的实际显示效果仍待设备复测。

## 工具计时

统一执行器的串行与并行分支都在 executeTool 前调用 timing.start，返回后固定 durationMs；文件、包及代理调用均进入该入口。缺计时记录时界面不补 0，因此不能用旧版 0 秒判断记录缺失。旧版展示 millis / 1000，0～999 毫秒都变为 0 秒。并行分组取实际执行区间并集，调用数不能直接相加成时长。

本轮不足 1000 毫秒显示毫秒，达到一秒后保留整数秒；亚秒阶段约每 100 毫秒刷新，之后每秒刷新，完成时直接显示固定记录。仍使用单调时钟的毫秒记录，没有把模型生成或权限等待加入耗时。截图无法还原此前 100 次调用的精确毫秒值，没有运行额外设备基准测试。

新增亚秒执行与并行并集的两项回归源码，使用确定的时钟值验证 175 毫秒和 125 毫秒不会在记录与分组中被取整成零。

## 普通工具错误

统一聚合器在转成文字前使用 toolFailurePayload 读取结构化失败，文件操作的 env 和 details 形成唯一错误说明，独立输出另存。ConversationMarkupManager 仅在生成最终 XML 时组装这些字段。不同步骤的来源和附加命令输出继续保留；不解析来源前缀，也不在界面中过滤错误行。详见 [失败结果归并](error-result-contract.md)。

新增三项带来源错误的回归源码，原有终端额外输出与结构化错误回归保留。

## 图片读取状态

ConversationService.analyzeImageWithIntent 检查图片理解是否启用图片输入，图片加载及模型请求异常传播到工具层，缓存按 finally 清理，不再把错误转换为成功正文。指定 intent 的请求失败后直接返回失败，不切换到 OCR。

StandardFileSystemTools 的图片分支对直接图片注册失败、位图解码失败、OCR 资源缺失及识别异常返回 success=false，错误放在 error 字段，不再构造成功 FileContentData。OCRUtils 增加工具调用使用的严格错误选项，原 UI 调用保留既有默认行为；识别成功但没有文字仍然是正常结果。

read_file_full 直接返回图片处理结果，read_file 和 read_file_part 沿用其失败传播分支，失败不会再被拼成带行号的成功文件正文。

# 补丁 18：工具调用耗时与完成标题

工具计时覆盖统一执行器实际执行区间，包含提供方、包激活和结果收集，不计入模型思考、生成参数与权限确认等待。分组使用执行区间并集，内部保存毫秒，不足一秒显示毫秒，达到一秒后显示整数秒。普通组、思考合并组和单个工具卡片沿用相同统计与完成状态。

## 执行与保存

参考 Operit2 的界面计时，将计时和正文完全分离。执行器通过类型化事件发布开始、完成和停止；一次回答的 ToolTimingState 单独接收，消息和标题订阅该状态，即使没有新的正文也更新，亚秒阶段约每 100 毫秒刷新，之后每秒刷新。

完成后记录保存在现有 sections JSON 的 tool_call.execution 字段。正文渲染不输出 execution，复制、搜索、提示词及工具结果正文不携带它。旧 Protocol/raw 计时生成器和渲染节点已移除；旧候选计时 Protocol 在读取时清理，供应商续传协议继续保留。

定稿及取消固定快照并释放运行态，回答版本独立保存。旧历史没有执行记录时只显示次数和真实完成状态，不补造耗时。跨进程时钟分开汇总，不在重启后继续使用上一进程的单调时钟。

## 验证范围

已有 11 项计时回归已改为类型化记录，新增 5 项取消终态锁定、正文隔离和数据库、版本、备份回归源码。尚未本地执行。仓库工作流与设备验证以真实结果为准。完整本轮范围和参考源码证据见 [首轮反馈修正](../patch18-integration/feedback-fixes.md)。

## 完整回归操作与预期

1. 执行单个耗时约 5 秒的工具：显示“工具调用 • 1次（x秒）”，运行时不足一秒显示毫秒，达到一秒后按秒更新，结果完整后改为“已完成”并固定耗时
2. 串行执行两个工具：次数为 2，耗时覆盖两次实际执行区间，不把间隔的模型生成计入
3. 并行执行两个不同耗时工具：重叠时间只算一次，不把两个耗时直接相加
4. 并行执行两个同名工具且后者先返回：结果保持原始顺序，单个耗时不交换归属，组耗时不重复累计
5. 产生一段思考和多次调用：合并标题显示“正在执行（x秒） • 1次思考 • N次调用”，完成后改为“已完成”
6. 连续执行较多调用：次数只统计原工具调用，不把类型化计时事件算成调用次数，计时不生成正文或可见空卡片
7. 使用只折叠只读工具的设置：保留原折叠范围，不分组的单独调用也显示摘要和耗时
8. 使用全部、全量折叠并手动展开收起：原展开选择保留，组内工具不重复叠加单独摘要标题
9. 工具完成后发送下一条消息：旧消息的次数与耗时继续显示，不依赖当前是否为最新消息
10. 滚动离屏再返回、切换聊天：已完成的耗时保持不变，不从零开始也不继续增长
11. 重启应用读取历史或继续旧消息：已保存耗时保持，未完成记录不会使用新进程的单调时钟重新计时
12. 复制正文、导出和后续模型请求：正文与工具结果不出现计时元数据，结果中的代码或元数据示例不被删除
13. 分别使用对话框、命令框及分享图片：单个与分组标题一致，分享读取固定耗时，明暗主题文字可读
14. 执行中停止或取消请求：停止后计时不继续增长，不把缺少结果的调用标为已完成；再次调用正常
15. 工具失败、拒绝权限或被拦截：保留原错误结果；未真正执行的调用没有执行区间，允许显示已记录的 0 毫秒
16. 等待人工权限确认及模型输出工具参数：这些等待不计入工具执行耗时，包激活与工具内部执行计入
17. 分别通过内置工具、包、MCP 和代理工具调用：统一执行器记录有效，计数口径仍是原始顶层调用
18. 使用流式、非流式和随机化 XML 工具标签：工具状态、参数详情和结果显示保持正常
19. 触发消息流保存点与回滚：被替换前缀的计时不重复累计，新节点使用其对应的回答和调用位置
20. 打开没有计时字段的旧历史及含其他提供方协议的消息：保留次数和真实完成状态，不补造耗时，协议不泄露
21. 切换同一消息的回答版本：每个版本保留自己的计时和展开状态，不借用其他版本的记录
22. 一个合并组中包含多轮工具调用：思考次数和调用次数正确，工具耗时排除两轮之间的模型生成时间

以上项目均未测，结果表单独保存，不标记为通过。

# 语音条第一版实现

本文记录第一版的 STT 文字请求实现。后续录完即试听确认、发送时选择音频处理方式及版本 2 数据格式见 [音频路由](04-audio-routing.md)，该文为当前行为。


本轮基于个人仓库的六分支联调及终端退出码修复版本，提供 Android 主聊天页中独立发送的语音条。实现已接入当前 STT 配置和当前对话请求，云端编译、单元测试结果及设备效果分别记录，不以静态检查代替运行结果。

## 输入与录音

经典和 Agent 输入组件新增可选录音回调，主聊天页主动接入。尚无当前聊天时先沿用新建聊天流程，再打开录音面板。空白文字、没有附件、没有引用且未处理请求时显示麦克风；已有附件仍走发送，正在处理仍保留取消逻辑。附件菜单里的语音通话继续使用原入口。未接入新回调的其他输入组件调用点保留原行为。

`ui/features/conversation/chat/modules/voice/` 独立提供底部录音面板、会话状态和播放器。首次打开请求麦克风权限，录音显示计时、实际 PCM 音量波形、关闭和“说完了”。录制结束进入确认页，成功转写后才允许发送，可以试听、查看文字和重录，失败后可重试转写。

`api/speech/voicemessage/` 使用独立 AudioRecord 录制 16 kHz 单声道 PCM16 WAV，文件位于 `filesDir/media_pool/voice/`，现有媒体存储统计和音频清理会覆盖该目录。Silero VAD 检测人声，连续三秒未检测到人声时停止；从开始一直无人声同样停止并提示重新录制。第一版设置 60 秒上限，波形压缩为至多 48 个峰值。VAD 和 AudioRecord 在录制结束时释放，非阻塞读取避免取消等待音频读满。

关闭、离开聊天及应用进入后台会结束面板并清理未发送录音。重录先删除上一条未发送录音。配置变化和进程终止不恢复未发送面板草稿，已经发送的语音仍保留在消息历史。

## 识别服务

转写器通过 `SpeechServiceFactory.createSpeechService` 使用当前 STT 配置，不增加服务选择页面或新模型。现有接口保留无语言参数调用，并增加带语言参数的重载；本轮传入 `zh-CN`。本地 NCNN 增加预录 FloatArray 识别，在原识别互斥锁内提交样本、完成解码和重置引擎，不重新打开麦克风。

OpenAI 和 Deepgram 批量识别在 finally 删除临时 WAV，取消时传播 CancellationException。共享 `api/speech/stt/http/SttHttpRequest.kt` 将 HTTP Call 接入协程取消，响应体在回调内读取并关闭；JSON 结果没有文字时返回空转写，不把原始 JSON 当作识别文字。转写设置 60 秒超时，服务正在准备、识别或处理时拒绝占用，使用后释放工厂服务租约。

本轮复用当前模型，不改变本地识别准确率。普通话是当前界面的使用范围，不代表新增多语言模型或对所有语言的识别能力作出保证。

## 消息和模型请求

`core/chat/voice/VoiceMessageMarkup.kt` 将录音附件、时长、波形和转写编码为版本为 1 的 `<voice_bar>`。录音使用现有自闭合 `<attachment>` 引用，转写经过 XML 实体转义。严格解析拒绝无效版本、时长、波形、附件和混入的正文；用户消息解析允许系统附加的工作区、代理发送者及回复标签。

消息保存继续调用 AIMessageManager，输入处理钩子接收转写文字，处理后重新封装语音条。Bubble 和 Cursor 用户正文直接渲染播放器；XML 渲染器另注册语音条插件，覆盖需要走 XML 渲染的内容。普通文本渲染路径不能依赖仅注册插件来显示用户语音。

当前请求、历史请求、对话标题生成以及上下文窗口统计会将有效语音标签替换为转写，保留外部工作区等上下文。模型消息处理钩子和 EnhancedAIService 收到文字，不触发录音附件的原生音频理解。消息自身保留语音标签，重开聊天可以继续播放和展开文字。

发送固定原会话，首次提交及异步配置读取后再次核对草稿、附件、引用和处理状态。语音不消费编辑器状态，因此不会把稍后添加的附件并入语音消息。用户消息保存后交接文件所有权，面板才关闭；尚未保存时关闭面板，会先取消并等待发送任务结束，再删除录音。正在保存期间禁止重复发送和重录。模型回复仍由既有聊天管线异步执行，保存成功不代表模型回复成功。

## 播放和数据边界

播放器点击时才创建 ExoPlayer，一次只播放一条，支持播放、暂停、播完重播和展开转写，使用语音媒体音频焦点，拔出耳机时暂停。退出后台或离开组合时释放资源，录音文件缺失显示错误并保留转写文字。

原始数据快照会包含 `filesDir/media_pool/voice/`。聊天记录文本导出保留消息数据及附件路径，并不新增音频文件打包；跨包名或不同存储路径导入后的录音重定位不在本轮实现。删除聊天或单条消息沿用当前媒体池保留策略，音频可通过现有媒体清理入口删除，清理后语音条显示文件不可播放。

# A2UI 本轮表单等待

## 背景与目标

原生卡片已经支持本地输入和模型向 live 卡片更新数据，但提交给模型会创建新的聊天请求，正在处理的轮次也会拒绝普通卡片提交。

本次给 `a2ui_prepare` 增加 `wait_timeout_seconds`，默认 0，允许 0–600 秒。设为 180 时，宿主在工具执行中显示卡片，等待用户提交、用户取消或超时，再将结构化结果返回当前工具调用。等待使用可取消协程，不通过持续轮询或新增聊天消息接收结果。

## 作用域

- 在专用 submission 包内管理等待请求、期限、提交身份及终态
- 流式工具执行负责显示卡片并挂起；停止生成时取消等待
- UI 保留输入校验和发送确认，确认后将等待表单数据交回当前工具调用
- 超时、取消、已提交和历史卡片均有明确状态，不能重复消费或转成新请求
- 普通卡片默认行为不变；live 与等待模式可一起使用
- 语法与用法说明集中在 `a2ui_catalog`，基础工具定义仅增加等待参数的类型、范围和默认值
- 不修改已保存聊天和 A2UI 协议的字段结构，等待身份使用独立 surface ID

## 返回结果

工具结果包含卡片引用及 `status`。成功提交时返回 `submitted`、动作和用户提交的 `data`；超时返回 `timed_out`；用户取消返回 `cancelled`。超时和取消不生成用户答案。父任务取消会终止工具调用。

## 回归检查

- W01：表单设置 180 秒；工具返回前即可看到并填写卡片
- W02：填写并确认提交；当前工具收到原始结构化字段，继续同一轮次，没有新增用户消息
- W03：不提交直到超时；收到 timed_out，卡片显示超时，不出现伪造答案
- W04：点击取消等待；立即收到 cancelled，后续提交不能唤醒该等待
- W05：停止生成；等待协程及请求记录被清理
- W06：提交后重复点击；结果只消费一次
- W07：其他聊天、不同卡片、不同消息或候选回复提交；均不串入当前请求
- W08：显示与挂起之间快速提交；结果保留，不丢失早到提交
- W09：等待期间滚出可见区、返回或切换前后台；同一请求继续等待，不重建等待计时
- W10：等待超时后重看历史；卡片不可再提交给已结束的任务
- W11：live=true 与等待一起使用；模型字段保护、数据版本和提交结果均正常
- W12：普通表单提交、保存草稿、取消编辑及本地交互；原行为正常
- W13：无效秒数、无运行上下文和无流式发布通道；工具明确拒绝，不留下悬挂记录
- W14：必填项未完成；不能提交，填写正确后可继续
- W15：历史卡片回放、消息内容和再次发送模型的上下文；表单与工具结果均保留且不重复投递

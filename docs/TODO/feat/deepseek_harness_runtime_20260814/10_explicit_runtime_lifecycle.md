# DeepSeek Harness 显式运行时生命周期

## 原状

侧边栏进入时将版本检查、pnpm 安装和 Web 启动合并执行。只要本地 DSH 进程不在运行，
就会自动执行 `pnpm add @latest`，用户无法在下载或编译前决定是否更新。

安装期间的状态区域只显示最后一条终端片段，终端回显和真实 pnpm 输出混在一起，无法判断
当前阶段和实际进度。

## 修改

- 进入侧边栏后先读取本地 DSH 版本，再显式查询上游 `latest` 版本。
- 未初始化时只显示初始化操作；检测到新版本时显示安装更新与继续使用当前版本两个操作。
- 本地版本已是最新时直接启动现有 DSH，不执行 pnpm 安装命令。
- 将运行时 API 拆分为检查、安装更新和启动，移除自动安装语义。
- 安装脚本发出结构化阶段与输出事件；界面上方显示当前安装阶段，下方显示 pnpm 和编译输出。
- 将等待界面重排为页头、状态摘要、版本信息、操作区和按需出现的安装输出区。
- 未初始化、发现更新和错误等静态状态不显示进度条；检查、安装、启动与网页加载期间才显示进度。
- 操作按钮使用图标、稳定高度和 8px 圆角，安装输出使用只读终端样式展示。
- 安装失败时保留精确失败命令、退出码、超时状态与终端原始输出；结构化结果缺失不得覆盖真实错误。
- 已安装版本通过 Linux 文件 API 读取绝对路径清单，不依赖新终端会话的当前工作目录。

## 验收标准

- 已安装且版本相同的 DSH 只检查版本并启动 Web，不执行 `pnpm add` 或 `pnpm install`。
- 检测到更新时，安装命令只能由用户点击更新操作触发。
- 首次使用时，安装命令只能由用户点击初始化操作触发。
- 安装界面同时显示当前步骤、进度条和持续追加的结构化安装输出，不显示 PTY 输入回显。
- 静态操作页面不显示 0% 进度条，版本与主要操作在窄屏上仍保持清晰层级。
- Node.js 等前置条件检查失败时仍返回 shell 原生结构化事件，并在界面中展示可复制的命令结果。
- 重新进入侧边栏时能够从绝对路径读取已安装版本；检查失败时界面展示具体诊断信息。

# DeepSeek Harness 启动就绪协调

## 原状

侧边栏在 DSH Web 启动后只等待 30 秒。未达到 HTTP 就绪状态时，界面显示错误。
普通 `Retry` 传入 `forceRestart`，侧边栏重入也会重新进入安装与启动流程，可能终止
已经在启动的 DSH 进程。

## 修改

- Web 就绪检查最长等待两分钟。
- PID 指向存活进程但 HTTP 尚未就绪时，继续等待该进程。
- 普通 `Retry` 继续检查当前服务；服务控制子包的显式重启保持终止并重启语义。
- 状态接口返回 `starting`，区分服务启动中和已停止。
- 本地健康检查的连接失败只作为未就绪状态处理，不重复记录插件错误，也不打印 HTTP
  请求异常堆栈。
- PID 文件中的数字必须对应带有 DSH 运行时标记的进程；PID 被复用或服务退出后，不能被误认为
  正在启动，也不能被停止操作误杀。
- 终端命令完成事件不能提供 Bash 的真实退出码，因此进程检查只识别目标进程实际输出的专用成功标记。

## 验收标准

- 首次原生模块编译后的 DSH Web 启动不因 30 秒检查窗口被错误报告为失败。
- 重开侧边栏或点击普通 `Retry` 不会终止已经启动中的 DSH 进程。
- 显式重启工具仍会停止旧进程并启动新进程。
- DSH 尚未监听回环端口时，日志保留简短的工具失败文本，不包含 `ConnectException` 堆栈或
  `DeepSeek Harness health check failed` 重复记录。
- PID 文件过期或指向其他进程时，普通启动会重新拉起 DSH；显式停止和重启不会向该其他进程发送
  `kill`。
- 目标进程检查命令即使被终端标记为 `exitCode: 0`，未输出专用成功标记时也必须视为未运行。

# 图片气泡极小平铺卡顿与简化调节

继续使用 `feat/chat-batch-and-settings` 和 PR #18。用户反馈将图片气泡各项调到最小值后，预览或聊天容易卡住；原编辑器同时展示裁切、横纵起终点、缩放和两侧留白，不易判断每项对应的视觉效果。

## 原因

`BubbleImageBackgroundSurface.kt` 原先通过横向、纵向和双向循环逐块绘制平铺区域。中段缩至 1 像素、缩放调到最小时，有效平铺周期仍是一像素；例如 1080 × 2400 的中心区域需要约 259 万次 `drawImage` 调用。滑动和流式输出不断重新绘制，主线程无法及时处理其他事件。参数限制只能保证坐标合法，不能限制绘制次数。

## 渲染实现

- `BubbleImageLayout.kt` 保留已有裁切比例、缩放范围、像素取整和分段消息几何规则，将布局计算独立为纯函数，供绘制和 JVM 回归共用
- `BubbleImageTiling.kt` 为中间与四边各建立 `BitmapShader`，重复方向使用 REPEAT，边框厚度方向使用 CLAMP；每个区域一次矩形填充，四角各绘制一次，每个气泡背景最多九次绘制，不再随平铺数量增加主线程绘制调用
- 切片在后台准备，按源图片与实际切片布局共用有大小限制的缓存；缩放和透明度变化复用切片，每个气泡单独持有 Shader、Paint 和 Matrix，避免不同消息修改同一份绘制状态
- 顶底装饰仍只出现在消息首尾，中心与两侧供连续内容块使用；普通图继续平铺，`.9.png` 继续沿用拉伸模式、导入标记和内容区处理，背景透明度只作用于背景

## 设置交互

图片气泡编辑器独立到 `ui/features/settings/components/bubble/BubbleImageStyleEditor.kt`，用户和 AI 气泡共用，常用区只展示以下调节：

- 装饰大小：20%～300%，直接修改原图片缩放参数
- 文字左右留白：0～32 dp，同时修改左右；恢复按钮将大小设为 100%、左右留白设为 12 dp，保留裁切与扩展范围
- 保留多少边框装饰：少一些、适中、多一些，分别保留四周 20%、35%、45%，中间区域对应 20%～80%、35%～65%、45%～55%；只在点击时写入，不覆盖自定义范围

高级区默认折叠，保留四向裁切、横纵扩展区间和左右独立留白。每个扩展区间用双端滑块成对编辑，横纵范围一次写入草稿，减少起终点分开修改时的无效组合。新增说明与控件标签覆盖现有九种语言。

既有配置键、图片 URI、角色主题字段和保存值均保留。打开编辑器只显示经过原约束后的滑块位置，不自动重写旧配置；主题草稿的保存、放弃、取消及玻璃气泡互斥机制继续由原会话处理。

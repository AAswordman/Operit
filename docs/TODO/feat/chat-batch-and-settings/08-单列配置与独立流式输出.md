# 模型配置单列排版与独立流式输出

沿用 PR #18 和 `feat/chat-batch-and-settings` 分支，目标 `dev`。本轮在尚未发布的模型工作区上继续迭代，按已确认的原 HTML 排版调整 Android 页面。

## 预期行为

- 请求能力采用一张卡片中的纵向整行开关，顺序为工具调用、流式输出、图片理解、音频理解、视频理解；保留“x / 5 已开启”，不添加说明展开功能
- 新配置的工具调用与流式输出默认开启，已有配置保留用户保存的工具开关
- 流式输出独立保存到每份模型配置；升级时将旧全局选择一次性写入已有配置，此后不同配置独立修改
- 功能分配采用一行一项，保留现有筛选、绑定、思考设置和测试菜单；显示名称使用“记忆更新”和“群组发言规划”
- 页面标题与服务选择对齐 HTML，配置预览放进顶部“更多”，使用真实已保存配置并遮罩密钥

## 实施步骤

1. 扩展模型配置与偏好版本迁移，将流式设置接入现有保存协调；旧聊天设置接口继续使用原字段名，操作当前聊天绑定的配置
2. 在服务创建和消息发送处应用当前配置的流式选择，保留调用方明确请求非流式的行为
3. 调整请求能力、功能列表、页面标题和服务选择，增加居中的配置预览；功能编辑菜单保持现有实现
4. 补充迁移和请求转发的远端单元测试场景，更新完整验收清单及结果空表；不运行本地编译、构建或测试
5. 核对提交范围，排除对话滑动多选草稿，推送原分支，派发 Android Build 与 Android Tests，更新 PR 说明后结束，不轮询 CI

## 已实现与验证范围

模型配置新增 `enableStreamOutput`，偏好版本升至 6。迁移只对缺少该字段的已有配置写入旧全局选择；保留已有独立值，后续修改、复制、导入导出跟随配置。旧聊天设置接口保留字段名，读取和修改当前聊天绑定配置，不再保存全局覆盖值。

`ConfiguredStreamingAIService` 在统一服务创建处约束实际发送方式；聊天的请求元信息同步使用当前执行快照中的流式选择。调用方明确使用非流式时继续保持非流式，后续工具轮次与其他功能服务也经过该约束。

连接页沿用原服务、OAuth、本地模型、密钥池、模型列表和保存协调，将请求能力移出 API 卡片，改为单张纵向卡片。功能分配只改列表体，`ModelFunctionEditor.kt` 的菜单源码未改。配置预览在保存完成后读取当前配置，遮罩单密钥、密钥池和请求头值，窗口居中显示。

新增 9 项 JVM 用例，分别覆盖迁移与序列化、两种配置独立发送、调用方非流式与回调及生命周期转发、预览内容和认证遮罩；交由远端 Android Tests 执行。本地只进行了差异、Kotlin 语法、资源 XML 与引用、Material 图标覆盖、草稿哈希和完整验收数量核对，没有执行 Android 编译、构建、单元测试或真机验收。语法解析不能替代编译结果。

完整验收保留此前 422 项，新增 18 项，共 440 项；每项都有独立结果行，历史结果保留，新增结果留空。远端使用 Android Build 的 `assembleDebug` 与 `publish_release=false`，以及 Android Tests；派发和运行结果以 PR 真实记录为准。

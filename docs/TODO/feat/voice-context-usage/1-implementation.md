# 实施记录

## 语音结果分离

辅助音频模型一次接收录音，按 JSON 协议返回 transcript 和 audio_context 两个字符串。原话单独验证，空原话或缺少原话字段不能因为声音描述非空而被认为识别成功。描述只能包含有依据且相关的语气、说话方式、语速、录音内相对音量及背景声音；不要求每段都填写描述。

VoiceAnalysis 和语音消息存档分别保存原话与声音观察。语音条仍只读取 transcript；文本请求明确标注声音观察来自辅助模型，不是用户原话。输入钩子已有的附加文字单独保留为请求上下文，避免混入新的转写。

直接音频路径继续携带真实录音与已有文字，不强制增加识别调用，也不改成一律 STT。未配置或无法使用辅助模型时沿用已有 STT 顺序，STT 不生成声音观察。直接音频路径仍不保证额外生成展示转写，这轮不增加强制转写或新的点击转写流程。

旧版 v1/v2 语音消息继续可读，不自动重写历史已保存的转写。历史请求保留原话和已有文字观察，原始录音仍只随当前用户轮次发送。原附件描述、播放和失效入口保持原流程。

## 累计用量九类记录

只调整累计用量页：用户消息、AI 消息、工具结果、系统提示词、常驻工具、MCP／包工具、技能目录、压缩摘要、其他，九类全部为一级条目。颜色复用窗口页，比例以累计消耗总额计算。窗口页保持消息历史父项和三项子列表；配色声明仅放宽到同包复用，布局代码未改。

主请求及工具后续请求完成时，按实际请求消息与工具估算输入分类，并校准到现有提供方输入总额；输出加入 AI 消息。各次请求累加为本轮明细，沿既有会话累计入账时点保存。分类是估算，累计输入、输出的来源和现有统计口径不变，不把最新窗口比例当作历史消耗比例。

会话新增可空 usageBreakdownJson，数据库由 28 迁移至 29。旧记录没有分项信息，旧输入归入其他，已有输出归入 AI 消息，累计总额保留。界面九语种说明明确标注分类估算与历史未分项输入。本轮总额与分类先一起入库，再更新内存统计，避免切换保存抢先记成未分项输入。普通保存按新增累计差额入账，重复或迟到快照不重复累加；窗口刷新不改累计明细。

会话分支、实体与模型转换保留明细字段，JSON 归档与 CSV 导出、导入均传递可选明细字段，旧备份缺少该字段或列时继续可读。完整数据库备份包含新列。清空累计总额后，旧明细会按新总额归零，不影响后续新请求。

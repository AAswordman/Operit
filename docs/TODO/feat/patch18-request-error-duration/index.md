# 补丁 18：请求错误提示时长

OKToast.requestError 原来默认使用 LENGTH_LONG，即 3500ms。本轮沿用原卡片、队列、宿主和点击销毁，只调整请求错误的计时规则。

请求错误最短 5000ms，前 80 个 Unicode 字符保持 5 秒，超出后每个字符增加 25ms，最多 12000ms。系统无障碍建议参与计算后仍限制在 5～12 秒。普通 info、success、warning、error 不改变现有时长。

保留 requestError 的现有函数签名，避免影响已发布调用方。其 SHORT/LONG 参数不再缩短请求错误的最小时长。

## 工作范围

1. 新增独立的请求错误时长规则，接入显示调度
2. 保留正文、空白区域和无障碍点击销毁，拖动长文本不触发销毁
3. 静态核对并保存本地快照，不运行构建、测试、真实请求或工作流


## 本地完成情况

原始 OKToastView 与点击销毁代码逐字节保持；仅在 requestError 的显示调度中应用新时长，兼容既有函数签名。

本轮仅静态核对，没有编译、构建、运行测试、设备验收或真实模型/工具请求；没有 commit、推送、PR 或工作流。

## 完整回归操作与预期

1. 显示 1～80 个字符的 requestError：基础显示 5 秒，保留原卡片样式
2. 分别显示 81、160、360 个字符：基础时长依次为 5025ms、7000ms、12000ms
3. 显示超过 360 个字符的请求错误：显示时长不超过 12 秒，正文仍可滚动
4. 显示包含表情和中英文的文本：按 Unicode 码点计数，不按 UTF-8 字节或代理对重复计数
5. 分别传入 LENGTH_SHORT、LENGTH_LONG：requestError 均遵循 5～12 秒规则；空白消息仍不显示
6. 显示普通 info、success、warning、error：原有短提示 2 秒、长提示 3.5 秒及无障碍建议保持原行为
7. 点击请求错误正文和卡片空白区域：立即销毁本条提示，队列继续显示，原请求不被取消
8. 拖动长错误正文、切换窗口并使用无障碍关闭：拖动不误销毁，点击及无障碍销毁有效，请求错误最终推荐时长仍限制在 5～12 秒

# 聊天弹起菜单的主题形状与位置

截图中的附件、模型选择和聊天设置弹窗使用固定圆角和右下角定位，未读取通用消息菜单的主题外观。工作室需要分别编辑这三个容器，并能移动整个弹窗。

## 实现范围

1. 在现有主题协议中增加 `attachmentMenu`、`modelMenu`、`chatSettingsMenu` 三个区域，复用形状、描边、填色、图层和内容留白。新增 `popupOffset.up/down/left`，每项为 `0..256 dp`，默认零；仅这三个区域可使用非零偏移。
2. 三个真实菜单与工作室预览共用原生容器和定位实现。向上与向下取差，向左使用物理方向；按实际窗口和菜单尺寸限制位置，保持完整容器可见。原菜单动作、滚动和关闭逻辑继续由业务内容持有。
3. 工作室增加独立部件、中文和英文标签及位置滑杆；同步脚本类型声明、制作文档与现有全量验收清单。

## 预览参照与偏移编辑迭代

1. 上下位置控件互斥，滑杆和数字输入同步禁用，归零后解锁。既有同时设置上下的工程按净位移显示，编辑时写回等效的单方向数值，保留实际位置并避免两个方向都无法操作。
2. 三个菜单切入完整聊天场景，显示正式顶栏、示例消息、输入区和复用真实内容的菜单；移除独立空白画布和简化菜单列表。预览只展示，不执行会话、配置或附件操作。
3. 从工作室外层应用窗口取得扣除系统栏的聊天尺寸，小预览和全屏使用同一尺寸测量并按可用空间等比缩放，避免编辑面板和全屏标题改变菜单的坐标参照。
4. 更新既有 PR 与完整验收清单，只提交到当前工作分支，派发新的 Debug 构建，不等待或轮询。

## 小预览满宽滚动迭代

1. 小预览按可用宽度等比显示完整聊天画布，超出当前高度的部分上下滚动；全屏继续完整适配窗口。
2. 菜单和其他已接入的部件在选中并完成布局后，使用实际边界请求滚动到可见区域；手动滚动不持续触发自动定位。
3. 保持原始聊天测量尺寸、菜单坐标和缩放比例一致，滚动仅改变小窗口的查看范围。更新几何回归、制作文档和完整设备清单后，提交到原工作分支并派发 Debug。

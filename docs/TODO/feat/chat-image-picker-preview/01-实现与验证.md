# 实现与验证

## 旧实现与目标

经典输入布局与 Agent 输入布局都在 `AttachmentSelector.kt` 使用 `OpenMultipleDocuments` 添加图片。图片添加后通过 `AttachmentChip` 显示缩略图，缩略图没有查看大图的操作。

本次把聊天图片入口改为应用内媒体库选择器，并为附件与相册共用全屏预览。只在用户确认时添加选择结果，关闭选择器或预览不会自行提交。

## 组件与数据流

图片选择与预览位于 `ui/features/conversation/chat/modules/attachments/images/`，包含以下组件：

- `ChatImagePickerDialog.kt`：全屏 Compose 相册网格，按 MediaStore 的图片时间倒序展示；支持相册筛选、跨相册多选、长按或按钮预览、确认数量、刷新，以及照片授权状态
- `MediaStoreImageRepository.kt`：在 IO 线程读取图片元数据，读取循环响应取消；区分无权限、部分图片权限和完整权限，不把查询失败显示成空相册
- `AttachmentImagePreviewDialog.kt`：黑底全屏 Dialog，支持双指缩放、双击三倍放大或复位、放大后拖动、右上角关闭和系统返回；关闭预览不删除附件
- `ImagePreviewTransform.kt`：根据图片适配视口后的实际尺寸计算缩放焦点和拖动边界，限制在一至六倍；缩小到适配大小时回到居中位置

`AttachmentSelectorPanel` 与 `AttachmentSelectorPopupPanel` 移除图片专用的系统文档选择器 launcher，统一调用新选择器。`AttachmentChip` 点击图片时打开预览，经典、Agent 与已有使用该组件的窗口共享预览能力。

选择器只提供 MediaStore URI，继续由现有 `AttachmentDelegate` 复制到附件临时目录再加入待发送列表。`services/core/attachments/ImageAttachmentIndex.kt` 缓存待发送图片的 SHA-256 指纹，在 IO 线程比较相同内容，避免不同 URI 或不同临时路径导致重复添加；图片提交串行处理，重复副本删除并显示已有 Toast 事件提示。移除当前附件后可以重新添加相同内容，同名不同内容仍允许添加并由现有命名规则区分。

## 权限与兼容性

Android 8 至 12 使用已有外部存储读取权限；Android 13 使用 `READ_MEDIA_IMAGES`；Android 14 起同时支持 `READ_MEDIA_VISUAL_USER_SELECTED`。已有完整文件访问授权按完整访问处理。进入设置、调整照片权限后返回，会重新检查可访问的图片并清理失效选择。

未授权时显示明确授权入口和应用设置入口；部分授权时仅显示系统允许读取的图片，并提供管理可访问图片的操作。图片列表的 UI 由 Compose 绘制，权限授予仍使用 Android 权限机制。

缩略图由可见网格项按需解码；预览只加载当前图片，限制最大解码边长，避免直接解码超大原图。图片读取失败显示错误文案。

不修改持久化数据或公开接口。新增照片权限声明与九种语言各十四条提示文案。第 6 条全局 Toast 样式和第 22.2 条删除动画保持待定。

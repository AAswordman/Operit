# 打包、文档与验证

新增命令由现有 native terminal composite action 构建，生成独立清单。Gradle 及最终 APK 校验要求 `apply_patch` 和 `web-chat` 两套资源同时完整。PR 检查分类包含新命令目录，后续仅修改该目录也会覆盖完整 Android lane。

新增回归源码包括 Rust 参数和 IPC、Kotlin 协议与登录 URL、网页登录状态，以及 ARM64 分发安装。用户操作与迁移说明见[命令文档](../../../doc-src/feature-protocol/web_chat_cli.md)和[更新日志文案](release-notes.md)。

## 完整回归清单

- V01：在普通 proot 新开终端，`web-chat --help` 可用且不启动 HTTP。
- V02：在 root chroot 新开终端，命令寻址宿主控制通道。
- V03：升级后 `status` 显示原端口、启用状态和真实运行状态；`token show` 保留旧 Token。
- V04：首次 `start-server` 使用默认 8094 并生成 Token。
- V05：指定端口启动后，本机与当前网络 URL 使用实际监听端口。
- V06：同端口重复启动不更换 Token；切换端口后旧端口停止监听。
- V07：端口为 0、负数、非数字或大于 65535 时，返回参数错误，不改服务配置。
- V08：端口被占用时返回服务错误，不误报启动成功。
- V09：不带 `--login` 时仅输出带说明的 URL 和 Token，剪贴板不变。
- V10：带 `--login` 时请求默认浏览器，自动使用当前 Token 登录。
- V11：URL Token 覆盖浏览器中旧 Token，地址栏仅移除 Token，保留其他参数和锚点。
- V12：Token 中包含加号、空格、引号或查询分隔符时，编码和解析保持正确。
- V13：无效 Token 仍被服务拒绝，网页显示现有鉴权错误；手动登录继续可用。
- V14：`token reset` 后新 Token 可鉴权，旧 Token 的后续请求被拒绝。
- V15：`stop-server` 停止网络服务并关闭自动启动；再次打开 App 不自动重启。
- V16：仅退出终端会话不停止已经启动的 HTTP 服务。
- V17：`examples` 按同步、异步、健康检查、Intent 顺序输出全部四类。
- V18：四个指定类型各只输出对应示例；未知类型、重复参数或多余位置参数报错。
- V19：示例使用当前端口和 Token，特殊引号不会破坏 shell 参数，不自动发送请求。
- V20：同步 HTTP、异步回调、健康检查与 Intent 按现有协议工作。
- V21：A2A Agent Card 与 JSON-RPC 仍使用相同端口及 Token。
- V22：设置入口和旧页面路由不存在，九种语言中没有旧页面专用资源引用。
- V23：应用进程重启后新终端重建控制通道；不可用通道返回非零结果。
- V24：资源校验拒绝篡改、错误架构、缺失命令以及与当前生成目录不一致的 APK。
- V25：并发安装、含引号路径、重复安装和命令升级均保留完整可执行命令。

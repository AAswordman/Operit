# 请求错误提示样式修正与 +7 范围评估

## 请求错误提示

缺密钥和空模型 ID 已有发送前校验，但调用 UiStateDelegate.showErrorMessage 后会显示居中的“请求失败”对话框，需要用户确认才能继续编辑。用户希望使用 HTTP 429、502 等请求错误的上方提示样式。

在现有 OKToast 内增加请求错误入口，复用四态颜色、图标、宿主、队列、长文滚动和无障碍阅读时间。请求错误使用靠上位置与较宽卡片，正文从起始侧排列；普通提示继续使用下方 90% 高度处的紧凑居中布局。两种位置都按当前可见窗口比例计算，不恢复独立的旧聊天 Toast 队列。

缺配置、HTTP 重试提示和最终请求失败共用上方请求错误入口；配置错误不再写入模态错误状态。发送前返回、保留草稿与附件、失败保存部分回复及解除加载的逻辑保留。

## 插件文件功能的工作量与发版组合

此前文件接口、归属传递、存储后端和快照恢复的调查见 [04-插件文件统计与快照评估.md](04-插件文件统计与快照评估.md)。完整实现资源登记、按插件统计管理、快照导出与恢复，初步预留 1～2 个开发日；CI 排队和用户真机反馈另计。该估算不等于功能已开始实现或通过验证。

该评估最初考虑将插件文件功能纳入 +7；用户随后确认暂时搁置。1.12.2+7 仅发布已实现的 Toast、对话列表与请求错误修正，插件文件功能不纳入本次发行。

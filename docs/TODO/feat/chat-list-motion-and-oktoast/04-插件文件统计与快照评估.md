# 插件创建文件统计与快照覆盖评估

状态：仅代码调查，尚未实现，不属于本轮必须修正的两项功能。

## 现有调用链

`core/tools/javascript/JsTools.kt` 将 `Tools.Files.write`、`writeBinary`、`apply`、`create`、`edit`、`copy`、`move`、`download`、`zip`、`unzip` 等操作交给统一工具调用。文件类型由内容决定，文本、图片、音频、视频和任意二进制都能覆盖，不需要按扩展名维护白名单。

`JsEngine.ExecutionSession` 已记录 `packageName` 和 `callId`，但同步、异步和流式工具桥接入口还没有把插件归属随每次调用传给 `JsNativeInterfaceDelegates`。异步委托会新建线程，不能依靠某个全局“当前插件”变量判定资源归属。多个插件并发时需要传递不可变的调用来源。

`StandardFileSystemTools` 会将 Linux 和 SAF 环境分派给对应后端；还有管理员与 Root 等实现。只在某个 Android 写文件函数中登记，会遗漏复制、移动、压缩、解压、下载与其他后端产生的文件。

## 快照当前覆盖

`data/backup/RawSnapshotBackupManager.kt` 归档应用内部文件、应用专属外部文件、偏好、数据库和显式引用的资源。`RawSnapshotResourceReferences.kt` 当前登记的是头像、背景、气泡图和字体，不包含插件创建文件清单。

`OperitPaths.pluginsDir()` 位于公共 `Download/Operit/plugins`。写到应用专属目录里的插件文件可能已随整目录进入快照；写到公共目录、用户指定目录或其他环境的文件，没有因“由插件通过接口创建”就自动进入快照的保证。不能把整个 Download 目录当成插件资源进行归档。

## 建议实现范围

- 新建独立的插件资源目录与登记模块。登记插件 ID、环境、规范路径或 URI、创建来源、大小和时间；相同文件去重，保存与覆盖成功后登记，删除或移动成功后更新，不登记失败写入
- 将调用来源沿同步、异步和流式桥接传递到底层。覆盖 create、write、writeBinary、apply、edit、新文件下载、复制、移动、压缩与解压；目录操作登记实际生成的文件清单
- 增加按插件查看文件数量、总大小、清单、备份开关和清理的管理入口。可为新资源提供插件专属默认目录，旧接口的明确路径不静默重定向
- 快照增加资源清单和内容归档，恢复时处理路径、URI 权限、重复文件、原目录不可用以及插件内保存的引用；清单也需要随快照恢复，否则恢复后无法继续统计
- 区分临时文件与持久资源：`cleanOnExit`、缓存及中间产物不应默认成为永久快照内容；备份期间的写入需要一致的版本或文件读取策略

## 边界与难度

只针对通过应用文件接口创建的文件，完整实现为中等偏大的改动，主要工作在插件归属、多个文件后端与恢复一致性。可以拆成资源登记、管理入口、快照导出恢复三个提交单元集中开发。仅增加一个创建目录或扫描目录不足以满足全部接口覆盖。

Shell、终端、FFmpeg、原生 Java 桥接等外部执行过程自行写出的文件，不会自动经过 `Tools.Files` 的成功返回边界。以后要纳入这些输出，可以增加显式资源登记接口或约定受管理的输出目录；不应宣称能自动追踪任意进程对文件系统的所有写入。

历史文件缺少插件归属记录，不能准确倒推出由哪个插件创建。后续如需纳入，可让用户选择导入管理；新增登记不自动猜测历史所有权。

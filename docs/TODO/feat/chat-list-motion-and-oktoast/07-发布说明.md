1.12.2+7（versionCode 63）：本补丁精简对话列表操作，加入新建与删除动画，统一四态提示，并完善模型配置错误、请求失败和增量更新说明的处理。

## 更新

- 精简对话与文件夹菜单：移除重复的「上移」「下移」「移动到…」入口，继续使用已有的长按拖拽移动、排序和文件夹悬停展开。
- 将「新建文件夹」收进原有的新建对话胶囊，保留独立点击区域；胶囊宽度保持，搜索和显示设置的位置不变。
- 删除对话时增加标题分块消散和列表补位动画。菜单删除与左滑删除沿用确认流程，删除失败时恢复标题，锁定对话仍受原有保护。
- 新建空白对话时增加固定 1.8 秒的 Operit 像素聚字动画，粒子轨迹随新会话变化；输入、发送或离开页面时可结束动画，系统关闭动画时跳过效果。
- 全局提示统一为 OKToast，区分信息、成功、警告和错误四种状态，覆盖聊天、附件、设置、插件与技能等入口，并适配应用主题和无障碍阅读时间。
- 普通提示按可见窗口比例显示在下方，卡片随文字收紧，文字居中、图标贴近正文；移除关闭叉号，长内容支持换行和滚动。
- 缺少密钥或模型 ID、HTTP 重试及最终请求失败统一使用靠上的错误卡片，无需关闭居中确认弹窗即可继续操作。

## 修复

- 未配置有效 API 密钥或模型 ID 为空时，发送前显示明确的配置错误，保留草稿和附件；本地免密端点、账号认证、密钥池和自定义认证请求头按各自配置处理。
- 调整请求失败后的异常传递和收尾，避免多个协程重复抛出同一普通请求错误；保留已生成的部分回复、解除加载状态，并保留正常取消行为。
- 修复发布流程把 JSON 元数据写入 Release 正文的问题。页面显示可读更新说明，元数据保留为附件；新版客户端兼容从元数据附件读取跨版本补丁链索引。

## 增量更新

本版以 `v1.12.2+6` 的正式 APK 为增量基线，提供完整 APK、增量 ZIP、补丁元数据和发行摘要。已安装原签名 `+6` 正式版的用户可在应用内检查更新；按照现有渠道规则，`+n` 补丁版需要开启 Beta 计划。调试包与 Kong 正式包的数据及签名不同，请使用正式版更新入口。

## Update

- Simplified conversation and folder menus by removing redundant move actions. Existing drag-and-drop movement, sorting and folder expansion remain available.
- Placed the new-folder action inside the existing new-conversation capsule, with a separate touch target and unchanged capsule width and adjacent controls.
- Added a dissolving-title transition and animated list movement when deleting conversations. Confirmation and lock protection remain in place, and failed deletion restores the title.
- Added a fixed 1.8-second Operit pixel intro for newly created empty conversations. Particle paths vary between sessions; typing, sending or leaving the page can end the effect, and disabling system animations skips it.
- Unified application notices with four OKToast states: info, success, warning and error, with theme support and accessibility-aware reading time.
- Positioned ordinary notices proportionally near the bottom of the visible window. Cards fit their text, use centered wording and a nearby icon, omit the close button, and support wrapping and scrolling for longer content.
- Routed missing configuration, HTTP retries and final request failures through a shared upper error card so editing can continue without dismissing a modal dialog.

## Fixes

- Check for missing valid API credentials or an empty model ID before sending, while keeping the draft and attachments. Local endpoints, account authentication, key pools and custom authentication headers retain their configuration rules.
- Reworked request-failure propagation and cleanup to avoid rethrowing the same ordinary failure across multiple coroutines, preserve partial replies, clear loading state and retain cancellation behavior.
- Fixed Release pages showing JSON metadata as their description. Human-readable notes are now separate from metadata attachments, and the new client can read patch-chain indexes from those attachments.

## Incremental update

The incremental baseline is the official `v1.12.2+6` APK. This release includes the full APK, an incremental ZIP, patch metadata and a distribution manifest. Official `+6` installations using the original signature can check for updates in the app; the existing channel rules require the Beta plan for `+n` patch releases. Debug builds use separate signing and application data.

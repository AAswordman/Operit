# 第十二节：插件 UI 注册与工具箱导航兼容

测试全部通过。完整操作与预期保留，结果如下。

## 原状与目标

`registerToolboxUiModule` 同时注册 UI route 与工具箱导航卡片，插件详情的配置界面列表又依赖这条导航卡片。显式声明 `surface: "toolbox"` 也会向工具箱发布插件入口。工具箱将逐步移除，本节先让旧注册 API 只保留界面及路由能力，并确保插件详情仍可打开 Compose DSL 界面。

## 改动范围

- 旧 `registerToolboxUiModule` 调用保持可用，继续验证包内 screen、生成稳定 UI route 和页面模块，但不再自动生成 toolbox 导航项。
- 插件详情根据旧 UI 模块的注册来源列出界面，点击后沿用原来的 Compose DSL 页面；显式注册的 toolbox UI route 也继续在详情中可打开。
- 旧 `surface: "toolbox"` 声明仍可解析及校验，宿主不再向导航目录发布该入口；`main_sidebar_plugins` 导航项和独立 UI route 维持现有行为。
- 不删除工具箱原生页面和其他内置工具，不改插件资源格式及其余入口迁移。

## 核对

- 静态检查：确认旧注册的 route、模块和详情入口保留，自动与显式 toolbox 导航均不会发布，主侧边栏注册仍发布。
- 本地编译和测试不运行；按仓库规则触发远程 Android Tests 与 assembleDebug，结果由后续通知确认。

## 设备回归

1. 启用仅用旧 API 注册 Compose DSL UI 的插件：工具箱没有插件卡片，插件详情能打开配置界面，返回正常。
2. 启用显式注册 `surface: "toolbox"` 的旧插件：插件加载正常，工具箱没有该插件卡片，注册的 UI route 仍可用。
3. 启用显式注册 `surface: "main_sidebar_plugins"` 的插件：主侧边栏入口仍可打开并返回。
4. 通过内部路由、桌面小组件打开已注册的插件 UI：页面及返回仍可用。
5. 检查工具箱原有内置卡片：本轮未调整的卡片仍按原状显示。

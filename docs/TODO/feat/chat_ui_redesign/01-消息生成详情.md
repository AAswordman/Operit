# 消息生成详情

本次补录：用户确认目前 Bug 均已修复，本页待填写的验收说明已按用户确认同步。验证来源及现有 CI 记录见[验证结果补录](../../chore/distribution_integration/06-验证结果补录.md)。

## 原有行为

聊天底部的 Token、耗时、速率和时间使用四段独立文本。消息信息弹窗显示身份、时间与耗时、Token，但没有 Speed 和精确总计。两处 Token 数字均没有千位分隔符。

## 实现范围

`app/src/main/java/com/ai/assistance/operit/ui/features/conversation/chat/modules/messages/details/` 独立负责生成详情和公共格式化。`ChatArea.kt` 接入详情和右下角完成时间，`MessageInfoDialog.kt` 复用完整数字、Token 明细、耗时和速率格式。

生成详情默认折叠。启用 Token 简报时，标题只显示整数 K/M/B 总用量；不足 1,000 时显示原数字。缩写使用四舍五入，达到 1000K 或 1000M 时进位为 1M 或 1B。展开后按以下顺序显示四组信息，窄屏和大字体允许明细自然换行：

1. 精确总计：输入 + 输出，缓存命中不重复计入
2. 输入、输出、缓存命中和命中率：保持同一组紧凑文本
3. 首包等待与生成耗时：以秒显示时保留两位小数
4. Speed：输出 Token / 输出耗时，保留一位小数，单位为 tokens/s

只启用耗时或速率时，折叠标题显示“生成详情”，Token 字段继续由自己的开关控制。消息统计更新不重置展开选择，切换回答版本时恢复默认折叠。回答版本切换入口继续独立保留。

完成时间显示在整条消息右下角，使用已保存的 `completedAt`，不加入定时刷新，不受详情展开状态影响。未记录完成时间的消息不显示该时间。

长按消息信息在原有时间与耗时卡片中增加一排 Speed / 完成时间，保留精确到毫秒的时间和毫秒耗时。Token 卡片增加精确总计，所有完整数字使用逗号千位分隔符，例如 `417,762` 和 `419,177 ms`。速率所需数据未记录时，消息信息显示“未记录”。聊天显示开关不限制长按信息的完整数据。

## 设置与统计口径

沿用 `show_message_token_stats`、`show_message_timing_stats`、`show_message_token_speed` 和 `show_message_timestamp`，不新增数字格式选项、不修改数据库或消息字段。相关说明覆盖现有 9 种语言，旧的独立简报渲染和未再使用的资源已清理。

缓存命中率仍使用缓存输入 / 输入，并保留原来的百分比截断规则。生成耗时仍使用已有首包至本轮结束的时间记录，包含这个区间中的工具执行和等待；Speed 表示该区间的平均输出速率，本节没有引入纯模型生成耗时计量。

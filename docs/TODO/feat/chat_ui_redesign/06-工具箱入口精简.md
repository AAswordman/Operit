# 第六节：工具箱入口精简

测试全部通过。完整操作与预期保留，结果如下。

工具箱同时展示内置脚本已覆盖的操作、重复的终端入口和准备删除的辅助页面。本节先移除五个工具箱卡片，后续需要迁移设置或调整插件导航的功能另行处理。

## 改动范围

- 移除获取密钥、SQL 查看器、FFmpeg 工具箱、命令执行器和命令终端的工具箱入口
- 在 `ScreenRouteRegistry` 中将这五个页面登记为隐藏路由，不再生成工具箱导航卡片
- 保留原生页面及路由 ID，并保留终端、获取密钥的默认导航映射，支持现有内部调用和插件按路由打开页面
- 聊天主页的终端继续通过 `WorkspaceHubScreen` 直接打开 `ComputerScreen` 与共用的终端组件
- 其他工具箱卡片及内置工具不在本节处理；ToolPkg 注册和 Compose DSL 导航的后续调整见[第十二节](12-插件UI注册与工具箱导航兼容.md)

## 验证记录

完成导航登记、默认路由映射、工具箱列表来源和聊天终端调用链的源码检查。设备上的显示与交互仍待回归。提交后触发 Android Tests 与 `assembleDebug`，执行结果单独确认。

## 回归操作与预期

1. 打开工具箱：获取密钥、SQL 查看器、FFmpeg 工具箱、命令执行器和命令终端卡片全部消失
2. 检查其他内置卡片：仍可显示并打开，原有顺序保持
3. 通过 `registerToolboxUiModule` 注册界面的插件：工具箱不出现自动入口，插件详情仍能打开 Compose DSL 界面并返回
4. 显式注册 `surface: "toolbox"` 的旧插件：工具箱不出现该入口，插件仍可加载；其对应 UI route 保持可用
5. 从聊天页进入工作区主页，再进入终端：终端显示、输入和会话切换可用
6. 从终端环境初始化向导进入初始化页面：初始化入口可用
7. 通过现有内部导航或插件原生路由打开这五个页面：路由仍可解析；终端与获取密钥的默认导航映射可用

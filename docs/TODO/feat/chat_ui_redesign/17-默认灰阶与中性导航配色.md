# 第十七节：默认灰阶与中性导航配色

本次补录：用户确认目前 Bug 均已修复，本页待填写的验收说明已按用户确认同步。验证来源及现有 CI 记录见[验证结果补录](../../chore/distribution_integration/06-验证结果补录.md)。

## 背景与目标

此前主界面在 Android 12 及以上采用壁纸动态配色，较早系统采用紫色默认配色；设置页分组标题与图标、侧栏标题和工具箱图标直接使用主色。即使顶部透明，页面仍可能出现接近纯黑的底色、蓝紫色标题和不一致的卡片灰阶。

本节采用 Operit2 的默认种子色与灰阶，使页面、卡片、菜单和弹窗具有稳定的表面层次。普通标题和功能图标在深色模式使用白色、浅色模式使用黑色，说明文字和分隔线采用相应灰阶。

## 参考来源

参考 [Operit2 的主题定义](https://github.com/AAswordman/Operit2/blob/main/apps/flutter/app/lib/ui/theme/OperitTheme.dart)，读取时文件 blob 为 `2eb7935de9f3de65f47aacf19e81affdd1d0897d`。其默认种子色为 `#BBDEFB`，配色变体为 `DynamicSchemeVariant.tonalSpot`。

使用 Material Color Utilities `0.3.0` 的 `SchemeTonalSpot`，以该种子色、深浅模式和默认对比度生成固定色板。正文与页面标题色按本节要求分别设为白色和黑色，其余色阶沿用生成结果。色板计算工具只用于提取颜色，未新增 Android 运行依赖。

主要色阶如下：

- 深色页面：`#101417`；低层容器：`#181C20`；卡片：`#1C2024`；高层容器：`#262A2E`；最高层容器：`#313539`
- 浅色页面：`#F7F9FF`；低层容器：`#F1F4F9`；卡片：`#EBEEF3`；高层容器：`#E5E8ED`；最高层容器：`#E0E3E8`
- 深色普通文字与图标：`#FFFFFF`；说明文字：`#C1C7CE`
- 浅色普通文字与图标：`#000000`；说明文字：`#41474D`

## 实现范围

- `ui/theme/DefaultColorSchemes.kt` 集中声明完整深浅色板，包含页面底色、全部容器层级、正文、说明、边框、强调色和错误色。移除已无引用的旧紫色常量文件。
- `ThemeColorSchemeResolver.kt` 提供共用的主题解析；主界面根据当前主题快照和深浅模式直接调用同一入口，其他依赖 Context 的调用保留原有入口。默认配色不再自动采用 Android 壁纸颜色。
- 自定义主色、次色及强调色上的文字选项继续生效。自定义配色仅调整强调色及其容器，正文、说明文字和基础表面沿用统一色板，避免整页再次出现不同的灰阶。
- `Theme.kt` 保持透明系统栏及图标深浅适配；背景图片已有的错误占位和视频遮罩使用主题背景色。删除重复配色生成函数，避免主界面与共用解析入口产生差异。
- 设置页分组标题、分组图标、条目标题及功能图标使用 `onSurface`，说明和箭头使用 `onSurfaceVariant`；卡片统一使用不透明的 `surfaceContainer`，在背景媒体开启时也保留可辨识的卡片层次。
- 侧栏默认标题及状态标识采用正文色，选中项和紧凑按钮用中性容器灰阶，分隔线采用 `outlineVariant`。侧栏自定义背景上的文字按该背景选择黑白色，已配置的专用侧栏强调色继续生效。
- 工具箱卡片采用 `surfaceContainer`，图标底色使用 `surfaceContainerHigh`，功能图标与标题按正文色显示。
- 独立恢复与错误页面，以及悬浮窗的既有默认浅色方案，复用统一色板；悬浮窗调用方传入的活动主题仍直接生效。

本节不调整页面布局、功能归属、角色绑定、记忆策略或背景媒体配置格式。品牌位图及供应商 Logo 保留原图；修改的是界面功能图标的主题着色。按钮、开关、链接等交互强调仍使用主色，错误状态仍使用错误色。

## 兼容性

没有新增偏好键、数据迁移或 API。主题切换仍支持跟随系统和手动深浅模式，角色或群组当前主题快照仍按原方式选择。默认表面现在固定，不再跟随系统壁纸颜色；专用侧栏背景与强调色配置仍被读取。

## 验证记录

已对本次 8 个新增或修改的 Kotlin 文件进行语法结构解析，未发现语法错误；72 个深浅色角色已核对参考色板生成结果与黑白正文覆盖；`git diff --check`、文档链接和旧色板引用核查通过。以上静态核验不代替 Kotlin 编译或设备视觉验证。

本地未运行 Gradle 构建或 Android 测试；远端验证安排为工作分支 Android Tests 与 Android Build `assembleDebug`。下列视觉检查需在新构建上实际操作，结果待填写。

### 设备检查步骤

1. 关闭自定义配色与背景媒体，进入深色模式，检查设置、侧栏与工具箱：页面为柔和深灰，卡片略亮，普通标题和功能图标为白色，说明文字为灰色。
2. 切换浅色模式，检查相同页面：页面和卡片为浅灰层次，普通标题与图标为黑色，说明文字为深灰。
3. 在 Android 12 及以上改变系统壁纸后返回应用：默认灰阶保持稳定。
4. 切换跟随系统、手动模式及角色或群组主题：顶部、正文与侧栏同步更新，系统栏图标可辨认。
5. 开启自定义主色与次色，分别检查深浅模式及强调色上的文字选项：按钮和交互强调生效，页面灰阶与普通标题保持中性配色。
6. 开启图片背景和视频背景并调整透明度：媒体按既有配置显示，设置卡片保持灰阶层次，视频遮罩跟随当前页面底色。
7. 配置侧栏自定义背景和专用强调色：背景配置生效，文字可辨认，专用强调色配置仍按原范围生效。
8. 打开权限悬浮窗、错误页面和数据恢复页面：默认表面采用新色板，传入活动主题的窗口使用该主题。

# 分窗口重建聊天记忆

## 原状

长期记忆自动保存按回复完成后入队，并在处理时仅读取触发消息前的最近 48 条消息。聊天设置中的手动记忆保存会读取当前运行态窗口；对于历史很长且已有多条聊天总结的会话，无法可靠补建此前丢失的记忆。

## 意图

在“设置 - 聊天记录管理”中选择一个或多个会话，指定每个 AI 提取任务的消息窗口大小，顺序重建长期记忆。每个窗口复用现有知识图谱提取、检索去重、合并和资料更新逻辑，而不将整个会话一次提交给模型。

聊天中的 `summary` 消息不参与长期记忆提取。页面展示会话、窗口和消息进度，支持取消，单个窗口失败后继续处理其余窗口并累计失败数。

## 作用域

- 新增可单测的窗口规划器与重建协调器
- 将记忆图谱模型输出统一为具名对象协议，协议错误计入窗口失败
- 在聊天记录管理的会话多选区提供窗口大小与构建入口、进度和取消操作
- 为新增文案提供默认语言资源
- 新增窗口规划器的 JVM 单元测试

## 验收

- 用户可选择一条或多条聊天记录、选择窗口大小并启动重建
- 每个模型请求只接收一个有限窗口的原始用户/助手消息，摘要不会混入记忆分析
- 进度显示当前会话、窗口数、已处理消息数和失败数
- 取消后不启动新窗口，已完成窗口的记忆仍保留
- 重建复用现有记忆图谱入库逻辑和记忆空间绑定规则
- 有效的 `new`、`update`、`merge`、`links` 不依赖 `main` 节点存在

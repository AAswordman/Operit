# 全局主题包与场景契约

## 包模型

每个已安装主题版本由以下内容组成：

- 身份：`package_id`、显示名、作者、精确版本、内容摘要和 API 范围
- 基底：单一精确基底版本与摘要
- 能力：所需场景、资源类型、宿主表面和可选渲染能力
- 资源：具有类型、摘要、尺寸、大小和用途的本地只读资源
- 参数模式：作者公开的参数、默认值、范围、分组与本地化文案
- 场景：声明式 UI 场景树、槽位映射、状态选择器和视觉节点
- 组件皮肤：通用语义组件的部件和状态视觉规则

用户主题选择是应用级 `ThemeInstance`。它固定引用一个已安装的包版本，并仅保存该包参数值。角色卡和群组不再保存主题实例。

## `.otheme` 专有格式

主题包是可上架 Operit 插件市场的专有 `.otheme` 文件，而不是用户直接处理的通用归档。容器内部使用 ZIP 存储，但必须在根目录精确存在唯一 `operit-theme.json`，其 `schemaVersion` 必须等于 `1`；该入口文件和专有扩展名共同构成格式身份。ZIP comment 写入 `Operit Theme Package` 作为辅助标识。

```
author.cyber-night-v1.2.0.otheme
├── operit-theme.json
└── assets/
    ├── background.webp
    ├── frame.nine.png
    ├── display.ttf
    └── glow.path
```

`operit-theme.json` 使用严格 JSON：未知字段拒绝。它包含身份、精确基底、能力、资源清单、变体、作者公开参数、token 和场景树。市场下载资产的 SHA-256 直接成为 `ThemePackageCoordinateV1.archiveSha256`。

## Scene DSL v1

首版不是自由 UI 语言。它只允许宿主实现且可校验的节点：

- `stage`：场景根、背景色、边缘安全区和内容边界
- `layer`：固定 z 顺序的叠加容器
- `row`、`column`、`grid`：受限布局容器
- `frame`：锚定、相对尺寸、最小最大尺寸、内边距和对齐
- `host_slot`：宿主提供的受控语义内容
- `surface`：纯色或渐变、受限路径裁切、单描边、单外阴影和透明度
- `image`、`nine_slice`、`text`、`path`：主题资源和纯装饰节点
- `transform`：平移、缩放、二维旋转和透明度

节点不执行代码，不引用 URL，不接受任意 SVG、HTML、脚本、shader、Canvas 指令或表达式。

## 资源 v1

- 位图：`png`、`jpeg`、`webp`，支持 fit、crop、stretch
- 九宫格：位图加显式 cap inset 和中心 stretch 或 tile 策略
- 字体：`ttf`、`otf`，以明确 family 和 face 注册
- 路径：归一化 `M`、`L`、`Q`、`C`、`Z` 命令，用于形状和纯装饰
- 根背景图：仅本地静态位图；视频背景留待后续格式版本

导入器限制资源路径、MIME、像素数、字节数、节点数、路径复杂度和包总大小。所有资源在应用私有目录中按内容摘要保存。

## 主题与宿主边界

主题包可以决定已登记槽位的排列、包裹结构、装饰图层、背景、边框、字体和视觉状态。

宿主保留：

- 路由、返回守卫、导航目标与插件动作
- Android Insets、系统栏实际调用、IME、输入、选择与焦点
- 业务状态来源、事件执行、权限、外部 Activity 和生命周期
- 列表虚拟化、消息顺序、消息 ID、流式内容解析和内容安全
- 无障碍标签、角色、live region、最小触控范围和模态焦点管理

## 场景与组件的关系

场景表达页面级构图。组件表达可重用的业务语义。主题场景只能引用宿主注册的场景槽位和组件；主题不会直接取得领域对象或 Composable 回调。

场景输入是稳定的标量状态、枚举状态、列表节点、受控内容槽与封闭事件。场景输出只能是宿主定义的布局选择和视觉节点树。

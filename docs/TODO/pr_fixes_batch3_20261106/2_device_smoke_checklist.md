## 优先验证

1. 流式滚动：让模型输出长答案，向上拖动并按住列表，等待数秒再松手。列表不应跳回底部。再滑到底部或点回到底部，应恢复跟随；历史消息定位和会话切换应正常。
2. SSE 断连：分别用 Web Chat 和已有 external-chat 流式客户端开始长回复，生成中关闭页面或断开连接，然后重新连接再发一条。应用不崩溃，后续请求能继续完成；external-chat 的最终正文与应用内一致，不把已作废重试片段拼回来。
3. 终端超时：普通执行、流式执行和 hidden exec 分别执行 `sleep 10` 并设置 1 秒超时。工具结果应报告 `success=false`、`timedOut=true` 并含超时说明；再执行 `echo ok`，正常结果仍成功。保留此前已验证的按对话隔离行为。
4. MCP 参数：在 inputSchema 明确要求 string 的工具中依次传 `109`、`true`、`{"a":1}`、`[1,2]`。服务端都应收到原字符串，不能变成数字、布尔、对象或数组；声明 number 的工具仍按 number 发送。
5. GREP 行号：准备 30 行文本，给第 1、2、25、30 行放不同关键词。搜索并开启上下文，核对首行、末行和不连续的多命中区间；显示的编号必须等于文件真实行号，匹配行的标记正确。

## 界面和既有契约

6. 环境变量：找一个有必填变量的工具包，空值时显示错误颜色；输入有效值后立即取消错误颜色，保存并重开仍正常。可选变量不显示必填错误。
7. 思考规则：在中文和英文分别打开模型配置的思考配置编辑器，检查规则类型、模型匹配、开关动作、档位、请求路径示例及删除按钮。保存后重开，规则内容与档位顺序不变；长编辑窗口仍能正常滚动。
8. 插件悬浮窗：同一插件打开后关闭，close 应返回 JSON null。两个插件使用相同窗口 ID 时，关闭 A 仅移除 A，B 仍能操作；A 重复关闭应报未知窗口。
9. 日语资源：切到日语并打开功能模型配置，界面正常。孤儿资源删除主要由资源检查验证，不要求制造特殊界面场景。

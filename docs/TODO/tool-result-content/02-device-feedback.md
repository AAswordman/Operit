## 编辑器修复

`MessageEditorContent.kt` 原先把 XML 片段周围的换行、空格和缩进拆为 TEXT，`MessageEditor.kt` 为每个 TEXT 绘制输入框，造成旧消息看起来有大量空框。与数据库版本无关，任何包含这种格式间隔的消息都可能出现。

为这类原文间隔新增 SPACING 片段。可视化编辑跳过 SPACING，重组仍写回全部原字符，保留原始片段索引。整条纯空白消息、手动添加的空文本、XML 的空正文仍正常进入各自编辑入口。思考 token、协议 payload 和数据库 schema 沿用原规则。

新增四个 JVM 用例，验证思考/协议间隔的分类、修改正文后空白与索引保持、整条空白消息与新增空文本、空 XML 正文；既有空白往返用例同时检查 SPACING 类型。新增用例尚未在本地执行，结果以派发的 Android Tests 为准。

## 相关源码核查

`MessageSectionCodec.findNextStructuralTag()` 已在持久化解析阶段跳过代码和普通 XML 容器。`ToolExecutionManager.extractToolInvocations()` 仍只使用 XML 流插件，然后在整个 XML 分组中搜索工具标签，没有复用 sections 的顶层边界：代码中的示例和容器中的嵌套工具仍可能进入真实工具检测。现有 `StreamMarkdownFencedCodeBlockPlugin` 只定义反引号围栏，未定义波浪号围栏。

本轮修改修复 B01。M05、M09 按截图保留为展示失败，不把 Codec 的源码覆盖等同于整条渲染与执行链路通过，也不把尚未修正的链路写成已完成。

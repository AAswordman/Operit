# 统计恢复与保存

## 实现

- `ChatHistoryManager.getChatTokenCounts` 按会话 ID 读取数据库元数据，历史会话的恢复不再依赖侧边栏列表 Flow
- `ChatTokenStatisticsLoader` 串行处理恢复请求，首次使用前初始化；打开历史会话时重新读取持久化快照
- `ChatHistoryDelegate.saveCurrentChat` 在统计尚未加载时跳过累计保存，`ChatServiceCore` 在首轮累加前确保旧基数已恢复
- `saveChatStatistics` 按固定会话 ID 读取和保存统计；切换、新建、分支和取消后台请求不再依赖 UI 活跃统计
- `ChatRuntimeHolder` 将显式清空通知到主界面和悬浮窗两套运行时，清零目标会话的缓存，不影响其他会话
- `TokenStatisticsDelegate` 将输入和输出放在同一份并发快照中，以原子操作累加和合并；迟到的普通快照不降低累计值
- `ChatDao.updateChatTokenCounts` 仅更新统计字段，并保留输入、输出各自较大的累计值；显式消息清空仍使用原来的元数据更新，并单独清零该会话的内存统计
- 普通保存采用只增不减合并；如果数据库已有偏大的累计值，普通保存不能向下修正，需通过显式清空或专门的数据修正流程处理
- 统计恢复失败不阻止消息加载；回合完成时仍同步主界面和悬浮窗的消息，但缺少可信统计时不向另一运行时写入零值
- `refreshStableContextWindow` 使用独立的窗口保存方法，不写入累计输入和输出；后台会话恢复统计时不改变当前会话

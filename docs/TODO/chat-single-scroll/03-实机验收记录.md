## 与 #1278 的合并关系

本 PR 保持独立，只提交卡片、聊天渲染与滚动改动，不携带 #1278 的持久化及数据库变更。两个 PR 都修改 `StreamMarkdownRenderer.kt` 和 `CustomXmlRenderer.kt`。组合分支已解决冲突，并在 `ChatTimelineEntries.kt` 将结构化 `displaySections()` 接入消息持有的静态节点准备入口。

组合中的各消息块共享 sections，sections 渲染入口直接绘制已准备的节点，完整渲染保留 section 边界及独立缓存键。后续同时合入两个 PR 时需要保留该组合适配，不可只消除文本冲突而继续从原始字符串准备静态消息。

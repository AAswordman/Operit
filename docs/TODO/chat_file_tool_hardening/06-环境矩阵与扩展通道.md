# 06 环境矩阵与扩展通道

## 旧实现

repo: 环境下 zip/unzip/open/share/apply/create/edit/move/copy 无 guard，静默落 Android FS 报"不存在"；linux 环境无结构化编辑；grep 的 linux/SSH 路径直接喂 Android FS 上的 native ripgrep；SAF 写白名单报错不列扩展名；禁用包调用报 "Tool not found" 而非"未启用"。

## 意图修正

- repo: 环境 clean guard：zip/unzip/open/share/apply/create/edit/move/copy 入口返回 "X is not supported for repo environment"
- linux 环境编辑实装：linuxTools.readFileFull → FileBindingService → linuxTools.writeFile
- grep_code/grep_context linux 路径经 PathMapper 映射后跑 native ripgrep
- SAF 白名单报错列出支持的扩展名
- AIToolHandler.getToolExecutorOrActivate 回传"包未启用"真实原因
- 与 01 阶段的 environment 文档矩阵保持一致

## 期待的新实现

跨环境行为可预测：不支持即明确报错（可自纠），支持则行为与文档一致。

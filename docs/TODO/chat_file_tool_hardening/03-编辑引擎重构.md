# 03 编辑引擎重构

## 旧实现

FileBindingService.kt：无精确匹配快路径（唯一"完美"判定也在滑动窗内）；0.9 阈值多候选不拒绝、静默取最优窗替换（仅完美重复才中止，:280-283/:666）；read_file 的 `N| ` 行号前缀污染匹配；每 op 匹配行号算出即弃（:284）；[START-REPLACE] 块解析为死代码（无生产调用者）。

## 意图修正

1. hasMultiplePerfectMatches 重构为 (count, positions) 扫描器；findBestMatchRange 顶部归一化精确 indexOf，唯一命中直接定位
2. 并行搜索统计 >0.9 窗口，非完美多候选 ≥2 → 失败并报各候选拿的行号+相似度，提示加上下文或用 occurrence
3. applyFile 入口对 old 剥离 `^\s*\d+\| `（MULTILINE）
4. 新增 occurrence 可选参数（默认 1）；ToolRegistration 同步
5. 成功结果含 "Replaced at lines X-Y"；失败附最佳候选拿的行号+相似度
6. 描述写明匹配语义与重试策略；删除死代码解析路径
7. 新增 JUnit 五组用例

## 期待的新实现

edit_file 首次成功率显著提升；失败报错可指导模型精读目标行后重试，不再退化为终端脚本。

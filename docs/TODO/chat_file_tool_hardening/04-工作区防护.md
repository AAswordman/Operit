# 04 工作区防护

## 旧实现

文件工具对任意绝对路径直接执行（PathValidator 只查绝对前缀）；权限检查按工具名，无路径维度；JS 包嵌套调用绕过 ToolExecutionManager；delete_file recursive 对 / 等根目录零防护。

## 意图修正

- 根解析：SendMessageOptions.workspacePath 传入 executeInvocations + 按 chatId 查 ChatHistory.workspace 为准；未绑定工作区 → 所有路径按区外
- 新 WorkspacePathChecker（纯函数可测）：canonicalPath 前缀比较；工具 env 与 chat workspaceEnv 错配 → 区外；linux 经 PathMapper；repo: 按 bookmark
- 行为矩阵（checkToolPermission 判定 stage）：区内 ALLOW 直执行 / ASK 弹窗 / FORBID 拒绝；区外 ALLOW 强制弹窗 / ASK 弹窗 / FORBID 直接拒绝
- 嵌套兜底：ToolRuntimeContext 扩展携带 chatId/workspaceRoot；AIToolHook 对 JS 包/package_proxy 嵌套文件工具同样判定，区外拒绝回传理由（hook 无 UI）
- delete_file 危险路径硬底线：拒绝 /、/storage/emulated/0、/sdcard、/data 等根级目录 recursive 删除

## 期待的新实现

工作区内流畅、区外必经用户把关；未绑定工作区默认全防护；危险根目录删除被硬拦截。

# 08 AI 读取提炼

## 旧实现

- read_file / read_file_part / read_file_full 原样返回文件内容（带行号），read_file 单次 32KB 字符截断；长文件读取占用大量上下文
- read_file_part 需模型自备行号，行号未知时只能先读再猜，二跳成本高
- 功能模型范式（FunctionType + FunctionalConfigScreen 枚举驱动 + 未配置默认主模型）已由 TOOL_REVIEW 建立并验证

## 意图修正

- FunctionType 新增 FILE_DISTILL；FunctionalConfigScreen 补三处穷尽 when（显示名/描述/连接测试）+ 新字符串，未配置时经既有 getConfigMappingForFunction 返回 DEFAULT_CONFIG_ID，即默认跟随主模型
- ApiPreferences 新增 FILE_DISTILL_ENABLED 开关（默认开），UI 置于工具审查三开关同区域；开关关闭时三工具行为与现状完全一致
- 新建 FileDistillService：单次协议（一次调用完成 related/worth 判断 + 带行号摘录）与扫描协议（read_file_part / 大文件 full 逐块滚动，每轮 related + 摘录 + continue_scan，块约 24KB，上限 8 轮）；worth=false（≥50% 相关）直接返回原文；扫描结束摘录占比过高同样返回原文
- ToolRegistration 在 read_file / read_file_part / read_file_full 的 executor 外包提炼拦截（不动 5 个权限子类实现）：开关关 → 透传；isSpecialFileType（图片/PDF/文档/音视频 OCR 抽取管线）→ 透传；raw=true → 透传；文件 ≤2048 字节 → 透传原文；其余进提炼
- 新参数：raw（默认 false，true 读原始内容）、focus（AI 模式必填，缺失报错要求补传）；失败（超时/异常/JSON 不可解析）一律显式失败 ToolResult，error 指引 raw=true 重读，不降级
- 三工具描述注明：除非确认要读原始内容，否则使用默认 AI 提炼；read_file_part 额外注明不确认行号时省略行号参数用 AI 读取自动定位
- 工具描述与 UI 字符串多语言同步

## 期待的新实现

默认读取返回 AI 提炼后的带行号相关摘录，上下文占用大幅下降；主模型可继续用摘录中的行号做 edit_file；需要精确原文时 raw=true 一次到位。

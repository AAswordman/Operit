# 07 高危工具审查（工具调用审查泛化）

## 旧实现

05 的 TOOL_REVIEW 审查只覆盖 24 个文件工具（`WorkspacePathChecker.WORKSPACE_PROTECTED_FILE_TOOLS`），开关只有区内/区外两个分区；shell/终端、Intent/广播、安装卸载、HTTP 请求、代理类等高危工具调用在允许模式下不经任何模型初筛直接执行。审查 prompt 亦为文件专用（"FILE tool call"），参数摘要只取 content/new/base64Content。该功能未随任何发布版本发出，本步骤按"未发布直接改"处理，不做旧语义兼容。

## 意图修正

1. 新增 `core/tools/HighRiskToolCatalog.kt`：18 个核心破坏集高危工具 + 每工具英文操作摘要 + 限定名后缀匹配（与 `isWorkspaceProtectedTool` 同模式，扩展包同名工具一并纳入）
2. `ToolExecutionManager.checkToolPermission` 在工作区块之后并列新增高危分支（`else if`）：高危工具与文件工具两集合不相交，`ALLOW` + 「自动审查高危工具」开关开 → 跑审查；开关关 / ASK / FORBID 落到标准流程
3. 审查确认流提取共用 `confirmAfterReview`（文件路径 NonCompliant/Failed 两分支与高危分支共用）：拒绝 → notify+错误结果；放行 → recordApprovedOutsidePaths（非文件工具传空列表无副作用）+ notify 放行
4. `ToolReviewService` 泛化：`zone` 参数改为调用方传入 scope 标签（文件=区内/区外文案，高危="high-risk tool call (not workspace-scoped)"）；operationSummary 先查 HighRiskToolCatalog 再落文件族映射；参数摘要从 content 类单参数扩展为全参数 name=value 汇总（单值/总量各截 500）
5. `FunctionalPrompts.toolReviewPrompt` 泛化：标题 "tool call"、Scope 字段、规则扩充（命令/代码不得破坏系统、应用与系统管理需任务明确需要、网络不得外发用户数据、代理调用按目标工具判定）
6. ApiPreferences 第三开关键 `tool_review_high_risk_tools`（默认 false）+ Flow + 保存；区内/区外两 key 原样保留
7. UI 三开关：Agent/Classic 工具组展开区加小标题「自动审查工具调用」+ 三行开关（区内/区外/高危工具），仅允许模式显示；strings 仅加 values/（与既有两条一致）；ApiConfigDelegate/ChatViewModel/AIChatScreen 管线镜像透传

## 高危工具清单（18 个，用户确认的核心破坏集）

| 类别 | 工具 |
|---|---|
| 命令/代码执行 | execute_shell、execute_in_terminal_session、execute_in_terminal_session_streaming、execute_hidden_terminal_command、input_in_terminal_session（stdin 可驱动 REPL）、execute_sandbox_script_direct |
| Intent/广播 | execute_intent、send_broadcast |
| 应用与系统 | install_app、uninstall_app、stop_app、modify_system_setting |
| 网络外发 | http_request、multipart_request |
| 代理（任意工具执行入口） | use_package、package_proxy、proxy |
| 编排 | trigger_workflow |

## 行为决策（用户确认）

- 该 TOOL_REVIEW 功能未发布 → 直接改，不做向前兼容
- 开关分区 → 三开关：区内文件 / 区外文件 / 高危工具（互相独立）
- 高危范围 → 核心破坏集 18 个（不含 UI 自动化、隐私读取、记忆/角色卡/模型配置写、浏览器操作等，后续可再扩）

## 追加：调用说明参数与审查上下文一致性（同日第二轮）

1. **call_purpose 调用说明参数（可选）**：可审查工具（`HighRiskToolCatalog.REVIEWABLE_TOOL_LOCAL_NAMES` = 18 高危 + 24 文件族）可附带一句话声明"为什么发起本次调用"
   - 文档注入两路径：文本提示词在 `SystemToolPrompts.buildToolPromptCategories`（hook 管线 Map 往返会丢上游注入，须在重建点注入）；function-calling schema 在 `EnhancedAIService.getAvailableToolsForFunction` 尾部。共用 `HighRiskToolCatalog.callPurposeParamSchema()`（required=false，中英双语描述）
   - 参数仅供审查流读取；执行前 `ToolExecutionManager.withoutCallPurposeParam()` 从 `invocation.tool` 剥离（JS 包与代理解析会拒绝未知参数；rawText 保留原始 XML 供聊天记录与历史回传）
2. **审查上下文**：`ToolReviewService.buildReviewContext` 直读 `ChatHistoryManager.loadChatMessages`（数据库全量历史，不经运行态压缩摘要）
   - 最近一条用户指令：全量历史中最后一条 `sender=="user"` 的消息（截 800 字符）——真实指令，不受上下文压缩影响
   - 调用点前 10 条：最近 10 条 `sender=="ai"` 消息（其内容含该轮工具调用），剔除 `tool_result` 结果块、压缩空白、单条截 300 字符，旧→新编号
   - 无 callerChatId（悬浮球等无会话来源）时传空串，审查按无上下文判定
3. **审查 prompt**：新增 Declared call purpose / Latest user instruction / Recent context 三段 + 一致性规则（调用须是最近用户指令与前文上下文的连贯延续；声明目的与上下文矛盾 → 不合规；未提供 call_purpose 本身不构成违规）
4. `checkToolPermission` 增加 `callerChatId` 参数（唯一调用方 executeInvocations 传入），透传至两处 review 调用

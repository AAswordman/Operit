# 02 读取上限与健壮性

## 旧实现

- read_file_full / read_file_binary 无大小上限（OOM 后报 error: null）；read_file 32KB 字符截断未文档化
- read_file_part 无 countFileLines 全量读（大文件全量 IO）；无 isTextLike 门禁（二进制返回乱码当成功）
- 特殊文件 OCR/解码失败返回 success=true（错误文本当内容）
- read_file 截断标记按字节判断按字符读取（SFS:1653 误判）
- read_file_binary 的 base64 被 toString() 摘要化，内容到不了模型
- FileApplyResultData.toString() 转义链为无效恒等替换（ToolResultDataClasses.kt:579）

## 意图修正

- ToolExecutionLimits 新增 MAX_FILE_READ_SIZE_BYTES = 32MB；read_file / read_file_full / read_file_binary 三环境实现入口检查（含特殊文件抽取路径），超限失败并引导 "Use read_file_part with start_line/end_line to read it in segments."
- read_file_part 改流式按行读取（去 countFileLines，end_line 缺省读到文件尾），保留 32k 字符输出截断
- read_file_part 补 isTextLike 门禁；特殊文件提取失败改 success=false
- 修 bytes-vs-chars 误判；read_file_binary base64 进入模型可见结果（超 64k 单条上限时明确报错并给替代路径）
- 修无效转义链

## 期待的新实现

大文件可安全分段读取；二进制/损坏文件得到明确失败；二进制读写可完成往返。
